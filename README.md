# GPT-Pub

GPT-Pub 是一个完全独立的公开项目仓库，独立制定规则、分配编号、维护项目、运行 CI 和发布版本。它不由任何其他仓库管理，也不是其他仓库的公开镜像或子仓库。

本仓库只维护已经确认可以公开的软件、工具和公共代码。私密专利、未公开科研、个人资料和内部工作记录不进入本仓库。

## 接入顺序

新对话或新维护者开始工作前，依次阅读：

1. [`GPT_RULES.md`](GPT_RULES.md)
2. [`目录.md`](目录.md)
3. 对应分类的 `README.md`
4. 对应项目的 `README.md` 与 `阶段记录.md`

## 独立分类与编号

GPT-Pub 使用自己的分类和编号。当前第一类为桌面软件：

```text
projects/
└── 1-桌面软件/
    ├── README.md
    ├── 101-VideoUpright/   # P101，待迁移
    └── 102-AtlasDesk/      # P102，待迁移
```

这里的 `1`、`P101` 和 `P102` 只属于 GPT-Pub，与任何外部仓库的编号没有继承或对应关系。

## 分支模型

每个项目使用两条长期项目分支：

```text
p101-exp      日常开发与连续迭代
p101-stable   P101 的稳定候选

p102-exp      日常开发与连续迭代
p102-stable   P102 的稳定候选
```

仓库级 `main` 只接收已经通过稳定候选验收的内容：

```text
项目 exp → 项目 stable → main
```

正式版本标签只建立在 `main` 上。详细的同步、路径隔离和 CI 规则见 [`GPT_RULES.md`](GPT_RULES.md)。

## 当前状态

当前只建立独立规则和目录骨架，尚未迁入任何项目源码。P101 与 P102 必须分别通过独立迁移 PR 接入。

迁移完成后，项目的唯一当前事实源、开发主线、CI、Issue、PR、标签和 Release 均在 GPT-Pub 内部维护；外部仓库只属于历史来源，不参与本仓库管理。

## 公开边界

本仓库禁止出现：

- 外部私有仓库的完整分支、完整历史或未经筛选的导出；
- 专利创意、未公开论文与实验资料；
- Token、密码、密钥、私有下载地址和内部访问凭据；
- 个人数据、真实用户文件、未脱敏日志和本机隐私路径。

跨仓迁移必须先过滤目标项目历史、执行公开安全扫描，并核对文件数量和 SHA-256。
