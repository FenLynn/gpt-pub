# 专利计算开发约束

> 约束层级：B｜分类级  
> 适用范围：`projects/2-专利计算/`  
> 上位规则：A｜`/GPT_RULES.md`

## B-01｜公开安全门禁

进入本分类的代码、输入、参数、几何、数据、图件、日志和元数据必须全部可以公开。以下任一情况存在时，停止写入 GPT-Pub：

- 能直接或组合推导未公开专利的核心结构、必要参数或决定性效果；
- 包含私有仓库编号、路径、项目名、任务名、内部结论或真实工程动机；
- 包含未获批准的实验数据、客户数据、私人配置或本机信息；
- 无法解释为什么当前内容公开后不会影响后续专利、论文或商业秘密布局。

删除说明文字并不能消除泄密风险。代码、边界条件、图像和文件名同样按公开披露审查。

## B-02｜编号与跨仓关系

- 本分类独立使用 `PUB-P201–PUB-P299`；
- 编号按本分类创建顺序分配，与外部仓库完全独立；
- 不为外部项目预留号码，不要求一对一；
- 本仓库不得保存外部私有项目到本项目的反向映射；
- 跨仓关联、真实用途和私有解释只由私有仓库维护；
- Pub 项目正式路径一旦被引用，应保持稳定。

## B-03｜中性命名

项目目录、分支、提交、PR、case、Artifact、Release、文件和变量使用公开可解释的中性名称。

禁止出现：

```text
HUB-PNNN
私有 idea 编号
未申请专利名称
用于某项专利验证
私有仓库路径或本机绝对路径
```

## B-04｜代码与输出接口

计算核心只接收明确输入和 `OUTPUT_ROOT`，不得识别或写死 Hub、Pub、盘符和私人工作区。

- 一次运行只能使用一个输出根目录；
- 配置、数据、图件、日志和 manifest 必须写入同一目标体系；
- GPT-Pub Actions 只允许公开输出，等价于 `RESULT_TARGET=pub`；
- GPT-Pub Actions 不检出私有仓库，不持有私有仓库 Token，不向外部仓库写入；
- 私有环境可以检出本项目固定提交并把 `OUTPUT_ROOT` 指向私有位置，但该运行及结果不回写本仓库；
- 缺少输出目标或目标越出允许目录时立即失败，不自动回退到其他仓库。

## B-05｜算例与结果

- 公开算例必须具有独立技术意义和可复现输入；
- 每个正式结果固定代码提交、配置、随机种子（如有）、环境、命令和输出清单；
- 关键结论使用解析极限、基准算例、收敛性、公平对照或独立实现验证；
- 已触发明确物理停止条件的路线不得用更复杂模型包装为成功；
- 图件必须由本项目代码生成，不复制受版权保护的出版图。

## B-06｜数据分层

```text
Git
→ 代码、配置、小型关键数据、最终图件、清单

Actions Artifact
→ 临时候选、中间结果、日志、待筛选数据

Release
→ 已冻结且确需长期保存的大型结果包
```

可重新生成的缓存、全量参数扫描中间场、调试日志和大矩阵不得长期进入普通 Git 历史。冻结结果包必须提供文件清单、大小和 SHA-256。

## B-07｜CI 与结果固化

普通 CI 只能读取仓库、运行测试或计算并上传 Artifact，不得自动：

- 推送结果到分支；
- 更新 `main`；
- 创建未经审查的 Release；
- 修改其他项目；
- 根据大批量参数扫描持续制造 Git 提交。

需要固化的结果先从 Artifact 复核，再通过范围明确的普通分支和 PR 提交。PR 必须核对公开安全、复现性、结果清单和路径范围。

## B-08｜元数据清洗

提交前检查：

- 分支、提交、PR 和工作流输入；
- 日志、异常栈和环境摘要；
- Artifact、压缩包和 Release 名称；
- 文件名、CSV 表头、JSON 字段；
- SVG 注释、PNG/JPEG 元数据和 notebook 输出；
- 本机用户名、盘符、绝对路径和私有 URL。

任何反向线索不明确时停止，不得先合并再清理。

## B-09｜停止与归档

项目终止后保留编号、目录、关键代码、公开结论和停止原因，不删除历史或复用号码。停止项目不得继续响应自动计算；需要复活时先重新审查公开边界和现有技术，再恢复活动状态。
