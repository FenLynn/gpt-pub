## 接入顺序

1. 阅读根目录 `GPT_RULES.md`；
2. 阅读根目录 `目录.md`；
3. 阅读本文件；
4. 阅读项目 `README.md`、`阶段记录.md` 和迁移/发布资料；
5. 查看项目分支、PR、标签与 CI；
6. 明确本次只修改哪个项目。

## 项目规则

- P201 使用 `p201-*` 分支、`p201-vX.Y.Z` 标签和 `p201-*.yml` 工作流；
- P202 使用 `p202-*` 分支、`p202-vX.Y.Z` 标签和 `p202-*.yml` 工作流；
- 项目源码、测试、配置和关键说明保留在各自目录；
- 活动 CI 放在根目录 `.github/workflows/`，并严格限制项目路径；
- 构建目录、缓存、日志、自动生成测试媒体和普通中间产物不进入 Git；
- 正式 EXE、ZIP、SHA-256、manifest 和版本说明通过 GitHub Release 交付；
- 一次性迁移、视觉验收和临时发布工作流完成后删除。

## 迁移边界

P201 与 P202 必须分别迁移，不得在一个 PR 中同时导入两个项目，也不得把私有仓库完整历史作为本仓库祖先。

每个迁移 PR 至少验证：

- 固定源提交与过滤历史；
- 允许路径之外零文件；
- 当前文件数量、字节数和 SHA-256；
- 全历史公开安全扫描；
- 新路径构建与测试；
- Windows 原生验证和正式产物；
- 旧编号、旧路径与新编号的历史映射；
- 私有仓库停止双线维护的收尾方案。
