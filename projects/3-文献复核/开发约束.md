# 文献复核开发约束

> 约束层级：B｜分类级  
> 适用范围：`projects/3-文献复核/`  
> 上位规则：A｜`/GPT_RULES.md`

## B-01｜正式来源

- 论文以 DOI 原文、出版社或学会官网为准；
- 专利以正式公开文本、独立权利要求、附图和专利家族为准；
- 标准以正式标准文本和发布机构为准；
- Google Scholar、搜索摘要、博客和二手报道只用于发现线索，不作为最终证据；
- 记录检索日期、版本、来源链接和适用范围，不得虚构 DOI、引文、公式或参数。

## B-02｜复核对象必须明确

每个项目必须准确写清：

```text
复核哪一篇公开资料
复核哪一个公式、图、表或数值结论
原文提供了哪些输入
哪些参数由本项目补充假设
判断复现成功或失败的标准
```

只做文献摘录或一般综述，不建立 P3xx 计算项目。

## B-03｜事实、实现与推断分离

项目文档必须区分：

- 原文明确给出的事实和参数；
- 本项目为实现而采用的解释、离散化和补充假设；
- 代码实际得到的复现结果；
- 对偏差原因的推断。

不得把自主推断写成作者原结论，也不得用拟合后的参数冒充原文参数。

## B-04｜版权与公开边界

- 不提交论文全文、出版物原图、付费补充材料或其他无权再发布的内容；
- 可以保存必要的书目信息、短引用、公式编号和自行整理的参数表；
- 图件必须由本项目代码重新生成，并清楚标注“复现”或“独立计算”；
- 私有实验数据、未公开理论、专利布局判断和内部评价不得进入本分类；
- 涉及私有用途时，Pub 只保留独立成立的公开复现，真实用途由私有仓库单向记录。

## B-05｜编号与命名

- 本分类独立使用 `PUB-P301–PUB-P399`；
- 编号与外部仓库完全独立，不预留、不复用；
- 项目名优先采用论文简称、公开机制或复核对象的中性名称；
- 不在分支、提交、PR、文件或日志中写入私有仓库编号和反向映射。

## B-06｜代码、输入与输出

- 计算核心接收明确输入与 `OUTPUT_ROOT`，不写死盘符或私人路径；
- 原文参数、自主参数和扫描参数分文件或分字段保存；
- 一次运行只能有一个输出根目录；
- 记录环境、依赖、命令、随机种子（如有）和输出清单；
- notebook 必须清理私人路径、隐藏状态和无关输出，核心结果应能通过脚本或明确步骤复现。

## B-07｜复现质量

至少执行与任务相称的验证：

- 单位、归一化和坐标定义核对；
- 解析极限或简单基准；
- 网格、步长或截断收敛性；
- 与原文图表的数字化或定量比较；
- 公平对照和误差度量；
- 对无法复现的部分明确说明缺失参数、实现歧义或可能错误。

“曲线看起来相似”不能单独作为复现成功依据。

## B-08｜数据与 CI

- Git 保存代码、配置、小型关键数据、自生成图件和结果摘要；
- 大型中间结果使用限期 Artifact，长期冻结结果使用 Release 资产与清单、SHA-256；
- 普通 CI 只读仓库并上传 Artifact，不自动提交结果或创建未经审查的 Release；
- 结果固化必须通过普通分支和 PR，核对来源、版权、复现性、公开安全和路径范围。

## B-09｜结论与停止

复核结论只能使用：

```text
复现通过
部分复现
未能复现
原文信息不足
实现待核验
```

项目终止或归档后保留编号、来源、代码、关键结果和停止原因，不删除历史、不复用号码。
