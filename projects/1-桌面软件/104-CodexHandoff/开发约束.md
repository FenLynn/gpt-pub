# CodexHandoff 开发约束

> 约束层级：C｜项目级

## C-01｜安全边界

CodexHandoff 对 Codex、Antigravity 及后续支持的数据源默认采用严格只读设计。

源码的数据源模块不得提供删除、移动、重命名、归档、追加、覆盖或数据库更新接口。涉及导出时，写入能力只能存在于独立 exporter 模块，且必须拒绝 `.codex`、`.gemini` 等源数据目录。

不得读取或导出 `auth.json`、OAuth Token、Cookie、刷新令牌等认证文件。API Key 迁移若未来立项，必须作为与聊天迁移隔离的独立安全功能重新评审。

## C-02｜启动与扫描

软件启动不得自动扫描会话目录。任何扫描必须：

1. 用户手动触发；
2. 扫描前展示计划；
3. 扫描时持续提供阶段、数量、进度和日志；
4. 支持取消；
5. 不因会话正文总大小而在启动阶段线性深解析。

## C-03｜大批量记录

项目索引阶段只允许枚举文件和读取 `session_meta` 首行、标题索引及必要的只读辅助元数据。完整正文只允许在当前页深度信息、用户预览或正式导出时读取。

列表必须分页，不允许默认一次性深解析全部会话。任何新增全局搜索或统计功能必须证明不会重新引入全量深解析阻塞。

## C-04｜会话边界

Codex 的一条顶层会话以 rollout JSONL 与其 `session_meta.id` 为逻辑边界。rollout 内部的 Turn、Item、exec、tool call、subagent 事件不得被拆成新的顶层对话。

标题优先使用 Codex 自身名称索引，缺失时才允许使用明确的回退策略。

## C-05｜写入确认

正式创建输出文件前必须展示：来源、项目、会话数、目标文件、计划读取内容、计划写入内容、不会执行的动作。敏感信息预检完成后仍需用户确认。

导出使用独立临时文件，成功后原子改名。已有目标文件默认不覆盖。

## C-06｜发布

Windows x64 是当前首要交付平台。正式候选必须提供单个可执行文件及 SHA-256。UI、WebView2、DPI 与真实 Codex 数据兼容性仍需 Windows 实机验收，构建成功不能替代实机结论。
