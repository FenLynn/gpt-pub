# P105｜LocalSub 开发约束

> 约束层级：C｜项目级  
> 上位约束：`/GPT_RULES.md`、`projects/1-桌面软件/开发约束.md`  
> 适用范围：`projects/1-桌面软件/105-LocalSub/` 与 `.github/workflows/p105-localsub-ci.yml`

本文件只能细化或收紧 A/B 级约束，不得覆盖上位规则。

## C-01｜项目身份与允许写入范围

- 正式编号固定为 `P105`。
- 正式路径固定为 `projects/1-桌面软件/105-LocalSub/`。
- 长期分支仅为 `p105-exp` 与 `p105-stable`，正式主线为 `main`。
- 固定流转：`main → p105-exp → p105-stable → main`。
- P105 项目分支相对最新 `main` 的有效差异只能位于：
  - `projects/1-桌面软件/105-LocalSub/**`
  - `.github/workflows/p105-localsub-ci.yml`
  - 本项目确有必要的 `/目录.md` 与 `projects/1-桌面软件/README.md` 状态行。
- 禁止修改 `103-DavBridge`、P104 或其他项目目录与 CI。
- 旧 `p103-localsub-*` 和 `103-LocalSub` 只作为编号错误的历史证据，不得再次成为活动开发入口。

## C-02｜双进程边界

产品长期方向固定为轻量 Windows Shell + 独立 C# Core：

- `LocalSub.exe`：窗口、托盘、Overlay、生命周期、默认 WebView2/Vue 主界面、旧 WinForms 备用入口、Core supervisor 与 IPC bridge。
- `LocalSub.Core.exe`：媒体解析、后台 ASR、后续实时 ASR、音频捕获和其他重任务。
- 已迁入 Core 的能力不得在 Core 缺失、崩溃或断开时静默回退到 GUI 进程。
- Core 断开时当前请求明确失败，GUI 必须保持可用，下一次重任务按需重启 Core。
- Shell 退出后 Core 应跟随退出，不允许长期残留孤儿进程。
- 为保持风险可控，优先复用已经验证的 C#/Windows/ASR 资产，禁止仅为架构形式重写底层链路。

## C-03｜IPC 与 Application Contract

- 传输：Windows Named Pipe。
- 编码：UTF-8 newline-delimited JSON。
- 当前 v1 方法保留 `ping`、`analyze`、`transcribe`、`cancel`、`shutdown`。
- 下一阶段实时链使用显式 session，新增 `live.start`、`live.stop` 与 `live.status / live.level / live.partial / live.final / live.discontinuity / live.failed` 等事件。实时任务不得建模成长时间不返回的单个普通 request。
- 同一 Core 同时只承担受控数量的重任务。现有后台请求继续串行化，实时 session 的并发边界必须显式定义，不得靠 UI 状态隐式互斥。
- `cancel` 和 `live.stop` 必须可以在重任务或实时 session 执行期间发送。
- IPC 请求、事件和响应必须异步消费，不得让 UI 线程同步等待长任务。
- `live.level` 等高频状态必须在 Core 或 Shell 边界限频，默认目标约 10 Hz，不允许按音频 callback 原始频率穿透到 Web UI。
- Shell、Core 与未来 Web UI 的 DTO、命令白名单和所有权以 `docs/APP_CONTRACT.md` 为准。
- 协议调整必须优先保持旧 Shell/Core 的错误可诊断性，协议不兼容时明确失败，不做静默行为替换。

## C-04｜运行时、模型与用户数据边界

- 目标运行环境：Windows x64。
- Shell/Core 均使用 `.NET 8` framework-dependent single-file。
- 模型不进入 Git 和基础发布包，默认根目录为 EXE 同级 `ASR/`。
- sherpa native runtime 默认在 `ASR/_runtime/`，不进入基础包。
- ONNX Runtime 不进入基础包。
- FFmpeg 为外部组件，优先复用 Mediova、手动路径或 PATH，禁止把 FFmpeg 固化进基础包。
- 用户转写结果、日志、配置和本机路径不得作为仓库测试数据提交。
- CI 临时下载的官方小型测试模型与 runtime 只用于当前 run，测试后清理，不进入 Git 或发布包。

## C-05｜后台进程隔离硬约束

Phase 1A 已迁入 Core 的媒体分析和后台转写必须维持编译期隔离：

- Shell 工程只保留 Proxy/IPC 入口。
- 完整 `BatchTranscriptionService` 与 `MediaAnalysisService` 实现不得编译进 `LocalSub.exe`。
- 不允许“优先 Core，失败后偷偷回本进程计算”的双路径。
- 后台波形、VAD、SenseVoice、Offline Zipformer、FireRedASR2、Fun-ASR-Nano 等重任务应由 Core 承担。

修改项目文件或共享源码时必须重新确认这一边界未被破坏。

## C-06｜迁移顺序

固定采用渐进迁移，不一次性重写。当前顺序调整为：

1. Phase 1A：后台媒体分析与后台 ASR 进程隔离，现有自动化基线已建立。
2. Phase 1B.0：冻结 Shell / Core / Web UI 的 Application Contract，抽离 snapshot、command、event 与实时 session 边界，不改变现有用户功能。
3. Phase 1B.1：将实时 Zipformer/Paraformer/SenseVoice、WASAPI、PotPlayer Process Loopback 和实时解码队列迁入 Core。
4. Phase 2A：建立 WebView2 + Vue 3 + TypeScript 主 Shell。只依赖已冻结 DTO 与白名单命令，可与后续 1B 工作交错推进，不要求等待全部模型重任务迁移完成。
5. Phase 1B.2：将模型下载、解压、校验、大目录替换等重任务迁入 Core。
6. Phase 2B：按实时、模型、后台、设置逐页迁移 Web UI。
7. Phase 3：删除旧 WinForms 业务页，Shell 只保留轻量 Windows 能力、Overlay、Core supervisor 与 IPC bridge。

允许 Phase 1B 后续工作与 Phase 2A/2B 在稳定契约下交错推进，但禁止在接口未抽离时直接把 `MainForm` 控件逻辑翻译成 Vue，也禁止同时重写实时链、模型链、后台链和全部 UI。

自 v0.1.3 起，普通启动固定进入 WebView2/Vue 主界面。旧 WinForms 仅作为迁移期显式备用入口，通过 `LocalSub.exe --legacy-ui` 或 `LOCALSUB_LEGACY_UI=1` 启动，直到 Phase 3 正式移除。默认入口切换不得成为把未迁移后台或设置业务逻辑复制到 Vue 的理由。

## C-07｜PotPlayer 与实时链

- PotPlayer 模式必须使用进程专用捕获，不得静默回退成全系统音频。
- Phase 1B.1 后，Shell 长期只负责 PotPlayer 进程发现、PID、窗口位置、最小化状态和 Overlay 跟随；按 PID 建立 Process Loopback、音频缓冲、断流恢复和实时 ASR 必须属于 Core。
- Web UI 不得直接访问 PotPlayer HWND、WASAPI、Named Pipe 或音频 callback。
- 已验证的恢复 supervisor、Process Loopback 和 Overlay 行为不得为了代码整洁被无依据替换。
- 任何实时链迁移必须验证普通窗口、最大化、全屏、快进/快退后的恢复、Core 故障恢复和长期运行。

## C-08｜CI 门禁

活动 CI 固定为 `.github/workflows/p105-localsub-ci.yml`，不得再创建长期重复 workflow。正式发布也复用该工作流的 exact-main build 结果，不建立版本专用长期 CI。

至少验证：

1. PR 来源/目标符合 `p105-exp → p105-stable → main`。
2. 差异范围只落在 P105 允许路径。
3. 活动实现与 CI 不残留 `103-LocalSub` 或 `p103-localsub` 标识。
4. Shell 和 Core 分别 publish。
5. 绿色目录同时存在 `LocalSub.exe` 与 `LocalSub.Core.exe`。
6. 真实启动 Core，完成 Named Pipe `ping` 与 `shutdown`。
7. Shell 真启动。
8. 后台工作区真进入。
9. Windows Process Loopback 真激活。
10. sherpa native runtime 真加载。
11. native offline ASR 真解码。
12. 最终包不携带模型、FFmpeg、ONNX Runtime 或 sherpa native runtime。
13. 正式发布包生成清单并在重新解压后核对文件大小与 SHA-256。
14. 进入 Web UI 阶段后增加 TypeScript typecheck、Vite production build、bundle 检查、多尺寸浏览器视觉预览、WebView2 host self-test 和 bridge 白名单检查。
15. Web UI 不得承载 Core 重任务或复制 C# 业务核心，CI 应保留对应边界检查。
16. v0.1.3 起必须验证普通启动进入 Web UI，并单独验证 `--legacy-ui` 仍可启动旧 WinForms 备用界面。

稳定准入、main 准入与正式 Release 都必须基于对应准确 head 或 main SHA 的成功验证，不得拿旧 run 代替。

## C-09｜实机响应性验收

CI 不能替代用户真实 Windows 机器响应性验证。Phase 1A 的关键实机标准是：

- 后台波形解析和 SenseVoice 等重任务期间，主窗口仍可拖动、缩放、切页和滚动。
- 主要 CPU/内存负载应落在 `LocalSub.Core.exe`。
- 手动结束 `LocalSub.Core.exe` 时，`LocalSub.exe` 不退出，当前任务失败，下一次后台操作可以重新启动 Core。
- 关闭 LocalSub 后 Core 不长期残留。
- 若仍出现未响应，优先检查 `Logs/core.log` 与 `Logs/responsiveness.log`。

尚未由用户实机确认的项目只能标记为“待验证”，不得写成“已验证”。

## C-10｜交付、版本与发布

- 每个完成并面向用户交付测试包的开发轮次都必须前进版本号，默认递增 patch 版本；同一轮内部修复提交不重复递增版本。
- Shell 与 Core 工程版本必须始终一致，CI 必须核对实际 Core IPC 返回版本。
- 每轮结束都必须向用户提供与本轮 exact-head 成功 CI 对应的可测试 EXE/候选包，不得只给提交 SHA。
- 日常验证优先提供相对用户现有绿色目录的增量覆盖包。
- Phase 1A 架构变化后，增量包至少包含 `LocalSub.exe` 与 `LocalSub.Core.exe`；现有 `ASR/`、`ASR/_runtime/`、Assets、Components、config 和模型默认不覆盖。
- 正式 Release 必须遵守 B 级发布规则，固定 `main` 准确提交、不可移动标签、正式资产、SHA-256、自动验证结论和实机验证状态。
- `RELEASE.md` 记录最近一次已授权正式发布版本，可以落后于 `p105-exp` 的开发候选版本；开发候选不得低于该正式版本。
- 只有用户明确授权正式发布并从 `main` 执行 formal release 时，`RELEASE.md` 才更新为待发布版本，并且必须与 Shell/Core 工程版本完全一致；既有正式标签不得复用。
- 默认情况下，Phase 1A 关键实机项未确认时不主动发布正式版本。
- 当用户明确要求将当前稳定候选正式固化并发布时，可以在完整 exact-main Windows 自动门禁通过后创建正式 Release，但 Release Notes 必须明确列出仍未完成的真实机器验证项，并且不得把自动 CI 成功表述成用户实机验收成功。
- 发布完成后 `p105-exp` 与 `p105-stable` 必须非强制快进到发布所对应的最新 `main`；P105 不保留其他长期或版本专用分支。

## C-12｜Web UI 视觉基线

自 v0.1.5 起，Web 主界面以最新版 DavBridge v0.4.10 的成熟桌面布局为主要视觉参照，后续页面迁移默认遵守：

- 一级页面固定使用左侧导航，不再把一级导航移动到顶部。
- 右侧工作区保持单栏连续流，禁止页面级“主内容 + 右侧详情/状态栏”的二次左右分栏。
- 模型详情、任务状态和操作区优先进入当前页面下方或同一卡片内，不建立独立右侧 inspector。
- 默认外窗尺寸固定为 1100×825，采用 4:3 比例；最小窗口保持 900×675，并纳入自动视觉检查。
- 配色采用浅灰白背景、明亮低饱和蓝色主强调、绿色正常状态和少量紫色功能区分，避免脏灰、重阴影与大面积深色。
- 左侧导航图标、页面功能图标和设置项图标使用较大的线性 SVG，强调识别性，不使用单个汉字充当功能图标。
- 页面只保留完成操作必需的短文字。原理说明、边界解释和辅助注释优先进入悬浮提示。
- Tooltip 必须使用 DavBridge v0.4.10 同类浅色浮层，并通过 Vue Teleport 挂到 body，使用全局最高层级，禁止恢复黑底 tooltip，也不得被卡片、滚动容器或 WebView 页面层级遮挡。
- 字体优先 Segoe UI Variable / Segoe UI。左侧一级导航约 15 px，主要表单与正文约 13–14 px，页面标题约 23–27 px；不得再以极小字号换取“精致感”。
- 卡片只用于明确功能容器。能通过分隔线、设置行、状态行和留白表达的内容，不重复套卡片。
- 1100×825 必须覆盖实时、后台、模型、设置和文档五页预览；实时页额外保留 900×675 响应检查。
- 自动截图只能发现明显视觉错误，最终视觉事实仍以用户真实 Windows 为准。

CI 必须锁定左侧一级导航、1100×825 默认窗口、body 级浅色 Tooltip，并阻止一级导航再次回退为顶部 Tab。

以上视觉约束不得改变 Application Contract、Core 所有权或 bridge 权限边界。

## C-13｜主页、滚动与后台生命周期

自 v0.1.6 起：

- Web 默认页固定为主页。主页只承担总体就绪状态、自检和实时字幕主开关，不堆叠高级配置。
- 实时页保持自然背景和纵向设置行。输入历史只能基于 Shell 已提供的节流归一化 `live.level` 累积，不得把原始音频送入 Vue。
- 右侧外层 `.workspace` 禁止滚动。确有长内容时只允许明确边界的内部模型表、设置区等滚动容器滚动，滚动条默认隐藏并在用户交互时出现。
- 模型页默认进入“配置”，只显示实时默认模型、后台默认模型和必要组件。完整 catalog 放入“模型库”，评分、语言、体积、状态和操作优先使用表格。
- 设置修改必须经过 Shell 显式白名单命令，不允许 Vue 直接读取或写入 `config.json`、注册表或其他本地文件。
- Windows 开机启动只允许写当前用户 HKCU Run，不要求管理员权限。
- `--startup-silent` 只表示静默进入托盘，不改变普通双击行为。
- AutoStartLive 使用 PotPlayer 音源时，如未检测到 PotPlayer，必须保持等待并在检测到后再启动。禁止静默回退到 All Audio。
- 托盘必须保留显示窗口、开始/停止实时字幕、状态和显式退出入口。
- CI 的设置 bridge smoke 不得向发布目录落入用户配置或修改真实启动注册；测试必须保持 ephemeral。
