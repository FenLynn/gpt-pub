## 当前事实

- v0.1.1 正式 Release 源码固定在 `225eafadb09f1553980153839f9d7c02bb79439c`，既有正式标签和 Release 不移动。
- Phase 1A 已把后台媒体分析和后台离线 ASR 移入 `LocalSub.Core.exe`。
- 当前最大的剩余 Shell 重耦合是 `LiveAsrPipeline`，其中仍包含 WASAPI、PotPlayer Process Loopback、实时模型加载、VAD、音频 queue 和实时解码。
- LocalSub 已实际依赖 WebView2，并使用透明 WebView2 字幕 Overlay，因此未来主 Web UI 不需要引入全新的浏览器运行时。
- `docs/APP_CONTRACT.md` 已建立第一版，冻结 Shell、Core、Web UI 所有权、snapshot、白名单命令、实时 session 与回退规则。
- 原来的严格 `1A → 1B 全部完成 → Phase 2` 顺序已调整为 contract-first 渐进迁移。
- Phase 1A 的用户特定高负载 GUI 响应性仍待真实机器确认，自动 CI 不替代该结论。

## 当前唯一开发断点

下一代码阶段只在 `p105-exp` 处理 Phase 1B.1：

1. 为 Core 增加 realtime session 状态机。
2. 增加 `live.start / live.stop`。
3. 增加 `live.status / live.level / live.partial / live.final / live.discontinuity / live.failed`。
4. 将 `LiveAsrPipeline` 的音频捕获、实时模型加载和解码循环迁入 Core。
5. Shell 保留 PotPlayer 进程发现、PID、窗口 bounds 与 Overlay 跟随。
6. 保持现有 WinForms UI 暂时可用，用它验证新 Core realtime API。
7. 该阶段稳定后建立 Vue 主 Shell，不直接翻译 `MainForm`。

## 当前验证原则

- 每一小阶段都必须在当前 `p105-exp` exact head 上通过 P105 CI。
- 新架构尚未提升到 `p105-stable` 前，stable 继续作为旧可运行基线。
- Web UI 自动截图只能作为布局检查，不能替代用户 Windows 实机视觉验收。
- 正式 Release 仍必须由用户对明确版本单独人工授权。
