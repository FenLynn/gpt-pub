## 本轮候选

功能代码提交：`0ff1cd4dc308ce684e882a3e0c7724304da1ecb4`

本轮主要变化：

- Shell/Core 连接增加 generation 代际，旧 reader loop 不得误伤重连后的新请求。
- Core 进程异常退出后当前 generation 立即标记失效并结束对应 pending request。
- 下一次后台请求重新启动新的 `LocalSub.Core.exe`，不复用已断开的 Pipe。
- 用户取消重任务后先发 `cancel`，若 1.5 秒内 Core 不收敛，则回收 worker，下一任务从新 Core 开始。
- Shell 正常退出时主动向共享 Core 发送 shutdown，并等待短时正常退出，超时才强制结束。
- 新增 `Logs/core-client.log`，记录连接 generation、PID、断开和恢复原因。
- Windows CI 新增真实故障注入：先建立 Core 请求，再强杀 Core，要求当前请求失败，随后同一个 Shell client 自动启动第二个 Core 并再次 ping 成功。
- Shell 与 Core 版本统一提升到 `0.1.1`，候选包名改为 `LocalSub-v0.1.1-dev-win-x64-net8.zip`。

## 用户实机验收重点

候选包生成后只需覆盖 `LocalSub.exe` 与 `LocalSub.Core.exe`，原 `ASR/`、`ASR/_runtime/`、Assets、Components、config 和模型保持不动。

重点验证：

1. 后台导入一个此前容易造成卡顿的视频。
2. 波形生成和 SenseVoice 转写期间持续拖动、缩放、切页和滚动。
3. 任务管理器中主要重负载应进入 `LocalSub.Core.exe`。
4. 转写期间手动结束 `LocalSub.Core.exe`，主窗口必须继续存活，当前任务明确显示失败。
5. 再次发起后台任务，应自动出现新的 `LocalSub.Core.exe` 并继续工作。
6. 关闭 LocalSub 后确认 Core 不长期残留。
7. 异常时同时检查 `Logs/core.log`、`Logs/core-client.log` 和 `Logs/responsiveness.log`。
