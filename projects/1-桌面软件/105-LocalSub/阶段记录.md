## v0.1.1 Core 恢复加强

v0.1.1 增加：

- Shell/Core connection generation 隔离。
- Core 异常退出后只失败所属 generation 的 pending request。
- 下一后台请求重新启动新的 Core。
- cancel 1.5 秒不收敛时回收 worker。
- Shell 正常退出主动 shutdown Core。
- `Logs/core-client.log` 记录连接、断开和恢复。
- Windows CI 真正强杀第一 Core，验证当前请求失败、同一 Shell client 拉起第二 Core并建立 generation 2。

## v0.1.1 正式发布设计

- Shell/Core 工程版本均为 `0.1.1`。
- `RELEASE.md` 是显式发布标记，当前声明 `Version: 0.1.1`。
- 正式标签固定为 `p105-v0.1.1`，不得移动或复用。
- 正式 Release 固定名为 `LocalSub v0.1.1`。
- 长期 `p105-localsub-ci.yml` 同时承担发布前 exact-main 构建验证，不创建版本专用 P105 分支或长期重复 workflow。
- 只有 main 合并提交实际修改 `RELEASE.md` 时才执行正式发布步骤。
- 发布 workflow 在准确 main SHA 重新执行完整 Windows build、Core IPC、Core 强杀恢复、Shell 启动、后台工作区、Process Loopback、sherpa runtime、native offline ASR 和 Runtime/Data 边界检查。
- 发布包生成文件清单并重新解压核对大小和 SHA-256。
- 正式资产包括完整 Windows x64 基础包、双 EXE 增量包与 SHA-256 清单。
- 发布成功后非强制快进 `p105-exp / p105-stable` 到发布 main，并验证 P105 只剩这两条长期分支。

## 实机状态

**用户特定高负载 GUI 响应性仍待真实机器验证。**

自动 fault injection 可以证明 Core supervisor/IPC 恢复状态机，但不能证明用户自己的媒体、模型和机器负载下 WinForms 消息循环绝不阻塞。用户已明确要求当前稳定候选正式发布，因此 v0.1.1 可以在完整 exact-main 自动门禁通过后发布，但 Release Notes 必须明确披露该待验证项，不得把自动 CI 写成实机确认。
