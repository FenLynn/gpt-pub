# 设计与演进

## 1. 产品定位

LaserBench 不是把 StarLab、BeamSquared、AQ6370D Viewer 或示波器前面板重新实现一遍，而是提供统一的实验观测、离散 Test 采集、原始数据整理和后续对账入口。

核心区分：

```text
Dashboard = 看
独立页 = 调
Floating = 辅助监视
Test = 离散数据锚点
Record = 持续视觉记录
```

## 2. 为什么首版选择 WinForms 自绘

LaserBench 需要高密度曲线、极窄工具栏、拖动和浮窗，同时基础包要求轻量、可移动、更新快，不提前捆绑大型 UI Runtime。

当前路线：

```text
WinForms
+ 自绘图表
+ 设备抽象层
+ Simulator
```

后续只有真实功能证明现有 UI 技术无法满足时才讨论迁移。

## 3. 两层 EXE

Portable 包使用：

```text
LaserBench.exe      NativeAOT dependency launcher
LaserBench.App.exe  framework-dependent .NET 8 WinForms app
```

如果主电脑缺少 .NET Desktop Runtime，NativeAOT 启动器仍能先完成检测并给出在线与离线修复入口。

## 4. 数据优先

磁盘结构保持简单：

```text
data/exp/<日期或自定义实验目录>/数据文件
data/pic/截图
data/video/录像
```

一次 Test 可以同时关联多个设备，但不为每次 Test 新建文件夹。共同点击时间与 Label 用于快速归类，文件内部和后续索引继续保留真实设备时间。

## 5. Never overwrite

任何目标文件已经存在时，不覆盖，而是产生：

```text
name.ext
name_1.ext
name_2.ext
```

保存组件不向设备驱动暴露 overwrite 快捷路径。

## 6. Dashboard 信息层级

Dashboard 不使用传统大卡片、宽边距和阴影。屏幕主体由图占据：

```text
Power      Spectrum
Beam       Scope
```

四块只使用中央细虚线分隔。Windows 原生标题栏保留；应用控制栏保持单行极窄；左侧导航默认折叠。低频设置进入各模块独立页。

视觉规则：

- 应用壳体使用冷浅蓝灰，绘图区使用白色。
- 绘图内部网格统一虚线，绘图区边界统一实线。
- Legend 透明、无边框并放图内。
- 字体使用紧凑层级，实时数值比 Alias 和说明文字更突出。
- 状态色只用于在线、忙碌、错误、录像、Trace 等真正需要区分的对象。

## 7. v0.2.0 主页面精修原则

### Power

左侧主曲线区和底部时间总览条保持连续视觉关系，右侧读数区独立。物理功率使用左纵轴，计算百分比等数学通道使用右纵轴，避免把不同量纲硬塞进同一尺度。右侧只显示当前值和少量统计槽，默认保留 Channel 1 Max。

### Spectrum

顶部只占一行，显示 λc、3 dB linewidth、RMS linewidth、功率和当前 OSA。扫描、通信、Trace 模式等配置进入独立页。Simulator 必须产生正常光谱峰形。

### Beam

左侧光斑、右侧 caustic 同屏。Z 条表示已经采集的轴向光斑浏览位置，拖动时只改变左侧显示，并在右侧 caustic 上同步当前位置参考线；绝不能借此改写 caustic。底部只允许一行：Z、浏览播放、Att、M²x、M²y、M̄²。

### Scope

Dashboard 只保留时域和 FFT 两张上下堆叠图，最多两个通道。独立纵轴、触发和采集配置留在 Scope 独立页。

## 8. 真机接入原则

每个真实仪器都必须实现统一抽象并先通过最小 Probe。Simulator 与真实 Driver 产生同类测量对象和保存格式，因此接入硬件不允许重写 Dashboard 或数据模型。
