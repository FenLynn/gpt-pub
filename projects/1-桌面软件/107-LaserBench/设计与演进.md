# 设计与演进

## 1. 产品定位

LaserBench 不是重新实现 StarLab、BeamSquared、AQ6370D Viewer 或示波器完整前面板，而是提供统一的实验观测、离散 Test 采集、原始数据整理和后续对账入口。

核心区分：

```text
Dashboard = 看
独立页 = 调
Floating = 辅助监视（目标能力，Web UI 生产版尚未恢复拖出交互）
Test = 离散数据锚点
Record = 持续视觉记录
```

## 2. UI 技术路线的演进

v0.1-v0.2 首版选择 WinForms 自绘，是为了快速建立 Portable、采集、安全保存和高密度仪器界面骨架。

随着主工作台进入高频视觉迭代，v0.3.0 已完成生产 UI 迁移，当前正式路线为：

```text
Vue 3 + TypeScript + Vite + Canvas
            ↓ typed JSON bridge
Microsoft WebView2 Evergreen Runtime
            ↓
C# / .NET 8 WinForms thin host
            ↓
LaserBench Core / Device Abstraction
            ↓
Simulator / future real drivers
```

因此“WinForms 自绘主页面”是历史阶段，不再是当前生产 UI。旧 `DashboardControl`、`ModuleViews`、`NavigationPages`、`UiPrimitives` 只保留作回滚参考。

## 3. 生产边界

C# 拥有：

- 设备通信、采集、缓存和数值模型；
- Test 点击瞬间的配置冻结；
- Portable 路径、配置持久化和 never-overwrite；
- 截图、录像和启动诊断；
- Simulator 与未来厂商 Driver。

Vue/Web UI 拥有：

- 页面布局和交互；
- Canvas 高频绘图；
- 用户意图收集；
- 通过白名单 typed JSON bridge 调用 C#。

不得把厂商 SDK、文件安全策略或另一套采集状态机复制进前端。

## 4. 两层 EXE 与运行依赖

Portable 包使用：

```text
LaserBench.exe      NativeAOT dependency launcher
LaserBench.App.exe  framework-dependent .NET 8 WinForms host
```

基础外部运行依赖为：

```text
Microsoft .NET 8 Desktop Runtime x64
Microsoft Edge WebView2 Evergreen Runtime
```

启动器在进入主程序前检查两者。WebView2 默认使用系统 Evergreen Runtime，不随基础 Portable 包捆绑大型 Fixed Version Runtime。

## 5. 数据优先

磁盘结构保持简单：

```text
data/exp/<日期或自定义实验目录>/数据文件
data/pic/截图
data/video/录像
```

一次 Test 可以同时关联多个设备，但不为每次 Test 新建文件夹。共同点击时间与 Label 用于快速归类；真实设备接入后，文件内部继续保留各设备自己的源时间信息。

## 6. Never overwrite

任何目标文件已经存在时，不覆盖，而是产生：

```text
name.ext
name_1.ext
name_2.ext
```

离散文本数据先写 partial，再以不覆盖方式移动到最终文件名。真实 Driver 不获得绕开该层的 overwrite 快捷路径。

## 7. Dashboard 信息层级

v0.4.25 延续 Dashboard 的核心原则从“高密度卡片”进一步收紧为 **Graph-first**：

```text
图 = 主体
结果 = 贴边
参数 = 模块页
Big Readout = 远距监视
```

四象限结构仍保持 Power / Spectrum / Beam / Scope。模块名和关键结果占用较窄但可读的标题行，并与壳体使用同一底色；Dashboard 不显示 X/Y 轴标题文字，坐标刻度留在深色 gutter；只有真正的数据矩形使用白底。顶部采集选择图标与模块左上图标选中时同步绿色，但动态反馈只存在于顶栏四个采集选择图标；模块标题图标固定静态。顶栏使用内联 SVG + CSS：Power 四根粗 bar 缓慢起伏，Spectrum 单峰纵向变高/变低，Scope 持续向左流动，Beam 固定十字 target、仅外环扩散。

### Power

Power 历史采用“启动后从左向右填充，满窗后滚动”的工业趋势图语义。下方 overview 使用左右两个真实范围手柄：默认位于窗口两端，中间为显示区，外侧弱化；拖动只改变观察范围，不改变采集数据。Dashboard 与 Power 独立页必须共享同一对手柄状态。

物理功率继续使用左轴，数学百分比继续使用右轴。Power 独立页管理活动通道、历史窗口、Dashboard Trace、移动平均、Offset、Scale、Normalize、Power density、Zero 与 Pass/Fail。显示开关只影响观测，不改变 Test 的采集选择。

### Spectrum

Dashboard 只保留光谱曲线和中心波长、3 dB、RMS、功率等结果。Spectrum 独立页按 OSA 工作流管理 Start/Stop、Center/Span、RBW、Sensitivity、Average、Sweep、Reference level、dB/div、Reference trace 与 Peak marker。

### Beam

光斑与 caustic 尽量占满模块。v0.4.17 起光斑视图不显示色条或比例尺，支持滚轮缩放、左键拖动、双击复位；光斑左边界与 Power 数据区对齐，上下边界与 caustic 数据区对齐。Z 浏览、自动播放和 Attenuation 因实验中高频使用继续常驻 Dashboard；其他设置进入 Beam 独立页。M²x、M²y、M² 作为结果贴边显示，caustic X 方向保留少量安全边距避免 marker 裁切。Beam 独立页围绕 2D profile、beam width、ellipticity、D4σ/FWHM、outlier 和 X/Y caustic 组织，不加入 3D 光斑。

### Scope

Dashboard 只保留时域与 FFT。Scope 独立页负责 Time span、FFT upper limit、Volts/div、Offset、Coupling、CH1/CH2、Trigger 与 Acquisition/Average。

### 独立模块页

独立模块页采用与 Dashboard 不同的舒展工作布局：左上图标/名称/状态可占两行；其下横排完整关键数据；中央/下方为主要图形；右侧固定放置该模块完整配置。独立页常驻显示轴标题和单位，不使用浅色页面卡片，只有实际数据图区域白底。

### Big Readout

Dashboard 中的关键结果可分别打开 Big Readout，多个不同指标可同时存在。每个窗复用同一 Snapshot，独立保存位置、等比例缩放和黑/白主题；同一指标再次点击只把已有窗口提到最前。左上状态点/名称常显，右上黑白切换与关闭及右下缩放柄默认隐藏、hover/focus 时显示。Big Readout 只在 Dashboard 渲染，进入模块页时隐藏；该能力用于远距离读数，不等同于模块 Floating。

## 8. Floating 状态

Embedded 与模块聚焦页已属于当前 Web UI 工作流。旧 WinForms 曾实现的“从模块拖出形成浮窗、拖回自动嵌入”在 Web UI 生产版尚未恢复。

Floating 仍是产品目标，但恢复时必须复用同一后台数据源和状态，不能启动第二套设备会话。

## 9. 真机接入原则

每个真实仪器必须先完成最小 Probe：依赖检测、枚举/连接、最小读取、时间戳、错误释放和真实 Windows 行为。

Simulator 与真实 Driver 应产生同类测量对象和保存语义，因此接入硬件不得重写 Dashboard，也不得绕开统一安全保存层。0.5.x 起优先按 Ophir Juno → Yokogawa AQ6370D → BeamSquared/SP920 → Tektronix MSO44 顺序推进。


### v0.4.21 动态与轴辅助信息

采集动画必须慢、稳定、可识别，但不能抢夺 Plot 视觉注意力。Power 只做四根粗 bar 的电平变化；Beam 的十字定位线永久静止，仅外圈缓慢变化。轴标题属于低频辅助信息，因此通过轴中央 hover 延迟呼出，而不是常驻显示。


### v0.4.22 顶栏动态边界

动态状态只服务“本次采集选择”，因此集中在顶栏四个选择器；Dashboard 每个模块左上标题图标是结构标识，应保持静止。结果数据属于 Plot 的附属读数，应贴近对应数据框上沿；分隔线位于相邻指标之间的等距中点，不允许因 M² 或其他模块出现独立排版例外。


### v0.4.23 可验证动画与趋势窗

动态图是否“存在”以 WebView2 实际解码为准，而不是以仓库中有 GIF 文件为准。Power 底部 overview 是显示范围选择器：左右各一个手柄，默认占满完整历史窗；拖动只改变观察窗口，不改变采集数据。顶部结果组可以有轻微独立背景以提高读数识别度，但不能覆盖或裁切 Plot 的端点刻度。


### v0.4.24 动画实现原则

顶栏采集动画属于矢量状态反馈，不再使用低分辨率位图动图。实现必须满足三点：只在顶栏运动、模块标题静止；整体周期慢但渲染连续；是否可用以 WebView2 Web Animations API 时间轴推进为准，而不是以资源文件存在为准。


### v0.4.25 工作页设计边界

模块页的目标不是复制厂商完整前面板，而是把实验中最常用的基础操作按熟悉语义集中到 LaserBench：Power 参考功率计软件常用测量处理；Spectrum 参考 OSA 常用扫描/显示/marker；Beam 参考 BeamSquared 的 2D/M² 工作流；Scope 提供主要水平、垂直、触发与采集参数。真实硬件接入前，能在 Simulator/显示层闭环的设置立即生效；依赖真实仪器的参数先进入统一配置模型，后续由对应 Driver 映射，不在前端伪造第二套设备状态。
