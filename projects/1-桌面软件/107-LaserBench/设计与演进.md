# 设计与演进

## 1. 产品定位

LaserBench 不是把 StarLab、BeamSquared、AQ6370D Viewer 或示波器前面板重新实现一遍，而是提供统一的实验观测、离散 Test 采集、原始数据整理和后续对账入口。

核心区分：

```text
Dashboard = 看
独立页 = 调
Floating = 辅助监视
Test = 离散数据锚点
Record = 持续视觉记录
```

## 2. 为什么首版选择 WinForms 自绘

LaserBench 需要高密度曲线、极窄工具栏、拖动和浮窗，同时用户要求基础包轻量、更新快、不要一次捆绑大量依赖。

v0.1.x 因此选择：

```text
WinForms
+ 自绘图表
+ 设备抽象层
+ Simulator
```

而不是在第一版复制 DavBridge 的 WebView2/Vue 结构。后续只有在真实功能证明现有 UI 技术无法满足时才讨论迁移。

## 3. 两层 EXE

完整 Portable 包包含：

```text
LaserBench.exe      NativeAOT dependency launcher
LaserBench.App.exe  framework-dependent .NET 8 WinForms app
```

原因：如果主电脑缺少 .NET Desktop Runtime，framework-dependent 主程序本身无法显示友好的环境修复入口。NativeAOT 启动器可以在没有 .NET Runtime 时先完成检测，并提供在线与离线两条路径。

## 4. 数据优先

磁盘结构保持简单：

```text
data/exp/<日期或自定义实验目录>/原始文件
data/pic/截图
data/video/录像
```

逻辑上一次 Test 可以同时关联多个设备，但不为每次 Test 新建文件夹。共同点击时间与 Label 使同轮数据可以人工快速归类，文件内部和后续索引继续保留真实设备时间。

## 5. Never overwrite

实验数据安全优先于文件名整洁。任何目标文件已经存在时，不覆盖，而是产生：

```text
name.ext
name_1.ext
name_2.ext
```

保存组件不向设备驱动暴露 overwrite 快捷路径。

## 6. Dashboard 层级

Dashboard 不再使用传统大卡片和宽边距。屏幕主体由图占据：

```text
Power      Spectrum
Beam       Scope
```

四块只使用轻量分隔线。所有低频参数进入各模块独立页。

## 7. 真机接入原则

每个真实仪器都必须实现统一抽象并先通过最小 Probe。Simulator 与真实 Driver 产生同类测量对象和保存格式，因此接入硬件不允许重写 Dashboard 或数据模型。
