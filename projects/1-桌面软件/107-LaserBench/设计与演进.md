# 设计与演进

## 1. 产品定位

LaserBench 不是重新实现 StarLab、BeamSquared、AQ6370D Viewer 或示波器完整前面板，而是提供统一的实验观测、离散 Test 采集、原始数据整理和后续对账入口。

核心区分：

```text
Dashboard = 看
独立页 = 调
Floating = 辅助监视（目标能力，Web UI 生产版尚未恢复拖出交互）
Test = 离散数据锚点
Record = 持续视觉记录
```

## 2. UI 技术路线的演进

v0.1-v0.2 首版选择 WinForms 自绘，是为了快速建立 Portable、采集、安全保存和高密度仪器界面骨架。

随着主工作台进入高频视觉迭代，v0.3.0 已完成生产 UI 迁移，当前正式路线为：

```text
Vue 3 + TypeScript + Vite + Canvas
            ↓ typed JSON bridge
Microsoft WebView2 Evergreen Runtime
            ↓
C# / .NET 8 WinForms thin host
            ↓
LaserBench Core / Device Abstraction
            ↓
Simulator / future real drivers
```

因此“WinForms 自绘主页面”是历史阶段，不再是当前生产 UI。旧 `DashboardControl`、`ModuleViews`、`NavigationPages`、`UiPrimitives` 只保留作回滚参考。

## 3. 生产边界

C# 拥有：

- 设备通信、采集、缓存和数值模型；
- Test 点击瞬间的配置冻结；
- Portable 路径、配置持久化和 never-overwrite；
- 截图、录像和启动诊断；
- Simulator 与未来厂商 Driver。

Vue/Web UI 拥有：

- 页面布局和交互；
- Canvas 高频绘图；
- 用户意图收集；
- 通过白名单 typed JSON bridge 调用 C#。

不得把厂商 SDK、文件安全策略或另一套采集状态机复制进前端。

## 4. 两层 EXE 与运行依赖

Portable 包使用：

```text
LaserBench.exe      NativeAOT dependency launcher
LaserBench.App.exe  framework-dependent .NET 8 WinForms host
```

基础外部运行依赖为：

```text
Microsoft .NET 8 Desktop Runtime x64
Microsoft Edge WebView2 Evergreen Runtime
```

启动器在进入主程序前检查两者。WebView2 默认使用系统 Evergreen Runtime，不随基础 Portable 包捆绑大型 Fixed Version Runtime。

## 5. 数据优先

磁盘结构保持简单：

```text
data/exp/<日期或自定义实验目录>/数据文件
data/pic/截图
data/video/录像
```

一次 Test 可以同时关联多个设备，但不为每次 Test 新建文件夹。共同点击时间与 Label 用于快速归类；真实设备接入后，文件内部继续保留各设备自己的源时间信息。

## 6. Never overwrite

任何目标文件已经存在时，不覆盖，而是产生：

```text
name.ext
name_1.ext
name_2.ext
```

离散文本数据先写 partial，再以不覆盖方式移动到最终文件名。真实 Driver 不获得绕开该层的 overwrite 快捷路径。

## 7. Dashboard 信息层级

Dashboard 不使用传统大卡片、宽边距和阴影。屏幕主体由图占据：

```text
Power      Spectrum
Beam       Scope
```

四块使用统一工业化语言。Windows 原生标题栏保留；应用控制栏保持单行极窄；左侧导航保持窄并可折叠。低频配置进入 Settings 或模块聚焦页。

视觉规则：

- 应用壳体冷浅蓝灰，绘图区白色。
- 绘图内部网格虚线，绘图区边界实线。
- Legend 透明、无边框并放图内。
- 实时数值比 Alias 和说明文字更突出。
- 状态色只用于在线、忙碌、错误、录像和 Trace 等真正需要区分的对象。

### Power

物理功率使用左轴，数学百分比使用右轴。时间总览条属于左侧曲线区，右侧只保留当前值和少量统计。

### Spectrum

顶部单行显示中心波长、3 dB linewidth、RMS linewidth、功率和当前 OSA；扫描与通信等低频参数不挤入 Dashboard。

### Beam

Z 是已采集轴向光斑的浏览位置，只改变当前光斑并在 caustic 上同步参考线，不改写 caustic。

### Scope

Dashboard 最多两个通道，显示时域与 FFT。CH1/CH2 开关必须对两张图使用同一选择语义。

## 8. Floating 状态

Embedded 与模块聚焦页已属于当前 Web UI 工作流。旧 WinForms 曾实现的“从模块拖出形成浮窗、拖回自动嵌入”在 Web UI 生产版尚未恢复。

Floating 仍是产品目标，但恢复时必须复用同一后台数据源和状态，不能启动第二套设备会话。

## 9. 真机接入原则

每个真实仪器必须先完成最小 Probe：依赖检测、枚举/连接、最小读取、时间戳、错误释放和真实 Windows 行为。

Simulator 与真实 Driver 应产生同类测量对象和保存语义，因此接入硬件不得重写 Dashboard，也不得绕开统一安全保存层。0.5.x 起优先按 Ophir Juno → Yokogawa AQ6370D → BeamSquared/SP920 → Tektronix MSO44 顺序推进。
