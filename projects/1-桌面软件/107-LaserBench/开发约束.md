# LaserBench 开发约束

> 约束层级：C｜项目级  
> 适用范围：P107 LaserBench  
> 上位规则：A｜`/GPT_RULES.md`；B｜`../开发约束.md`

本文件保存 LaserBench 当前长期有效、后续版本不得随意破坏的产品与工程约束。

## C-01｜项目身份与写入范围

- 产品名称固定为 **LaserBench**，项目编号固定为 **P107**。
- 正式路径固定为 `projects/1-桌面软件/107-LaserBench/`。
- 长期分支为 `p107-exp`、`p107-stable` 和 `main`。
- P107 只允许修改 P107 项目目录、P107 活动 CI，以及确有必要的 P107 共享入口状态行。
- 不修改其他项目源码、CI、版本、Release 或长期分支。

## C-02｜公开边界

- 本公开仓库只允许保存通用仪器软件代码、公开安全文档、Simulator、匿名测试和可再生构建产物。
- 不提交真实实验原始数据、未公开研究结论、真实实验标签、真实仪器序列号、实验室私人路径、截图、录像或日志。
- CI 与 Artifact 只能使用 Simulator 和公开安全数据。

## C-03｜技术栈与轻量原则

- Windows x64、C#、.NET 8 和 WinForms 原生宿主继续作为基础运行平台。
- v0.3.0 起生产业务 UI 固定为 **WinForms Host + Microsoft WebView2 + Vue 3 / TypeScript / Vite + HTML Canvas**；设备、采集、保存和数值逻辑不得复制到 JavaScript。
- 不使用 Electron，不引入第三方图表库；高频图表继续使用 Canvas 或原生轻量绘制。
- 主程序默认 framework-dependent 单文件发布，避免重复打包完整 .NET Runtime；WebView2 默认使用系统 Evergreen Runtime，不随基础 Portable 包捆绑大型 Fixed Version Runtime。
- `LaserBench.exe` 为 NativeAOT 轻量启动器，在主程序启动前执行基础运行依赖检测。
- 新依赖只有在真实功能需要且完成体积、许可证、在线/离线安装和 Portable 边界评估后才能引入。
- 厂商 SDK、驱动或大型运行库不得因为“以后可能会用”提前塞入基础包。

## C-04｜Portable 根目录

- LaserBench 是 Portable 软件，默认不安装到 `Program Files`，不把产品配置、状态和数据拆到 AppData。
- 软件根目录是配置、数据和运行状态的共同便携边界。
- 默认目录固定为：

```text
config/
data/exp/
data/pic/
data/video/
logs/
runtime/
```

- 根目录不可写时必须明确停止并提示用户移动完整软件目录，不得静默回退到 AppData。
- Windows 注册表只允许读取系统或厂商依赖状态，不作为 LaserBench 用户配置持久化位置。

## C-05｜实验数据目录

- `data/exp/` 下一层必须是用户自定义实验文件夹，或未指定时自动建立的 `YYYY-MM-DD` 日期文件夹。
- `data/exp/<实验文件夹>/` 下一层直接保存原始或导出数据文件，不为每个 Anchor 再创建子文件夹。
- `data/pic/` 下直接保存截图，不创建日期文件夹。
- `data/video/` 下直接保存录像，不创建日期文件夹。
- 用户自定义实验文件夹跨午夜继续使用，直到用户主动切换；默认日期目录在日期变化后下一次 Test 自动切换到新日期。

## C-06｜命名、Label 与 Alias

- Test 数据文件默认命名为 `HHmmss_<channel-or-device>_<label>.<ext>`。
- Label 为空时省略 Label 段，不生成多余分隔符。
- Alias 一旦设置，前台显示和新文件名优先使用 Alias；未设置时使用 `power1`、`power2`、`osa1` 等稳定默认编号。
- 用户输入的 Label 和 Alias 在 UI 中保留原值；用于文件名时只做 Windows 文件名安全化，不擅自改变实验语义。
- 点击 Test 的瞬间必须冻结本轮目录、Label、Alias、选中设备和保存策略。采集中用户后续修改不得污染已启动的一轮。

## C-07｜永不覆盖

- LaserBench 对实验数据、截图、录像和导出文件执行硬性 **never overwrite**。
- 基础文件名已存在时依次追加 `_1`、`_2`、`_3`，后缀位于扩展名前。
- 不允许任何驱动绕开统一安全保存层直接使用 overwrite。
- 离散数据优先先写临时文件，完整关闭并落盘后再以不覆盖方式移动到最终文件名。
- 采集中的单个设备失败不得删除其他已经成功保存的数据。

## C-08｜采集模型

- Dashboard 实时显示与 Test 离散采集是两条不同的数据链。
- 每次 Test 允许独立勾选 Power、Spectrum、Beam、Scope，并在未来支持每类设备下继续选择具体通道。
- 不要求每个 Test 强制采集全部设备。
- 各设备可以具有不同时间尺度和采集策略，支持并行完成，慢设备不得阻塞已经完成的数据安全写盘。
- 真实设备接入后必须记录设备自己的开始、完成或源时间戳，不把所有数据伪装成同一时刻。
- 补采必须使用真实补采时间，不篡改旧文件时间。

## C-09｜Dashboard 信息架构

- Dashboard 只承担最终综合观测，不承担低频设备配置；**图是绝对主体**，模块标题、坐标标题、Legend 和读数应尽量贴边或悬浮，避免占用独立大块空间。
- 默认只有一条极窄应用控制栏和极窄折叠导航，四模块绘图区尽可能占满可用面积。
- Dashboard 非绘图区使用冷深蓝灰工业壳体；纯白只用于真实 Plot / 图像绘图区，不把模块容器、标题条和页面底板做成白色卡片。
- Power、Spectrum、Beam、Scope 四个模块使用同一工业化视觉语言，不使用大卡片标题、宽留白或装饰性面板。
- 低频参数必须进入对应 Power / Spectrum / Beam / Scope 独立页；全局 Settings 只保存跨模块设置。Dashboard 不得因参数增加重新膨胀成设置页面。
- **显示选择与采集选择严格分离。** Power 独立页允许逐个物理 Channel / Math Channel 决定是否进入 Dashboard；隐藏显示不得改变 Test 的采集选择。
- Beam 的 **Z 浏览 / 播放** 与 **Attenuation** 属于实验中高频即时控制，是 Dashboard 的明确例外，必须常驻且保持紧凑；其他低频 Beam 设置进入 Beam 独立页。Dashboard 光斑视图不显示色条或比例尺，使用鼠标滚轮缩放、按住左键拖动，双击复位。
- Dashboard 中用于最终判断的关键读数必须支持 **Big Readout**。当前至少包括 Power 当前值、Spectrum 中心波长/线宽/功率、Beam M²x/M²y/M̄²、Scope 通道当前值。Big Readout 应尽量包裹内容，避免为大数字保留无意义空白。
- Big Readout **允许多个不同指标同时弹出**；同一指标再次点击时把已有窗口提到最前，不重复创建。每个窗口独立保存位置、比例和黑/白主题，左上固定绿色状态点 + 小字指标名；右上黑/白切换与关闭、右下拖拽缩放手柄默认隐藏，仅在 hover/focus 时显示。缩放必须保持窗口与内部文字/控件相对比例不变。所有读数窗持续复用同一后台实时 Snapshot，不启动第二套采集。
- Legend 统一透明并放在真实数据区内部。Dashboard **不显示 X/Y 轴标题文字**（如 Time、Wavelength、Power、Voltage、Z 等），只保留必要刻度与数值；坐标刻度所在边缘属于深色壳体，纯白严格限于实际数据绘图区。
- Scope Dashboard 只显示最多两个通道的时域和 FFT，独立纵坐标等详细设置进入 Scope 单页；上下两张图之间的内部 gutter 应压到满足刻度可读的最小值，不得形成明显空带。
- 顶部采集选择图标与对应 Dashboard 模块左上角图标必须使用同一选择状态：被选中时变绿；采集状态为 running 时两处同时执行**模块语义动画**，使当前正在采集的模块一眼可见。Power 四条 bar 独立上下跳动；Spectrum 与 Scope 波形沿横向持续扫动；Beam 使用由内向外的同心环扩散。动画不得改变 Dashboard 几何尺寸。
- Dashboard 标题行与页面壳体使用同一底色，不额外加深形成第二层卡片；标题栏允许略高于极限紧凑值，以保证文字和状态可读。模块图标与模块名使用统一的标题强调色；测量结果值使用另一种高亮色；坐标刻度使用冷灰蓝低优先级色，三者必须有清晰层级。上下区域可按内容密度微调比例，Beam / Scope 等下半区不得因追求对称而过度拥挤。
- 设备有几个显示几个；未配置设备不伪造占位设备。测试中已存在设备掉线时保留错误状态并允许恢复。

## C-10｜页面、全屏与浮动

- Dashboard 与 Power、Spectrum、Beam、Scope 独立聚焦页必须共享同一后台数据源，切页不得停止实时数据。
- Dashboard 导航始终可以回到总览，不另造冗余返回链。
- 独立模块页承担该模块的显示选择、量程、窗口、扫描范围、通道和其他低频设置；这些设置不得重复塞回 Dashboard。独立模块页**不采用 Dashboard 的极限紧凑布局**，固定使用“顶部单条标题/状态栏 + 左上无卡片读数区 + 左下图形显示 + 右侧整列配置”的工作页结构。读数区不得再拆成大号卡片；模块页不显示额外 breadcrumb 与重复标题。
- Big Readout 是“每窗单指标、可多窗并存”的远距监视能力，与模块 Floating 不同；各读数窗可以在应用工作区内独立拖动、等比例缩放、切换黑白主题和关闭，不等同于已完成模块拖出浮窗。
- 每个模块仍必须保留 Embedded、独立页和未来 Floating 三种工作方式的架构边界。
- Floating 的目标交互仍为从模块拖出形成可调整大小的浮动窗口、拖回后嵌回原槽位；在 Web UI 生产版真正恢复并完成实机验证前，不得把该交互描述为已完成。
- 任何 Floating 或 Big Readout 实现不得复制设备连接或采集状态。

## C-11｜截图与录像

- 截图和录像属于应用级功能，入口位于最高层全局顶栏。
- 截图保存当前 LaserBench 应用画面到 `data/pic/`。
- 录像保存 LaserBench 应用画面到 `data/video/`，不代替原始测量数据。
- v0.1.x 优先使用内部低码率 MJPEG AVI，避免为基础录屏强制捆绑 FFmpeg。
- 录像失败不得中断实验数据采集。

## C-12｜Simulator 与真实硬件

- UI、数据保存和采集流程只能依赖设备抽象层，禁止直接把厂商 SDK 调用写进 Dashboard。
- v0.1.0 默认 Simulator 必须可以在无任何仪器、无厂商软件的电脑上完整运行。
- Simulator 数据应具有合理的时间变化、光谱、光束 caustic、时域与 FFT 形态，不使用无意义随机数冒充真实测试链。
- 真实硬件逐个接入，每个设备先完成硬件 Probe、依赖检测、命令最小闭环和真实 Windows 验证，再进入正式模块。

## C-13｜依赖检测、在线与离线

- 软件本体始终使用 Portable 包，不做传统安装器作为主交付形式。
- 每个必需或可选依赖必须有明确检测结果。
- 对缺失依赖同时提供在线动作与离线说明；在线动作只从可信官方来源或经过明确审查的供应源获取。
- 可便携解压的依赖放到 LaserBench 根目录下的 `runtime/`；必须系统安装的运行库按官方安装方式处理。
- v0.4.x 基础必需运行依赖为 **Microsoft .NET 8 Desktop Runtime x64** 与 **Microsoft Edge WebView2 Evergreen Runtime**。NativeAOT 启动器在主程序启动前检查两者；WebView2 检测使用 Microsoft 官方 Evergreen Runtime 注册信息。
- Portable 包提供官方来源的在线安装脚本，并在 `OFFLINE-DEPENDENCIES.txt` 记录离线准备方法。
- 未来厂商驱动与 SDK 按需出现，不提前打包。

## C-14｜版本与候选包

- 版本遵循 SemVer，首版为 `0.1.0`。
- 每次候选构建必须保证程序集版本、包名、manifest 和文档版本一致。
- 首次使用提供完整 Portable ZIP；后续迭代优先提供仅包含修改文件的增量覆盖包，并明确适用基线。
- 增量更新不得删除用户 `config/`、`data/`、`logs/` 或运行期文件。
- 普通 CI Artifact 不是正式 Release。标签和 GitHub Release 仍需当前会话对明确版本的单独人工授权。
