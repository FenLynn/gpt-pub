## 2026-09-20｜v0.5.0 真实仪器通信数据平面

- 用户明确把“设备接上后如何真正与软件通信”提升为当前最高优先级，因此停止把接口配置页当作 Driver 完成标准。
- 调研并按设备能力拆分通信：Juno 用 OphirLMMeasurement COM/USB；AQ6370D 用 Ethernet socket/SCPI；MSO44 用 raw TCP/SCPI；BeamSquared 因官方 Automation 依赖 .NET Framework/.NET Remoting，采用独立 net48 bridge 进程。
- 新增 InstrumentRuntime / HybridInstrumentProvider 及四个设备 worker。UI Snapshot 永远只读后台缓存，网络/COM/Automation I/O 不进入 WebView 250 ms 刷新线程。
- DataPlaneReady 从“配置字段”变为真实运行时事实：只有成功完成设备身份/最小读取并产生真实样本才为 true。
- CaptureService 增加 provenance gate：真实接口开启但设备未 ready 时，Test 不允许生成冒充真实硬件的数据文件。
- AQ worker 支持 10001 socket authentication、*IDN?、TRA X/Y；MSO worker支持 waveform preamble/CURVe? 和本地 FFT；Juno worker维护真机 history；Beam bridge 隔离厂商 net48 依赖。
- Web UI 驱动区加入通信类型、实时状态、identity、最后样本、失败次数和手动 Probe；Scope 采样率由真实 XINCR 回传，不再固定显示 2.5 MSa/s。
- CI 新增真实驱动源码门禁、BeamSquared net48 bridge 构建/缺依赖失败 smoke，并把 bridge EXE 装入 Portable runtime。
- 物理实机测试仍未执行，因此本记录只说明“驱动代码和候选包具备真实通信路径”，不等价于“实验室硬件已验收”。
- 最终协议审计进一步收紧真机语义：AQ6370D 不再定时盲读 TRA，SINGLE 每轮重新 INITIATE、REPEAT 只启动一次，并按官方 `:STAT:OPER:EVEN?` bit0 等待新 sweep 完成后再读；Juno 在 StartStream 前调用 GetMeasurementMode/SetMeasurementMode 强制标准 Power 模式，避免把 Energy/Exposure 当 W；MSO44 显式设置连续 RUNSTOP + ACQUIRE:STATE RUN，避免继承前面板 STOP/SINGLE 后持续读旧波形。
- BeamSquared 官方公开 Automation 示例确认 RailControl/QuantitativeResults/LaserResults 的调用路径与 M² API，但公开示例未给出 `QuantitativeResults.BeamWidthX/Y` 的单位契约；当前宽度换算必须在目标 BeamSquared/SP920 实机上与软件显示值逐点核对后才可宣布单位验收完成。
- UI 最终按驱动事实收口：AQ6370D 删除可见 VBW 和未映射峰值阈值控件，把平滑明确为 LaserBench 本地处理，并把波长偏移升级为真机 `:SENSE:CORRECTION:WAVELENGTH:SHIFT` / Simulator 本地模拟的双路径，防止真机重复偏移；BeamSquared 真机模式锁定 Z、Attenuation、自动 Z 浏览以及 Simulator Run/束宽算法/outlier 控件，右栏明确只读 bridge 与厂商 Run/rail/Ultracal 边界。
