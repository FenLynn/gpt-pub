# P110｜WorkStation 设计与演进

> 本文是**规划与设计依据**，不是已经实现的功能清单。当前冻结产品边界和验收原则；具体存储格式、库版本、性能参数待合成样本及目标机验证后再定。

## D-01｜产品定位与架构选择

**目标：** 一套可复制到断网电脑、优先双击 HTML 运行的 All-in-One 工作站。主页面提供模块入口和统一交互；科研、办公、文件、娱乐能力独立演进。首个正式模块为 Zotero 7 离线文献管理。

**不采用：** 单一巨型 HTML 承载所有业务；不把 Zotero 作为整个产品名；不要求安装原 Zotero 软件；不把云同步、自动 DOI 抓取或远程插件作为核心依赖。

参考现有公开项目：
- [P108 FigureStudio](https://github.com/FenLynn/gpt-pub/tree/p108-exp/projects/1-桌面软件/108-FigureStudio/)：稳定对象/数据引用、文档与数据绑定分离、可迁移项目 schema。
- [P109 AttendScope](https://github.com/FenLynn/gpt-pub/tree/p109-exp/projects/1-桌面软件/109-AttendScope/)：`file://` 离线包、程序/业务数据隔离、目录优先、便携 ZIP 回退、读回校验。
- **仅借鉴设计，后续复用代码需逐个评估兼容性和公开边界。**

## D-02｜目录、模块与数据的职责

建议交付布局（**逻辑规划，不强制最终文件分片格式**）：

```text
WorkStation/
├── app/                         # 可整体替换升级：绝不存真实用户数据
│   ├── index.html               # 统一入口
│   ├── core/                    # 路由、主题、数据接口、导入/导出、错误反馈
│   ├── modules/
│   │   ├── zotero/              # 第一阶段
│   │   ├── figure/              # 未来，独立模块
│   │   ├── calculator/
│   │   ├── pdf/
│   │   ├── spreadsheet/
│   │   └── tools/
│   └── vendor/                  # 本地 JS / WASM / CSL / 字体
├── workspace-data/              # 用户持久化事实源，不随 app 更新
│   ├── workspace.json           # 工作区身份、schema、模块注册/状态
│   ├── config/                  # 用户/工作区偏好
│   ├── modules/
│   │   └── zotero/
│   │       ├── manifest.json    # 模块数据 schema 与来源记录
│   │       ├── library/         # 规范化文献/分类/标签/关系
│   │       ├── notes/           # 用户新增/编辑的笔记
│   │       ├── attachments/     # WorkStation 新增的文件
│   │       └── derived/         # 可重建索引/缓存
│   └── backups/                 # 用户明确生成的数据备份
└── zotero-original/             # 可选独立保留的 Zotero 7 原始备份
    ├── zotero.sqlite
    └── storage/
```

- 不要求把源 `storage/` 全部重复拷贝一遍；默认保持**显式关联**，备份或迁移到另一台机器时明确提示“是否包含附件”。
- `library/` 可以采用分片 JSON、JSONL 或其他可迁移格式，**不预先承诺数千条记录全部存一个 JSON**。
- 来源层保留导入快照/身份映射；WorkStation 规范化编辑层成为新增与修改的事实源。再次导入源库须做差异预览及冲突处理。
- 模块需定义至少 `moduleId`、`moduleVersion`、`dataSchemaVersion`、`capabilities`、`entry`；共用 core 中的工作区/文件/设置接口，不直接操纵其他模块文件。

## D-03｜Zotero 7 导入与字段模型

**输入：** Zotero 7 的 `zotero.sqlite` 与完整 `storage/`；检查数据库一致性、可能存在的 WAL、版本差异、附件有无。本机只读解析，绝不要求安装 Zotero。

导入逻辑为：选择数据库 + 选择存储目录 → 预检/统计 → 映射并生成规范化记录 → 关联附件 → 对照核验 → 保存独立工作区。受 `file://` 权限约束，必要时由用户选择目录/文件而不是假定浏览器可自动扫描整个磁盘。

**基础字段**：`itemType`、`title`、`shortTitle`、`creators`（顺序、角色、姓名结构）、`date`、派生 `year`、`publicationTitle`、`journalAbbreviation`、`volume`、`issue`、`pages`、`publisher`、`DOI`、`ISBN`、`ISSN`、`url`、`abstractNote`、`language`、`extra`，各文献类型特有字段按类型保留。不能识别的来源字段应保留原始备份/扩展数据并发出提示，不可静默丢失。

**管理关系**：
- stable `recordId` 与来源身份 `source.libraryID + source.itemKey` 分开，新增文献分配新 ID；不以标题或 DOI 单独认定身份。
- `collections` 支持层级、稳定 ID、同一文献属于多个分类；`tags` 与颜色独立、可自定义。
- `attachments` 按附件条目自己的 Zotero Key 和相对路径解析 `storage:<filename>`；支持标记缺失、外部链接附件与多个附件。
- `notes`、`annotations`、相关文献关系保留来源；完整 PDF 坐标批注重现可分阶段实施。
- `citationKey` 保留 Better BibTeX / 原生 Zotero 可能提供的来源值及来源标识，不擅自重新生成。
- 支持独立的用户自定义字段（例如用户手填的期刊等级）；SCI/SSCI/CSSCI/中科院分区等**不得在无来源时自动推断为权威事实**。

## D-04｜Zotero UI / 交互范围

以用户提供的 Zotero 经典界面作为布局参考，**不将私人示意截图提交到公开仓库**。

1. 左栏：所有文献、分层分类（增改名/移动/删除）、标签筛选、未分类/回收站。
2. 中栏：可定制显示列及列宽、升降序/多级排序、分页/虚拟滚动（规模足够时）；默认列含标题、作者、年份、期刊、标签、附件状态。
3. 搜索：全局和指定字段检索；至少覆盖标题、作者、期刊、年份、DOI、标签与摘要。可组合 AND 条件、多条件筛选；搜索范围与排序作用于同一个结果集。
4. 右栏：文献完整字段、作者角色/顺序、摘要、分类、标签、关联附件、笔记。数据录入按期刊/图书/会议/专利/学位论文等类型动态展示字段。
5. 阅读：按需打开本地 PDF，可在同页/独立阅读页切换；附件关联不等于必然拥有文件写入权限。阅读批注、全文索引和结构化笔记可以分阶段增强。
6. 写操作：手动新增、修改、复制、删除（可恢复）、多选归类/打标签；支持导入 BibTeX/RIS 和本地 PDF。DOI 在线抓取在断网环境**不承诺可用**。
7. 导出：按已选/筛选结果输出常用文献格式；若支持 CSL/BibTeX/RIS，应明确映射损失与未支持字段，完整备份不得只依赖引用格式导出。

界面优先高信息密度、克制配色、可读中文、键盘操作和明确保存状态；不复制插件市场、在线同步或其他不必要的复杂功能。

## D-05｜技术路径与 `file://` 边界

- UI 优先原生 HTML/CSS/JavaScript 或构建后**所有资源相对路径、本地可用**的静态包；不假定线上服务器。
- 候选 `sql.js`（含可内嵌 WASM 的发行形态）用于只读 SQLite 解析；候选 PDF.js 用于 PDF 阅读；候选 citeproc-js + 离线 CSL 样式用于引用；**均须实测浏览器、本地协议和版本兼容后再定案**。
- 数据目录优先经浏览器明确授权后写入；无相关 API 权限时使用手动加载与导出便携完整 ZIP。目录授权/浏览器缓存都不能当作永久跨设备路径。
- 文件协议可能限制 Worker、WASM、跨文件读取或模块请求；以真实目标 Chrome/Edge `file://` 验证，不通过时优先重新打包/内联依赖或提供不需要常驻服务的回退路径，不能静默改为在线依赖。
- 大型附件按需读取、避免把全部 PDF 加载到内存；索引可重建，不追求第一阶段全文 OCR。

## D-06｜数据升级与备份原则

- **事实源分层**：Zotero 原件只读 → 来源映射/快照 → WorkStation 可编辑数据 → 派生索引/呈现。
- **配置层次**：全局默认 → 用户设置 → 工作区设置 → 模块设置；改变一个模块不覆盖其他模块。
- 升级流程：检查 `schemaVersion` → 生成备份 → 显式迁移 → 校验数量/身份/引用 → 读回核验 → 才确认新状态。
- 保存失败、浏览器崩溃、取消文件授权或磁盘空间不足时需保留可恢复状态并提示；禁止无声地把编辑视为已落盘。
- 支持用户执行包含业务数据、配置与可选 PDF 的完整项目备份/恢复；明确备份包清单、格式版本和校验信息。
- 单独升级 `app/` 不得更改 `workspace-data/`；若新版本涉及数据迁移，则必须独立提示并可恢复。
- 不做 Zotero↔WorkStation 双向实时同步，不承诺在两个软件同时编辑时自动合并冲突。

## D-07｜实施阶段与验收

**阶段 0：架构和原件调查**（当前）
- 确认 Zotero 7 数据文件与是否存在 WAL，识别实际 schema 和附件路径，使用公开/合成样本做兼容原型；真实用户源文件仅留本机。
- 固定首版模块接口、数据版本与备份协议，验证 Chrome/Edge 本地文件协议、用户目录读写与便携回退。

**阶段 1：可用的主页 + 文献管理 MVP**
- 首页模块入口/通用主题/工作区选择；Zotero 数据导入、数量/关联核对。
- 三栏浏览、分类树、多字段查询、排序、文献详情；手动新增/编辑、分类/标签管理、关联 PDF 打开。
- 保存、重开、迁移、目录替换升级、完整备份恢复。此阶段不以 PDF 深度批注或 AI 功能作为阻塞项。

**阶段 2：文献管理增强**
- BibTeX/RIS/CSL 导入导出、引用样式，重复检测、字段完整性报告、笔记整理、PDF 搜索/批注能力。
- 需要真实验证的 Citation Key、不同条目类型与历史注释兼容。

**阶段 3：其他模块独立接入**
- 科研绘图/科学计算、PDF 文档、表格、图像/影音工具逐个评估，优先共享规范而非把业务逻辑塞进首页；可进一步接入公开安全的专业模块。

**最小验收用例（必须实测且留证据）**：
- 彻底断网，在目标 Chrome/Edge 从 `file://` 双击启动，无远程请求。
- Zotero 7 一致性 SQLite 导入后，按条目类型统计数量、分类关系、作者顺序、标签及 PDF 存在性，核对遗漏。
- 标题/作者/期刊/年份/DOI/标签/摘要检索、排序/列展示正确；移动/删除分类不误删文献实体。
- 新增文献、手动编辑、添加附件/标签/笔记、未保存提示、保存、关闭、重启及重新选目录。
- 保留原 `zotero.sqlite` 与 `storage/` 字节不变；重导入不会静默覆盖用户修改。
- 用新版代码目录替换旧版，数据/设置不丢失；老版程序遇到新 schema 不得回写；备份恢复可重现。
- 中文、空格、长路径、缺失 PDF、链接附件、损坏/有 WAL 的数据库、只读文件夹、无目录 API、较大文献库等边界必须说明覆盖程度。

## D-08｜目前明确不做

第一版**不做**：Zotero 官方实时双向同步、账号登录、插件商店、联网元数据抓取、自动权威期刊分区更新、本地大模型/AI、全部 PDF 高保真批注、复杂影音转码、跨模块单体业务状态。后续只有确认真实需求及离线可行性才扩展。

> 这份设计将用户已确认的产品路线固化为后续研发约束和验证基线。具体依赖版本、文件分片方式与 UI 像素细节仍属于待验证的实现选择。
