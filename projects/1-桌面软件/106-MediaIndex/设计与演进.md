# P106｜MediaIndex 设计与演进

> 记录影响长期维护的设计决策。硬约束以 `开发约束.md` 为准。

## D-01｜问题定义不是传统重复文件清理

MediaIndex 的核心问题是：

> 新收到的媒体是否已经以原版、压缩版、转码版、裁剪版或其他同源形式存在于大规模库存中，并返回其位置。

因此产品优先级是“查询与定位”，不是“扫描后删除重复”。

## D-02｜库存保持原位，建立旁路索引

原媒体目录保持不动。系统维护独立索引：

```text
绝对 / 可恢复路径标识
卷或存储标识
媒体元数据
精确 hash
感知指纹
局部特征或其摘要
视频时间序列指纹
```

离线磁盘仍可保留路径与索引状态。

## D-03｜快速召回与最终判定分离

初步架构：

```text
Exact hash
→ perceptual / multi-region hash
→ Top-k candidates
→ local feature geometry
→ content consistency
→ final class
```

原因：单一全局 hash 对强裁剪脆弱，而局部特征不适合对几十万库存逐一暴力比较。

## D-04｜分级结果而不是二值重复

预期输出至少分为：

- Confirmed
- Probable
- Similar
- Not found

“Similar”不等于“Same source”。

## D-05｜AI embedding 后置

在传统视觉召回 + 局部几何无法满足召回前，不默认引入 AI embedding。

AI embedding 更适合语义相似和候选补漏，但可能把同场景不同照片推得很近，因此不能默认承担最终同源判定。

## D-06｜图片路线冻结后再进入视频

图片和视频共享索引框架，但视频增加：

- 时间采样
- 关键帧序列
- 时间偏移
- 片段包含关系
- 可能的音频 fingerprint

视频不应在图片判定链尚不稳定时并行扩张。
