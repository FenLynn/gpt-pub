# P106｜MediaIndex 阶段记录

## 当前阶段

**Phase 0｜图片索引收敛 + 视频时间与规模架构验证**

目标是在正式 UI 与 MVP 之前，把图片和视频共享视觉底座、索引结构、视频时间层与规模边界基本定型。

## Phase 0A｜图片验证

状态：**R001 至 R016 已完成，A4 真实域验收待执行**

当前已形成：

- Lane A：28 至 60 个精选 pHash regions。
- Lane B：compact visual-word inverted index。
- 当前保守候选预算：约 Top-50。
- 高纹理 verifier：SIFT + RANSAC + content consistency。
- 低纹理 fallback：template / edge。
- verifier cache 当前领先候选：256 至 320 px grayscale thumbnail + hot descriptor cache。
- metadata：SQLite。
- 高频视觉索引：旁路紧凑文件或 mmap。

关键边界：

- 单一 pHash 对强裁剪不够。
- 同场景不同视角可以产生很高 RANSAC inliers，因此 final verifier 必须保守。
- 201-region 全表扫描过重，不作为 V1 默认。
- 全量永久 SIFT descriptor 存储不再是默认方案。

A4 状态：

- 协议已建立在 `docs/real-domain-acceptance.md`。
- 用户真实数据尚未执行。

## Phase 0V｜视频验证

状态：**V001 至 V014 已完成，其中 V011 真实域 runner 已准备但未跑用户数据**

### V001 至 V004

已验证：

- H.264 / H.265 转码。
- 分辨率与 fps 改变。
- 3 s / 5 s / 8 s clip。
- source offset。
- 1.05× speed。
- 插片头。
- 中间删除。
- unrelated negative。

结论：

- frame visual retrieval + temporal correspondence 路线成立。
- 单一 global offset / affine model 不足以解释剪辑。
- 3 s clip 可能正确 Top-1 但候选间隔不足。

### V005 至 V007

已验证：

- 0.5 s 与 1 s uniform sampling 均稳定。
- 2 s 与 4 s 对短 clip 出现明显 sampling phase alias。
- 当前方向为约 1 fps baseline + selected denser / scene samples。
- 删除中段可由 piecewise offset segments 解释。
- whole-video unordered ORB BoVW 不可靠。
- 视频 local-feature postings 必须保留 timestamp / frame_id。

### V008 至 V010

已验证：

- 字幕与 letterbox 对 pHash 时间序列影响有限。
- 画中画需要 multi-region 或 verifier。
- 强竖屏裁剪会让 pHash 排序失败。
- 3 段跨视频 composite 可自动恢复 3 个 source runs。
- Audio fingerprint 对重编码、clip、轻微 speed 很强。
- 同音轨不同视频是明确反例，因此 audio 只能作为 supporting Lane C。

### V011

真实视频小域验收工具已经建立：

- `docs/real-domain-acceptance.md`
- `experiments/v011_real_video_acceptance_runner.py`

状态：**等待用户真实域，不提交私人媒体到仓库。**

### V012

4 个 60 s 视频，具有共享片头、共享片尾和重复片段。

发现：

- 只含共享片头或片尾的 Query 对多个库存视频完全歧义。
- 独立中段可以唯一定位 source。
- 跨共享片头与独立内容的 Query 可由独立部分打破歧义。
- 同一视频内部重复 motif 会产生多个强 source intervals。

因此必须支持：

- Ambiguous source。
- 同一 source 多个 intervals。
- 高频模板片段降权。

### V013

强竖屏裁剪 local-feature rescue：

- pHash 可以把正确 source 放在非第一候选。
- 在粗 offset 邻域内使用 SIFT + RANSAC 后，正确 source 恢复第一。
- 竖屏 crop、竖屏 crop + watermark、非中心 50% crop + watermark 均被救回。
- 错误候选没有形成 verified frames。

结论：

- local geometry 可以解决 V008 的强竖屏失败。
- 但 candidate width 不能过早收窄。
- 正式 Lane B 应采用 timestamp-preserving local-feature retrieval。

### V014

视频索引规模模型已经完成。

约 1 fps baseline：

| 总时长 | 16 B baseline | 28-region | 24 postings | 每帧 6 KB thumbnail |
|---:|---:|---:|---:|---:|
| 1,000 h | 0.054 GiB | 0.778 GiB | 0.644 GiB | 20.1 GiB |
| 10,000 h | 0.536 GiB | 7.778 GiB | 6.437 GiB | 201.2 GiB |
| 50,000 h | 2.682 GiB | 38.892 GiB | 32.187 GiB | 1005.8 GiB |

结论：

- 1 fps lightweight temporal anchors 很便宜。
- 不能给每个 baseline frame 复制完整图片签名或 verifier thumbnail。
- 视频索引必须分层。

当前视频层级：

```text
Tier V0
约 1 fps
global pHash + video_id + timestamp

Tier V1
sparse scene / motion / periodic keyframes
local visual words + timestamp postings

Tier V2
very sparse verifier thumbnails
或在线源文件按需解码

Audio Lane C
compact audio fingerprint sequence
```

## 当前统一架构

```text
SQLite metadata / exact hash
        ↓
shared visual primitives
        ↓
image:
  pHash Lane A
  local Lane B
  spatial verifier

video:
  Tier V0 temporal anchors
  Tier V1 sparse local keyframes
  Audio Lane C
  temporal alignment
  selected-frame verifier
        ↓
Exact / Same / Derived / Partial / Composite / Ambiguous / Similar / Not found
```
