# P106｜MediaIndex 阶段记录

## 当前阶段

**Phase 0｜图片同源检索算法验证**

目标是在写正式产品代码前，先证明“几十万媒体库存中快速判断新媒体是否已经存在”这一核心能力可行。

## Phase 0A｜当前验证主线

### A0：受控合成样本

状态：**已完成**

主要结论：

- 全局 perceptual hash 对常规重新编码很强。
- DoubleGradient 可覆盖轻裁剪，但强裁剪仍会失效。
- SIFT 可以恢复强裁剪候选。
- 仅靠宽松 SIFT/RANSAC verdict 会产生严重误报。

### A1：自然样例正样本鲁棒性

状态：**第一轮已完成**

20 张自然 / 实际样例图，17 类变换，共 340 个 Query。

主要结论：

- 多区域 pHash 对中心型 Crop70 仍然很强。
- 任意位置 Crop50 和复合攻击会让 pHash 候选排名明显下降。
- ORB 局部候选与 pHash 互补。
- 在 20 张小库中，完整 ORB Top-5 与 pHash Top-5 候选并集覆盖 340/340。
- 128 个 ORB descriptors/image 与 pHash 联合 Top-10 也覆盖 340/340。

该结果只证明路线，不代表真实大库性能。

### A2：难负样本

状态：**第一轮已完成**

共 222 个 hard negative：

- 190 个普通跨图配对。
- 8 个同一真实场景不同相机视角及裁剪。
- 24 个重复纹理非重叠区域。

关键发现：

- 同场景不同视角可达到 362 个 RANSAC inliers。
- inlier ratio 可达到 0.978。
- 因此“高 inliers + 高 ratio”仍不能证明同源。
- 加入特征占比、覆盖度和 warp 后内容一致性后，本轮探索性高置信规则达到 173/200 true confirmed，同时 0/222 hard-negative false positive。
- 该规则仍不是生产阈值。

### A3：规模与索引

状态：**第一轮微基准已完成，Lane B 尚未冻结**

连续内存随机 64-bit hash 微基准：

- 500k × 28 regions：约 106.8 MB raw hash，warm query 约 54.9 ms。
- 500k × 60 regions：约 228.9 MB raw hash，warm query 约 138.5 ms。

当前判断：

- pHash Lane A 的规模不是主要风险。
- 真正未解决的是 crop-resistant Lane B 如何在 50 万规模做紧凑候选召回。
- 已试 ORB LSH 与 ORB/SIFT BoVW，小库结果均显示可行，但仍需更大公开数据交叉验证。

### A4：用户真实域验收

状态：**未开始**

只在 Lane B 与最终精确验证基本冻结后进行。真实素材不得进入公开仓库。

## 当前架构候选

```text
Exact hash
→ Lane A: global / multi-region pHash
→ Lane B: scalable local-feature index
→ candidate union
→ SIFT + RANSAC
→ content consistency
→ Confirmed / Probable / Similar / Not found
```
