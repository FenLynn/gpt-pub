# P106｜Benchmark Plan

## 目标

把“能找到”拆成三个独立问题：

1. 候选召回：正确原图是否进入 Top-k。
2. 精确确认：候选是否真的是同源素材。
3. 工程规模：几十万库存下是否仍然足够快、足够轻。

## A1｜真实自然图像正样本

每张原图生成至少以下变化：

- JPEG quality 多档
- Resize 多档
- JPG / PNG / WebP
- Crop 10 / 20 / 30 / 50 / 70%
- 非对称 crop
- 黑白边
- 水印
- 大文字覆盖
- 亮度 / 对比度 / 饱和度
- 模糊
- 锐化
- 小角度旋转
- 镜像
- 多重组合攻击

记录：

- pHash / multi-region hash Top-1 / Top-5 / Top-20
- SIFT candidate verification
- 最终判定
- 每类失败样本

## A2｜难负样本

必须优先收集“非常像但不是同一张”的负样本：

- 同场景不同角度
- 连拍
- 同主体不同表情 / 姿态
- 同一建筑不同视角
- 同一网页不同状态
- 同一海报不同文字
- 相似风景
- 低纹理
- 重复纹理
- 同背景不同主体

关键指标：

- False positive rate
- hard-negative top score distribution
- 与 true-positive 分布的间隔

## A3｜候选召回与规模

测试库存规模：

- 100k
- 300k
- 500k

候选召回方案依次比较：

1. 单全局 hash
2. 多区域 hash
3. BK-tree / Hamming neighborhood
4. 其他轻量索引
5. 仅在必要时加入 embedding

记录：

- 索引构建时间
- 增量更新时间
- 内存
- 磁盘索引体积
- 单 Query P50 / P95
- Top-5 / Top-20 recall
- 精确验证耗时

## A4｜真实用户域验收

只在仓库外执行。

建议最小集：

- 50 至 100 张真实库存图
- 多种实际压缩 / 转存 / 截图 / 裁剪版本
- 20 至 50 张真实 hard negatives

不得把原始私人媒体或可反推内容的索引提交到公开仓库。

## 冻结条件

图片 V1 路线只有同时满足以下条件才可冻结：

- 常规同源变换高召回。
- 强裁剪可通过候选召回 + 精确验证恢复。
- hard negative 误报可控。
- 500k 级查询可接受。
- 生产阈值不依赖单一合成集。
- 已记录明确失败边界。
