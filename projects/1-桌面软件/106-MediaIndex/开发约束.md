# P106｜MediaIndex 开发约束

> 约束层级：C｜项目级  
> 上位规则：`/GPT_RULES.md` 与 `projects/1-桌面软件/开发约束.md`

## C-01｜写入范围

在用户解除当前限制前，P106 只能修改：

```text
projects/1-桌面软件/106-MediaIndex/
```

不得顺手修改共享目录、根规则、分类规则、其他项目或公共 CI。

## C-02｜分支模型

长期只使用：

```text
main
p106-exp
p106-stable
```

日常实验、源码和记录只进入 `p106-exp`。  
`p106-stable` 只接收经过完整验证的 `p106-exp` 候选。  
正式准入只能 `p106-stable → main`，不得绕过。

## C-03｜只读库存原则

MediaIndex 第一职责是检索，不是清理。

默认行为必须：

- 不移动原媒体。
- 不重命名原媒体。
- 不删除原媒体。
- 不自动覆盖同源文件。
- 不因为相似度分数触发破坏性动作。

若未来增加清理能力，必须与检索核心分离，并设置显式人工确认。

## C-04｜算法事实与阈值证据

任何算法结论必须区分：

1. 合成受控数据。
2. 公开真实自然图像。
3. 难负样本。
4. 用户真实域验收。
5. 大规模索引压力测试。

禁止从小型合成数据直接冻结生产阈值。

每次 benchmark 至少记录：

- 数据来源与公开安全边界。
- 正负样本数量。
- 变换类型。
- 算法与参数。
- Top-k 召回。
- 假阳性。
- 查询耗时。
- 索引大小。
- 失败案例。
- 对架构的结论。

## C-05｜判定与候选召回分离

候选召回算法和最终同源判定不得混为一个分数。

优先结构：

```text
快速候选召回
→ 精确几何 / 内容验证
→ 分级输出
```

系统至少保留：

- Confirmed
- Probable
- Similar
- Not found

不得把“视觉相似”自动等同“同一素材”。

## C-06｜公开与隐私

公开仓库不得提交：

- 用户真实私人照片和视频。
- 用户真实绝对路径。
- 未脱敏日志。
- 私人媒体指纹数据库。
- 能反推私人媒体内容的缓存或索引。

算法验证优先使用可公开样本、自生成样本或仓库外临时数据。

## C-07｜图片先于视频

Phase 0 先冻结图片路线。只有以下条件满足后才进入视频：

- 图片同源正样本召回达到可接受水平。
- 难负样本误报得到控制。
- 数十万规模候选召回可行。
- 阈值与失败边界已记录。

视频验证再分别处理：

1. 完整视频转码。
2. 分辨率与帧率变化。
3. 片段截取。
4. 水印与字幕。
5. 时间偏移和序列匹配。

## C-08｜AI embedding 不是默认最终判据

AI embedding 可以用于候选召回或极端难例补漏，但在证明必要性前不进入 V1 主链。

原因：语义相似不等于同源，尤其在同场景、连拍、同主体不同照片中可能增加误报。

## C-09｜发布边界

当前项目没有正式 Release 授权，也没有正式版本基线。

`RELEASE.md` 只记录未授权状态，不得借普通开发提交触发正式标签或 Release。
