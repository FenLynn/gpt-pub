# AtlasDesk 开发约束

> 约束层级：C｜项目级
> 适用范围：P102 AtlasDesk
> 上位规则：A｜`/GPT_RULES.md`；B｜`../开发约束.md`（当前不存在）

本文件只保存 AtlasDesk 当前仍生效、后续版本不得随意破坏的长期规则。当前任务、版本进度和一次性验证结果不写在这里。

## 1. 项目身份与写入范围

- 产品对外名称固定为 **AtlasDesk**。
- 正式路径固定为 `projects/1-桌面软件/102-AtlasDesk/`。
- 日常开发分支为 `p102-exp`，稳定候选为 `p102-stable`，正式主线为 `main`。
- P102 开发只允许修改 P102 项目目录、P102 活动 CI，以及确有必要的 P102 状态入口。
- 不得修改 Mediova 的产品目录、源码、CI、长期分支、版本记录和发布记录。
- `PersonalWorkbench` 仅作为历史 namespace、工程目录或兼容标识存在，不得重新成为用户可见产品名。

## 2. 分支、版本与发布

固定流程：

```text
最新 main → p102-exp → p102-stable → main → 标签与 Release → 回流 p102-stable / p102-exp
```

- 日常功能和修复不得直接写入 `main` 或 `p102-stable`。
- `p102-exp → p102-stable` 必须通过完整 Windows 候选验证。
- `p102-stable → main` 必须再次执行正式准入验证。
- 正式标签采用 `p102-vX.Y.Z`，只从 `main` 建立。
- 发布完成后，最新 `main` 必须回流两条 P102 长期分支。
- 临时实现、迁移、发布和触发分支在闭环后删除，不长期堆积。
- 版本号必须对应真实产品变化，不为推进对话机械升级。

## 3. Runtime 与 Data 边界

AtlasDesk 使用“透明文件夹 Runtime + 独立私人 Data”架构。

### 3.1 Runtime

用户建立的 `AtlasDesk` 文件夹就是 Runtime 根目录：

```text
AtlasDesk/
├── AtlasDesk.exe
├── AtlasDesk.TerminalHost.exe
├── Assets/
├── runtimes/
├── runtime-manifest.json
└── 其他公开依赖
```

- Runtime 必须可公开、复制、覆盖、校验和删除后重建。
- Runtime 不得保存用户设置、历史、日志、缓存、Cookie、Token、私人路径、浏览器 Profile 或保险库。
- 程序不得把 EXE、DLL、Assets 或版本化应用目录释放到 AppData。
- 不得恢复 `%LOCALAPPDATA%\AtlasDesk\App\<版本>` 或 `AtlasDesk.App.exe` 自释放架构。
- 终端网页资源和公开依赖直接随 Runtime 发布，不在 Data 中生成运行副本。

### 3.2 Roaming Data

```text
%APPDATA%\AtlasDesk
```

只保存轻量、重要、私人、值得备份的内容，例如普通设置、任务历史、安全元数据、加密保险库和必要备份。

### 3.3 Local Data

```text
%LOCALAPPDATA%\AtlasDesk
```

只保存机器相关或可重新生成的私人状态，例如 WebView2 Profile、终端状态、日志、启动状态、缓存和崩溃信息。

- Roaming Data 与 Local Data 都属于私人 Data，不得进入公开仓库、Runtime、Artifact、Release 或更新包。
- 构建和自动测试必须使用隔离临时目录，不读取真实用户 Data。

## 4. 数据迁移、备份与兼容

- 正式产品代码不长期携带旧架构的一次性迁移逻辑。
- 跨架构迁移使用独立临时脚本或专用迁移工具，迁移完成后不进入 Runtime 和产品源码。
- 迁移前必须创建可识别的完整备份。
- 迁移不得静默删除旧数据、覆盖已经存在的新数据，或在校验失败后继续破坏性清理。
- 复制、移动和格式迁移必须具备明确校验与失败提示。
- 旧 Runtime 清理失败不能被误报为用户数据迁移失败；二者状态应分开表达。
- 配置格式或 Data schema 发生变化时，必须说明兼容范围、备份方式、回退条件和验证结果。

## 5. 安全中心边界

- 普通使用 AtlasDesk 默认不要求解锁，也不强制自动锁定。
- 主密码至少 20 位，用于真正的本地保险库加密；主密码本身不得落盘。
- 主密码派生使用 Argon2id，保险库使用 AES-256-GCM 或经过明确审查的等效现代方案。
- TOTP 与 Google Authenticator 等标准验证器兼容；TOTP 只承担二次授权，不直接作为数据加密密钥。
- TOTP 共享密钥必须受到主密码加密保护，不得明文写入普通设置。
- 可选四位数字只用于用户主动触发的临时界面遮挡，不参与保险库加密，不得被描述为高强度安全因素。
- 四位临时锁可以不设置、可以关闭，不得影响普通无锁使用。
- Runtime、日志和诊断输出不得包含主密码、验证码、TOTP 密钥、Token、Cookie 或保险库明文。
- Dashboard 的 Cookie 和网页登录状态由 WebView2 Profile 管理，不抽取后混入普通 JSON 或保险库。

## 6. 主界面与视觉原则

- 主壳采用连续、克制的平面布局，不以多个大圆角卡片、重复底纹、描边和阴影分割整个软件。
- 左侧导航和右侧内容优先使用单一背景与一根清晰的分割线区分。
- 只有存在真实信息分组、交互边界或状态语义时，才使用局部卡片、底色或边框。
- 文字、按钮和图标应自然嵌入布局，避免每个元素都被独立容器包围。
- 字体、字号、行高、按钮尺寸、图标尺寸、边距和对齐必须在同一层级保持一致。
- 次要说明优先使用悬浮提示，不长期占据主要布局空间。
- 不得通过增加更多装饰层掩盖布局问题。

## 7. 窗口、DPI 与全屏适配

- 最大化窗口必须遵守当前显示器的 Windows WorkArea，不得遮挡任务栏或超出可用工作区。
- 自定义标题栏必须正确处理窗口边框、DPI、最大化、还原、多显示器和任务栏位置。
- 顶部标题、窗口按钮和工具按钮必须垂直居中，不得在最大化后偏移或被裁切。
- 底部导航、状态区和操作区在普通窗口、最大化和不同缩放比例下必须可见、可达。
- 界面修改至少覆盖常见窗口尺寸、100%–175% DPI、最大化/还原和多显示器回归。
- 不接受只在单一截图尺寸下成立的固定像素补丁。

## 8. Dashboard 与浏览器边界

AtlasDesk 不发展为通用浏览器，Dashboard 采用混合模式：

- Dashboard 自身域名、内部路由和必要身份验证保留在 AtlasDesk WebView2 中。
- 跨域外链默认交给 Windows 系统默认浏览器。
- 不为外部复杂网站长期维护通用标签页、下载器、权限系统、扩展系统或完整浏览器兼容层。
- WebView2 新窗口请求必须先判断目标域名，不得无条件创建内部浏览器窗口。
- `RenderProcessUnresponsive`、渲染进程退出和导航失败必须形成可恢复状态；主 Dashboard 不得永久停留在错误页。
- 顶部可以提供“在默认浏览器打开当前页”等明确退出通道。
- Dashboard 登录状态只使用 Local Data 中的 WebView2 Profile。

## 9. 项目、环境与终端模块边界

- “项目”和“环境”是开发模块中的独立页面，二者不得因终端宿主切换而互相消失。
- 环境页面必须能够主动发现并展示 Conda、uv、venv 和系统 Python；不得只依赖偶然的可见性事件完成加载。
- 终端可以作为全局底部抽屉或独立窗口使用，但不得自动替换、隐藏或占据环境页面。
- `AtlasDesk.TerminalHost.exe` 只承担 ConPTY/原生边界，不保存用户设置和业务状态。
- WPF 主程序负责界面、会话组织和业务逻辑；原生宿主职责不得无边界扩张。
- TerminalHost 不可用或会话失败时必须有明确错误和可恢复路径，不得造成主程序失去响应。

## 10. 模块化与历史兼容层

- AtlasDesk 采用模块化单体，不引入插件市场、微服务、后台常驻服务或不必要的进程拆分。
- 新独立 EXE 只有在原生边界、隔离故障或明显技术收益成立时才允许增加。
- 不得继续为每个补丁无上限新增 `V06x`、`V07x` 等版本命名 Enhancer 层。
- 修复历史层之间的冲突时，优先合并职责、删除失效路径和回归测试，而不是再叠一层修正器。
- 稳定模块不为技术炫耀重写；已经造成重复控制、互相隐藏或生命周期冲突的兼容层应在有测试保护时逐步收敛。

## 11. 测试与完成判定

用户不承担主要回归测试。提交候选前必须尽可能自行完成：

- .NET 8 WPF/XAML 编译；
- smoke suite；
- C++20 TerminalHost 编译；
- 真实 CMD/ConPTY 会话；
- Runtime/Data 路径和隐私边界扫描；
- Runtime manifest、文件大小和 SHA-256 校验；
- 主密码、Argon2id、AES-GCM、TOTP 和二维码依赖编译与关键逻辑测试；
- Dashboard 同域、跨域、登录和渲染故障处理测试；
- 项目/环境/终端切换回归；
- 多窗口尺寸、最大化、DPI 和多显示器布局检查。

- 自动测试无法证明视觉、真实浏览器登录、显卡驱动或多显示器行为时，工作项必须保持“待验证”，直到获得实机证据。
- 不得把“代码已写”当作“问题已完成”。
- 不得通过隐藏错误、降低检查门槛或删除功能制造稳定版本。

## 12. 更新与交付

- 仅主程序变化时，默认只交付 `AtlasDesk.exe`。
- 多个 Runtime 文件变化时，只打包变化文件并保留 AtlasDesk 根目录下的原相对路径。
- 部署结构、主要依赖或资产整体变化时，才交付完整 Runtime ZIP。
- 更新包永远不包含 Roaming Data 或 Local Data。
- 每次交付必须给出版本、变更摘要、验证结果、文件清单和 SHA-256。
- 正式 Release 只包含经过固定 CI 验证的必要产物，不上传重复文件、调试文件、缓存、日志或真实用户数据。

## 13. 文档与决策记录

- 当前工作进入 `工作记录.md`；正式发布证据进入 `阶段记录.md`。
- 长期仍生效的规则才进入本文件。
- 重大架构原因、路线取舍和长期技术债进入 `设计与演进.md`。
- README 只作为入口，不复制完整约束、任务和发布证据。
- 普通小修复不要求同时修改所有文档。
- 工作项只有在实现、完成标准和可追溯证据同时存在时，才能移入最近完成。
- 正式发布后，完成项从活跃看板移除；旧版本历史由 Git、PR、标签和 Release 保存。

## 14. 开发决策原则

- 优先解决根因，不对同一问题反复打表面补丁。
- 不过度设计；能用简单、透明、可测试的本地方案解决时，不引入复杂框架。
- 不为形式增加进程、目录、配置层、文档或自动化。
- 不破坏用户数据，不把推测写成已验证事实。
- 对仍需用户实机确认的风险必须明确标注。
