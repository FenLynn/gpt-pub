# AtlasDesk 工作记录

本文件是 AtlasDesk 的滚动工作看板。正式版本证据见 [阶段记录](阶段记录.md)，长期规则见 [开发约束](开发约束.md)，架构决策见 [设计与演进](设计与演进.md)。

## 当前基线

用户已在真实 Windows 机器上确认：

- `v0.8.3` 启动闪退已消失；
- “开发”默认停留在“项目”，主动进入“环境”可完成检测；
- CMD 与 PowerShell 终端可打开；
- Dashboard 跨域外链进入系统浏览器；
- Dashboard 全屏可通过 Esc 和右上角退出方式返回；
- `v0.8.4` 未解决 Zotero 客户端与 AtlasDesk 同时运行的兼容问题，但用户确认该问题不阻塞主线。

当前分支状态：

- 当前任务分支：`p102-v085-shell-resilience`
- 当前开发分支：`p102-exp`，v0.8.4
- 当前稳定候选：`p102-stable`，v0.8.4
- 正式主线：`main`，仍为 v0.8.0

## 已知限制

### Zotero 并行运行

部分安装环境中，AtlasDesk 直接读取实时 `zotero.sqlite` 时仍不能与 Zotero 客户端稳定并行运行。`v0.8.4` 已将数据库工作移出 WPF Dispatcher，并取消多分类并行读取，因此该问题不再拖死主窗口，但没有解决底层实时数据库共存。

当前处理原则：

- 使用 AtlasDesk 资料库前关闭 Zotero；
- 该问题登记为非阻塞已知限制；
- 不继续在实时数据库上增加超时、并行或重试复杂度；
- 只有用户后续明确需要时，才评估“由 Zotero 导出或复制生成只读快照”的隔离方案。

## 推进总计划

开发按以下版本逐次进行。每一版必须先更新计划与版本记录，再完成代码、自动测试、Windows CI、稳定候选合入和开发分支回流；前一版未通过，不进入后一版。

| 版本 | 主目标 | 不做内容 |
|---|---|---|
| `v0.8.5` | Dashboard 恢复、主窗口 DPI/多显示器适配、快速导航稳定 | 不增加业务模块，不重写主壳 |
| `v0.8.6` | 收敛历史 Enhancer 层，明确模块唯一所有者 | 不一次性整体重构，不改变用户界面 |
| `v0.8.7` | 完善工作区与终端的真实使用链 | 不增加插件市场、后台服务或复杂任务系统 |
| `v0.9.0` | 建立项目驱动的工作区、终端、环境、Git 与任务协同 | 不做通用 IDE，不复制 VS Code |

## v0.8.5：主壳与 Dashboard 韧性

状态：**实施中**。

已实现：

- 新增 `ShellResilienceCoordinator`，作为主壳跨模块可靠性唯一所有者；
- 通过 `WM_GETMINMAXINFO` 使用当前显示器 WorkArea，避免最大化进入任务栏区域；
- DPI 或显示器拓扑变化后刷新布局，并将普通窗口限制回最近显示器可用区域；
- 快速导航使用单调递增请求版本，仅最终页面执行主壳稳定化；
- 离开 Dashboard 后清理滞留进度状态；
- Dashboard 健康检查只在 Dashboard 页面活动时运行；
- WebView2 丢失或错误页面进入已有重建链；
- 自动恢复串行、限流，并在 30 秒内超过三次后停止自动循环，保留主窗口可用；
- 新增 `V085ShellResilienceChecks` 源码边界门禁。

完成标准：

- 完整 smoke 通过；
- 独立真实窗口驻留通过；
- 开发页仍保持懒加载；
- Dashboard、终端、Runtime/Data 与安全边界不回退；
- Windows publish、manifest、ZIP 与 Artifact 全部通过；
- 合入 `p102-stable` 并回流 `p102-exp`。

## v0.8.6：Enhancer 收敛

状态：**排队**。

目标：停止继续叠加 `V06x`、`V07x` 修正层，逐模块建立唯一控制源。

计划顺序：

1. 主壳导航与页面生命周期；
2. Dashboard 交互与诊断；
3. 开发项目/环境/终端；
4. 工作区；
5. 工具与任务占位模块。

实施原则：

- 每次只收敛一个控制域；
- 将事件绑定、可见性、父容器和状态恢复移入有明确名称的长期组件；
- 删除已被新组件完全替代的旧 Enhancer 调用；
- 不以“大重写”方式一次删除全部历史代码；
- 每次删除前先建立等价 smoke 与真实窗口驻留门禁；
- 不改变当前用户界面和私人 Data 格式。

完成标准：

- 主壳、Dashboard 和开发模块各自只有一个生命周期所有者；
- `WorkbenchFeaturePipeline` 不再继续增加新的版本编号 Enhancer；
- 至少移除一批已失效的重复事件/布局覆盖路径；
- 启动、快速导航、开发三 Tab、Dashboard 和终端完整 CI 通过。

## v0.8.7：工作区与终端完善

状态：**排队**。

目标：让工作区与终端成为稳定、连续的实际工作界面。

计划内容：

- 保持单一左侧目录树，不恢复重复目录面板；
- 文件标题与路径采用紧凑单行结构；
- 文本查看支持自动换行切换；
- Markdown 渲染补齐图片、数学公式和基础表格边界；
- 工作区动作统一进入标题栏，减少占位小字；
- 项目终端、CMD、PowerShell 与环境终端入口使用同一会话模型；
- 终端支持标签切换、关闭、重开、工作目录恢复；
- 工作区切换不得错误关闭已有终端；
- 终端启动失败时显示可恢复状态，不阻塞窗口。

完成标准：

- 工作区打开、文件切换和终端会话拥有自动测试；
- 真实 ConPTY CMD 连续测试保持通过；
- 快速切换工作区与终端不产生重复会话或空白页面；
- 默认交付仍为 EXE-only，除非 Runtime 依赖实际变化。

## v0.9.0：项目驱动工作流

状态：**排队**。

目标：把已经存在的项目、工作区、终端、环境、Git 和任务能力连接为一条自然工作链，而不是继续增加孤立按钮。

目标流程：

```text
选择项目
→ 打开对应工作区
→ 终端进入项目目录
→ 显示 Git 分支与变更状态
→ 识别项目环境
→ 展示相关近期任务
```

计划内容：

- 项目卡片显示名称、路径、类型和固定状态；
- 显示 Git 当前分支、未提交变化和远程摘要；
- 显示 Python、Node、.NET、Rust、LaTeX 等环境摘要；
- 一键打开项目工作区；
- 一键建立项目终端；
- 最近文件与最近任务按项目关联；
- 项目固定、排序与搜索；
- 项目路径失效、环境缺失或 Git 异常时给出明确提示；
- 项目状态只在用户选择或刷新时更新，不在启动阶段扫描全部目录。

完成标准：

- 项目选择能够驱动工作区、终端和环境上下文；
- Git 与环境探测均有超时和后台执行边界；
- 不恢复 v0.8.2 的启动期全目录环境扫描；
- 项目链路、快速切换、窗口驻留、ConPTY 和 Runtime/Data 完整 CI 通过；
- 更新阶段记录，形成 `v0.9.0` 稳定候选。

## 暂缓或取消

| 工作项 | 状态 | 原因 |
|---|---|---|
| Zotero 实时数据库并行兼容 | 已知限制 | 当前收益不足以覆盖实时数据库隔离复杂度 |
| 多项目启动期自动扫描虚拟环境 | 暂缓 | 已在 v0.8.2 形成生命周期回归 |
| 可取消并行解释器探测 | 暂缓 | 并发、外部进程和窗口生命周期组合过重 |
| Zotero 多分类并行读取 | 取消 | 会增加实时数据库锁竞争 |
| AtlasDesk 通用内置浏览器 | 取消 | OAuth、下载、扩展与复杂网页维护成本过高 |
| 插件市场与后台常驻服务 | 暂缓 | 当前应先完成核心工作链和架构收敛 |

## 维护规则

- SQLite、文件扫描、Git、环境探测和外部工具不得占用 WPF Dispatcher；
- 页面可见性变化不得启动数据库或外部工具；
- 主壳跨模块行为必须进入长期命名组件，不再新增版本编号 Enhancer；
- 自动 CI 不能替代真实 Windows、真实 WebView2、真实终端和多显示器验证；
- 自动验证完成但仍缺真实设备证据时，状态保持“候选通过”或“待验证”；
- 每一版本完成后必须更新本文件，再进入下一版本。
