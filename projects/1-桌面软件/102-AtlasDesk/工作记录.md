## 当前准确断点

当前不应继续叠加新功能。

下一步首先由用户实机验证 `AtlasDesk v1.1.11 Runtime`，重点检查：

1. 品牌头像区域是否已经干净；
2. 项目上下文按钮是否位于搜索栏右侧且不遮挡搜索；
3. 集成 CMD、PowerShell 与弹出终端是否统一为纯黑风格；
4. 深色按钮文字是否清晰；
5. 右侧按钮排列是否整齐；
6. Dashboard 输入、项目、工作区、Zotero、任务和工具是否未受影响。

处理原则：

- 如果 v1.1.11 实机通过，再决定是否将 v1.1 阶段正式收口或进入下一阶段；
- 如果只存在局部视觉问题，只做定点修复，不再改 Dashboard 架构；
- 未经用户确认，不把 v1.1.11 合入 `main`，不创建正式标签或 Release；
- 不以 CI、截图审计或自动输入测试替代用户机器上的最终视觉确认。

## v1.1.10｜Dashboard 简化回归

v1.1.10 只回退 Dashboard 子系统，没有回退 AtlasDesk 其他模块。

保留：

- 项目上下文；
- 工作区；
- 原生终端与 ConPTY；
- Zotero 只读资料库；
- 任务与工具；
- 当前 UI、安全和 Runtime/Data 分离；
- v1.1.0–v1.1.3 的项目工作流功能。

撤销：

- 独立 `AtlasDesk.DashboardHost.exe`；
- `DashboardProcessSurface`、`SetParent` 和 `AttachThreadInput`；
- 跨进程标准输入输出协议；
- 登录窗口脱离与重新嵌入；
- Dashboard DOM 点击注入；
- 自动看门狗和后台销毁/重建 WebView2 Controller。

当前 Dashboard 重新由 MainWindow 直接拥有一个 WPF WebView2，主页面与登录弹窗共享原有 WebView2 Environment 和 Profile。极端原生故障可能仍需要重启 AtlasDesk，但键盘、输入法、剪贴板、快捷键和焦点重新使用原生 WPF/WebView2 路径。

验证包括真实 `App.Run()`、MainWindow、完整 Feature Pipeline、同进程 WebView2、真实 HTML 输入框和 Windows `SendInput` Unicode 输入。

## v1.1.0–v1.1.3 保留结果

项目上下文阶段仍然有效，并未被 Dashboard 修复覆盖：

```text
Ctrl+K Command Center
→ 选择项目 / 文件 / 文献 / 命令
→ 恢复项目上下文
→ 工作区、终端、Dashboard、Zotero 进入同一项目语境
```

保留能力：

- 项目显示名称、默认 Shell、Python 环境说明和 Dashboard 地址；
- 常用文件、目录和用户显式配置的命令；
- 安全恢复上次页面、项目、工作区位置和 Zotero 查询；
- 不保存终端输出，不自动重放命令；
- 项目与 Zotero 文献只读关联；
- Zotero SQLite 继续 `ReadOnly` 与 `query_only`；
- 私人项目上下文保存在 `%APPDATA%\AtlasDesk\productivity-context.json`；
- Runtime、Roaming Data 和 Local Data 边界不变。

详细历史证据见 PR `#322`、`#324` 及相应 CI 和 Artifact。
