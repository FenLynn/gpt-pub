## 实施中：v0.8.7 工作区—终端连续链

目标：不重做终端 UI，只建立统一会话创建和显式恢复边界。

已实施：

- 新增 `WorkspaceTerminalCoordinator`；
- 工作区、开发环境和项目中心终端请求统一由该协调器创建会话；
- `WorkbenchEnhancer` 不再直接创建工作区、环境或快捷键终端；
- 项目中心不再直接调用 `TerminalDrawerControl.OpenAsync`；
- 保存最近一次终端 shell、有效工作目录和显示标题；
- `Ctrl+Shift+T` 新建当前工作区默认终端；
- `Ctrl+Shift+R` 由用户主动重开最近终端上下文；
- 启动、加载和页面可见性变化均不会自动恢复终端；
- 不保存命令、输出或 shell 历史；
- 新增 `V087WorkspaceTerminalContinuityChecks`。

完成标准：

- 全部 smoke 通过；
- 工作区、环境和项目中心均只有一个会话创建所有者；
- 真实窗口驻留与开发三 Tab 不回退；
- 5 次真实 ConPTY CMD、终端前端、Runtime/Data、安全与发布链通过；
- 合入 `p102-stable` 并回流 `p102-exp`。

## 下一步：v0.9.0 项目驱动工作流

v0.8.7 完成后直接进入 v0.9.0，不再增加中间版本。

目标流程：

```text
选择项目
→ 生成项目上下文
→ 工作区切换到项目目录
→ 项目终端进入对应目录
→ 显示 Git 分支与变更摘要
→ 显示环境与最近文件摘要
```

实施范围：

- 将 `V070ProjectCenterEnhancer` 迁移为长期命名的 `ProjectWorkflowCoordinator` 并退休旧类；
- 项目选择触发有版本门禁的后台上下文读取；
- Git 状态读取具有超时、取消和无 Git 安全降级；
- 环境摘要仅根据项目标志文件识别，不在启动时运行解释器；
- 最近文件只从已保存的最近文件列表中过滤，不递归扫描全部内容；
- 工作区和终端动作继续复用现有控件与 `WorkspaceTerminalCoordinator`；
- 项目路径失效、Git 不可用或读取超时时给出明确状态；
- 不制作通用 IDE，不复制 VS Code。

v0.9.0 完成标准：

- 项目选择能够驱动上下文、工作区和终端；
- 快速切换项目时旧结果不会覆盖新项目；
- 项目状态只在用户选择或刷新时更新；
- 不恢复启动期全目录环境扫描；
- 项目链路、窗口驻留、ConPTY、Runtime/Data、安全与发布链完整通过；
- 更新 `阶段记录.md`，形成 v0.9.0 稳定候选并回流开发分支。

## 长期规则

- 不再新增版本编号 Enhancer；
- 历史层只能逐项迁入职责命名组件后删除；
- 页面可见性不得触发数据库、Git 或外部工具；
- SQLite、Git、环境探测和文件扫描不得占用 WPF Dispatcher；
- 最近终端上下文只能由用户主动恢复；
- 每一版本完成稳定合入和开发回流后，才进入下一版本。
