本文件是 AtlasDesk 的滚动工作看板，只保留当前活跃事项、暂缓/取消事项和少量最近完成。正式版本证据见 [阶段记录](阶段记录.md)，长期规则见 [开发约束](开发约束.md)。

## 当前目标

`v0.8.2` 在真实 Windows 机器上出现启动后闪退回归。日志显示主窗口、WebView2 和完整模块均已初始化，随后进程结束，但旧日志体系没有记录 WPF Exit、窗口 Closing/Closed 或 CLR ProcessExit，因此无法直接区分正常关闭、环境发现异步回归和进程级终止。

当前紧急候选提升为 `v0.8.3`，原则是先恢复启动可靠性，不继续叠加环境扫描能力：

- 当前任务分支：`p102-v083-startup-hotfix`
- 当前开发分支：`p102-exp`
- 当前稳定候选：`p102-stable`，v0.8.2（已确认真实机回归，不再推荐）
- 正式主线：`main`，仍为 v0.8.0

## v0.8.3 根因判断

此次不能在缺少 Windows 崩溃转储的情况下武断归因于单一异常，但代码审查确认两个高风险生命周期问题：

1. `DevelopmentControl` 将环境发现绑定到 `IsVisibleChanged`。该控件在三 Tab 开发页装配时会被移除、重新挂载并修改可见性，因此用户尚未进入“环境”页时也可能启动外部 Conda/Python 工具。
2. 进入“开发”时，`MainWindow` 保留的旧 Python 页面与 `V070ProjectCenterEnhancer` 当前环境页会各自启动一次发现，形成重复环境检测。v0.8.2 又加入四路并行解释器探测、项目目录扫描和取消时进程树终止，使该重复路径风险进一步放大。

因此 v0.8.3 采取回退式修复，而不是继续修补复杂异步链。

## v0.8.3 已实现内容

- 环境发现不再订阅 `IsVisibleChanged`；开发控件装配和可见性变化不会启动 Conda/Python。
- 环境检测仅在用户真正选择“环境”Tab或主动点击“刷新环境”时运行。
- 新增 `DevelopmentLifecycleGuard`，关闭 `MainWindow` 中已被三 Tab 页面取代的旧 Python 发现入口，确保开发页只有一个环境检测所有者。
- `PythonEnvironmentService` 恢复 v0.8.1 已验证的串行、有界检测顺序。
- 撤回 v0.8.2 的四路并行解释器探测、一级项目目录扫描和可取消进程树检测。
- 保留必要修复：先通过 `where.exe` 定位可选 `py.exe`；未安装时静默跳过，不再产生 Win32Exception 堆栈。
- 日志新增 WPF `Application Exit`、CLR `ProcessExit`、主窗口 `Closing` 与 `Closed`，后续若仍退出可区分正常关闭和进程级终止。
- 主窗口 smoke 从“仅构造后立即关闭”升级为真实 `Show()`、完整模块装配、进入“开发 → 环境”、持续泵送 Dispatcher 8 秒，并在窗口意外关闭时阻断候选。

## 维护规则

- 自动 CI 不能替代真实 Windows 驻留、交互和长时间运行测试。
- 启动或窗口生命周期相关改动必须显示真实窗口、泵送 Dispatcher 并验证窗口持续存在。
- 自动验证完成但仍缺真实 Windows 视觉、网页或长期运行确认时，状态保持“待验证”。
- 正式发布后移除已完成活跃项；历史由 Git、PR、标签和 Release 保存。
