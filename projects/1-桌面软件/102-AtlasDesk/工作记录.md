## 实施中：v0.9.0 项目驱动工作流

目标流程：

```text
选择项目
→ 读取项目上下文
→ 在工作区打开项目
→ 在项目目录创建终端
→ 显示 Git、环境和最近文件摘要
```

已实施：

- 新增 `ProjectContextService`；
- 新增长期命名的 `ProjectWorkflowCoordinator`；
- `ProjectCenterControl` 增加明确选择事件、读取状态和上下文显示；
- 删除 `V070ProjectCenterEnhancer.cs`；
- 删除 `V070RuntimeVerifier.cs`，改为 `ProjectWorkflowRuntimeVerifier`；
- Pipeline 改为 `ProjectWorkflowCoordinator` 唯一所有者；
- 项目工作区动作继续复用 `WorkspaceControl.OpenFromGlobalSearchAsync`；
- 项目终端动作继续复用 `WorkspaceTerminalCoordinator.OpenProjectTerminalAsync`；
- 环境摘要只读取已有项目标志，不启动 Python、Node、.NET 等运行时；
- 最近文件只过滤现有最近文件列表，不递归扫描项目；
- Git 只读取当前选中项目，使用 `--untracked-files=no` 并设置三秒超时；
- 快速切换项目会取消旧读取并通过 generation 门禁丢弃过期结果；
- Git 缺失、路径失效、非 Git 项目和超时均显示明确降级状态；
- 新增 `V090ProjectWorkflowChecks`，包含临时 Python 标志项目与最近文件的真实上下文 smoke；
- 历史项目中心和终端门禁已迁移到长期工作流组件。

v0.9.0 完成标准：

- 全部 smoke 通过；
- 项目选择能够驱动上下文、工作区和终端；
- 快速切换时旧结果不能覆盖新项目；
- 启动阶段不扫描项目 Git、环境或最近文件；
- 真实窗口驻留与开发三 Tab 不回退；
- 5 次真实 ConPTY CMD、Dashboard、Runtime/Data、安全、publish、manifest、ZIP 与 Artifact 通过；
- 更新 `阶段记录.md` 记录 v0.9.0 稳定候选证据；
- 合入 `p102-stable` 并回流 `p102-exp` 后停止本轮开发。

## 长期规则

- 不再新增版本编号 Enhancer；
- 历史层只能逐项迁入职责命名组件后删除；
- 页面可见性不得触发数据库、Git 或外部工具；
- SQLite、Git、环境探测和文件扫描不得占用 WPF Dispatcher；
- 最近终端上下文只能由用户主动恢复；
- 项目上下文只由选择或刷新触发，并必须可取消、有超时；
- `main` 只在明确正式发布时更新，本轮只形成 v0.9.0 稳定候选。
