## 最近完成：v1.3.0 聚焦全局快捷面板

本轮没有增加第二套功能系统，而是收紧现有 `Ctrl+K` Command Center。

### 统一快速入口

`Ctrl+K` 和现有顶部命令按钮继续打开同一个快捷面板，可快速到达：

- 现有页面：主页、Dashboard、工作区、Zotero、开发、工具、任务、设置；
- 当前项目及其现有项目动作；
- 已配置的项目文件；
- 用户显式配置的项目命令；
- 已关联的只读文献；
- 已有最近文件；
- 现有终端、目录和首页刷新动作。

### 搜索和交互

- 面板收紧为 `720 × 480` 的紧凑窗口；
- 搜索提示为“搜索页面、当前项目、文件、命令或文献”；
- `Ctrl+K` 提示移到页脚，不再挤在输入框中；
- 支持上、下方向键选择，Enter 执行，Esc 关闭；
- 结果按精确标题、标题前缀、标题、类别、描述和既有动作优先级排序；
- 当前项目、项目终端、Dashboard、项目文件和文献动作优先展示；
- 命令仍然只能由用户明确选择后执行，不自动恢复或重放。

### 主动做减法

Command Center 刷新不再执行：

- 工作区目录遍历；
- 项目目录重新扫描；
- 任务历史加载；
- 直接 Zotero 数据库搜索。

对应页面和原功能没有被删除，只是不再让快捷面板承担这些重型职责。

### 架构边界

- 当前项目资源继续来自 `ProductivityContextStore`；
- 项目动作继续由 `ProductivityContextCoordinator.TryExecuteAsync` 执行；
- 页面、终端、Dashboard、工作区和 Zotero 继续由原模块负责；
- Zotero SQLite 继续严格只读；
- 不新增快捷面板索引、Data 文件、schema、后台服务、定时器或文件监控；
- 不增加浏览器工作区、插件市场、MCP 市场或 Agent；
- WPF、ConPTY、同进程 WebView2 和 Runtime/Data 分离继续保持。

## 验证过程中的修正

### 1. 同步最新 main 基线

开始 v1.3.0 前，发现 `p102-exp` 比最新 `main` 落后 9 个提交。已经通过 PR `#372` 将 `main` 正常回流到 `p102-exp`：

- 不重置、不强推；
- 不覆盖 P102 独有历史；
- 同步后 exp 相对 main `behind 0`。

### 2. P102 范围门禁识别正式 main 基线

第一次稳定候选 CI 将最新 main 已正式包含、但旧 stable 尚未包含的两份 P101 文档误判为越界。

PR `#375` 将规则修正为：

- P102 白名单路径正常放行；
- 非 P102 文件只有与 `origin/main` 完全一致时才作为继承基线放行；
- 任何偏离 main 的非 P102 修改仍立即失败；
- 没有降低 P102 范围隔离。

### 3. 运行时验证器契约

旧 `V073RuntimeVerifier` 仍调用已被 v1.3.0 取消的工作区遍历 API。

PR `#376` 改为验证：

- 静态页面和本地动作完整；
- 最近文件可搜索；
- 结果数量受限；
- 搜索支持取消；
- 工作区项目不会被快捷面板重新扫描；
- 新快捷面板窗口和核心控件可以真实布局与渲染。

没有把旧遍历 API 加回来。

### 4. v1.1.3 历史门禁继承

旧 v1.1.3 smoke 依赖包含“任务、上下文泛搜索”的历史提示文案。

PR `#377` 仅更新提示文案为当前聚焦入口，同时继续强制检查：

- `ProductivityContextCoordinator.TryExecuteAsync`；
- 项目 profile；
- 安全会话续接；
- 项目与 Zotero 只读关联；
- Command Center 仍是唯一统一入口。
