AtlasDesk v0.8.5

This maintenance release hardens the main shell, Dashboard recovery and Windows display adaptation without adding a new feature module.

Dashboard resilience
- A shell-owned watchdog checks Dashboard health only while the Dashboard page is active.
- Missing or failed WebView2 instances enter the existing rebuild path instead of leaving a dead page behind.
- Automatic rebuilds are serialized, rate-limited and capped at three attempts in a 30-second burst so a damaged renderer cannot make the AtlasDesk window unresponsive.
- After the cap is reached AtlasDesk keeps the shell alive, stops the loop and exposes the existing reload action.

Windows display adaptation
- WM_GETMINMAXINFO uses the active monitor work area, so maximized AtlasDesk no longer extends behind that monitor's taskbar.
- DPI and display topology changes schedule a safe layout refresh and clamp a normal window back into the nearest monitor work area.
- Layout rounding and device-pixel snapping remain enabled across display changes.

Navigation lifecycle
- Rapid navigation changes use a monotonic request version. Only the final selected page performs shell stabilization.
- Stale Dashboard progress is collapsed after leaving the page, and Dashboard-only controls are normalized to the final route.
- The coordinator is cross-cutting infrastructure rather than another version-named visual enhancer.

Known limitation
- Direct reads from the live Zotero database may still be incompatible with running Zotero on some installations. This remains a non-blocking known limitation; close Zotero before using the AtlasDesk library.

Regression protection
- New smoke gates require monitor work-area handling, bounded Dashboard recovery and final-route navigation stabilization.
- Existing startup residency, Development, terminal, Zotero background-read, Runtime/Data and security boundaries remain unchanged.
