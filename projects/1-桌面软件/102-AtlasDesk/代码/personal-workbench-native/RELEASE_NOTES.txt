AtlasDesk v1.0.4 UI convergence candidate

This bounded maintenance candidate converges the visual hierarchy, adds adaptive-layout diagnostics and fixes the real home-surface host without adding a new product workflow. It remains outside main until user verification.

Visual convergence
- A centralized UiConvergenceResources dictionary unifies page headings, cards, navigation, buttons, text inputs, tabs and list density.
- Converged cards use one fine border and no additional drop-shadow layer.
- Primary, secondary, text and icon buttons share consistent heights, corner radii and interaction states.
- The terminal keeps its independent dark presentation and is not recolored by the light convergence layer.

Adaptive layout
- UiConvergenceCoordinator selects spacious, standard or compact density from the current window width, height and DPI.
- The shell adapts outer spacing, sidebar width, top-bar height, navigation density and low-priority labels.
- Home metrics switch between four and two columns; the context card and lower work/shortcut area can stack vertically.
- Settings cards reduce padding and label widths, and narrow footer actions stack instead of colliding.
- Development, project, task, tool and workspace pages use a reduced outer hierarchy without changing their business behavior.

Layout audit and diagnostics
- Diagnostics reports the current adaptive mode, window/content geometry, sidebar width and DPI.
- The audit contains no project path, URL, user name, file name, command or document content.
- Layout-health transitions are logged only when state changes, avoiding resize-log flooding.
- The diagnostics window now uses a two-level result row and wrapping footer actions instead of a fixed three-column hierarchy.

Home ownership correction
- V061ExperienceEnhancer explicitly owns and exposes the home and settings surfaces.
- Home installation now supports both Panel and ContentControl hosts.
- This fixes the real MainWindow HomeView host, which is a ScrollViewer/ContentControl and was not covered by the older Panel-only installer.
- UiConvergenceCoordinator receives the owned page instances directly and no longer guesses them from the visual tree.

Regression protection
- Source gates verify the shared styles, TextBox PART_ContentHost, three density modes, privacy boundary and flattened diagnostics layout.
- Real Windows residency verifies the physical compact top-level window and the converged diagnostics window.
- Standard 1320x780 and spacious 1500x860 home layouts are measured off-screen using the production ResolveMode and ApplyHome methods because the CI desktop is physically limited to 1080x720.
- All v1.0.3 and earlier smoke, ConPTY, Dashboard, Runtime/Data, security, publish, manifest and ZIP checks remain mandatory.

Verification status
- v1.0.4 is a UI-convergence candidate for user verification.
- It must not enter main or receive a formal tag/Release before user confirmation.

AtlasDesk v1.0.3 final candidate

This final pre-verification candidate completes the bounded reliability work requested after v1.0.0. It adds no new product workflow and remains outside main until combined user verification.

Performance baseline
- AtlasDesk records main-window readiness, feature-pipeline attachment time and process working set after a complete startup.
- Startup history is limited to the newest 20 samples.
- Samples contain only version, UTC time, safe-mode state, two elapsed durations and working-set bytes.
- No project path, URL, user name, terminal command, file name or document content enters the performance file.
- Diagnostics shows the latest and median startup baseline and includes the privacy-safe history in support bundles.

Log maintenance
- atlasdesk.log rotates before startup when it exceeds 4 MiB.
- At most two previous log generations are retained.
- Rotation failure never prevents application startup and never recursively writes to the log being rotated.
- Real-file smoke tests cover first and multi-generation rotation.

Diagnostics lifecycle
- The version-numbered V062StabilityEnhancer has been removed.
- DiagnosticsCoordinator now owns the diagnostics button, single-window activation and close lifecycle.
- Closing the main window closes and releases the diagnostics window.
- The diagnostics coordinator preserves safe-mode and unclean-start indicators without adding background checks.

Regression protection
- Real temporary histories verify the 20-sample boundary and summary calculation.
- Source and serialized-payload gates prohibit paths, URLs, users, commands and terminal content from the performance baseline.
- The old V062 component is rejected and the responsibility-named coordinator is required.
- All v1.0.2 and earlier smoke, real window residency, ConPTY, Dashboard, Runtime/Data, security, publish, manifest and ZIP checks remain mandatory.

Verification status
- v1.0.3 is the final candidate for combined user verification with v1.0.0-v1.0.2.
- Development stops at v1.0.3; it must not enter main or receive a formal tag/Release before user confirmation.

AtlasDesk v1.0.2 candidate

This reliability candidate protects startup and local configuration without changing the v1.0.1 user data model or entering the formal main branch.

Settings protection
- settings.json is written through a same-directory temporary file, flushed to disk and atomically replaced.
- The previous valid settings file is retained as settings.json.bak.
- A damaged primary file is quarantined instead of overwritten, then the latest valid backup is restored.
- If neither copy is valid, AtlasDesk starts from normalized defaults and records the recovery source for diagnostics.
- Safe-start runtime overrides never rewrite the user's saved Dashboard auto-open preference.

Safe startup
- StartupGuard keeps an atomic state file and backup.
- One unclean session produces a warning; two consecutive unclean starts enter safe mode.
- Safe mode suppresses Dashboard auto-open only for the current process and leaves all saved settings unchanged.
- The user receives a clear safe-start explanation and can open the diagnostics center before entering feature pages.

Diagnostics
- Diagnostics now reports settings source/backup state, safe mode, WebView2, Runtime/Data boundaries, terminal host, CMD, PowerShell, Git, configured Conda/uv, Zotero read access and logs.
- Dashboard reachability uses a cancellable four-second headers-only request and does not launch a browser or external tool.
- Tool discovery checks saved paths and PATH without starting the programs.
- Repeated diagnostic runs and support-bundle exports cancel the previous operation and reject stale results.
- Support bundles include a sanitized settings snapshot and settings-load summary without exposing project or recent-file paths.

Regression protection
- Real temporary files verify atomic replacement, backup retention and quarantine.
- Pure startup-policy tests verify the warning-to-safe-mode threshold and clean-exit reset.
- Source gates prohibit process launching from diagnostics and preserve cancellation/generation boundaries.
- All prior smoke, real window residency, ConPTY, Dashboard, Runtime/Data, security, publish, manifest and ZIP checks remain mandatory.

Verification status
- v1.0.2 is an intermediate candidate on the route to v1.0.3.
- It must not enter main or receive a formal tag/Release before combined user verification.

AtlasDesk v1.0.1 candidate

This maintenance candidate improves daily-use clarity without changing the v1.0.0 data model or adding a large product feature.

Home dashboard
- Showing the home page no longer reads the Zotero database or starts project/Git discovery.
- Home status is assembled from already saved settings, recent files, saved project paths and bounded task history.
- Repeated refreshes are cancellable and generation-gated so stale snapshots cannot overwrite the current view.
- The former Python and Workspace metric cards now summarize saved projects and shared task activity.
- Zotero status shows configuration and read-only mode only; actual database reads remain exclusive to the Library page.

Settings clarity
- Dashboard URL and known file/directory paths receive immediate existence or format feedback.
- Validation is informative only: AtlasDesk does not create, search for or guess user-entered workspace, Zotero, Conda, uv or PDF paths.
- Settings adds direct Runtime and log-directory entries alongside roaming and local data folders.
- Runtime is identified as replaceable program content, while logs and user data remain private local state.

Library layout
- Zotero keeps its three-pane structure but now uses bounded responsive widths.
- At constrained window widths, the collection pane narrows gradually and the read-only detail pane retains at least 320 px.
- Title, Citation Key, DOI, reference and PDF operations remain in the high-priority upper detail area.
- No Zotero write capability or new database access path was added.

Regression protection
- New v1.0.1 checks prohibit Zotero, Git and project scans from returning to home-page visibility refresh.
- Real temporary paths validate project, task and recent-file snapshot aggregation.
- Settings path behavior and Zotero responsive-layout boundaries are source-gated.
- All v1.0.0 smoke, window residency, ConPTY, Dashboard, Runtime/Data, security, publish, manifest and ZIP checks remain mandatory.

Verification status
- v1.0.1 remains a candidate for combined user verification.
- It must not enter main or receive a formal tag/Release before user validation.

AtlasDesk v1.0.0

AtlasDesk 1.0 is the first formal release of the stabilized Windows research and development workbench.

Core workbench
- A bounded project workflow connects project selection, workspace, terminal, Git status, environment markers and recent files.
- Projects can be pinned, reopened from recent history and explicitly relocated when saved paths move.
- The native ConPTY terminal remains isolated behind AtlasDesk.TerminalHost.exe and does not store commands or output.

Zotero research pane
- The library follows a compact three-pane, read-only information structure.
- Title, authors, source, year, Citation Key and DOI are immediately visible.
- Title, DOI, Citation Key, quick reference text, LaTeX citations and Pandoc citations can be copied.
- PDF attachments can be opened or selected in Windows Explorer for direct file copying.
- Zotero SQLite access is read-only with query_only enabled.

Tasks and tools
- File-integrity manifest generation, verification and file comparison share one task collection.
- Task and tool pages share status, progress, cancellation, results and bounded history.
- Active work is confirmed before application exit.
- One TaskToolCoordinator owns task/tool navigation and shutdown lifecycle.

Window and runtime
- Maximized windows use the active monitor work area and avoid taskbars on every edge.
- Common window sizes, 100–175% DPI, restore/maximize and Runtime/Data boundaries are protected by regression checks.
- Runtime remains a transparent replaceable folder; private roaming and local data never enter the package.

Release verification
- v1.0.0 adds a formal release-readiness gate over the stabilized components and retired compatibility layers.
- Full smoke, real Windows window residency, real CMD/ConPTY sessions, Dashboard, Runtime/Data, security, publish, manifest and ZIP checks remain mandatory.

Known limitation
- Close Zotero before opening the AtlasDesk library where the live database cannot be shared safely.
- GB/T 7714 and APA previews are quick-copy references; use Zotero/CSL output for formal submission formatting.

Previous stabilization milestones
- v0.9.5: task/tool lifecycle convergence and removal of V064/V065 enhancers.
- v0.9.4: unified tool tasks, cancellation and bounded history.
- v0.9.3: project favorites, recents and explicit path relocation.
- v0.9.2: read-only Zotero research pane and PDF file-location action.
- v0.9.1: native work-area maximization and constrained-height layout fix.
- v0.9.0: explicit project-driven workflow.
