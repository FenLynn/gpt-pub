AtlasDesk v0.8.7

This maintenance release creates one explicit terminal-session owner for workspace, development and project workflows while preserving the existing terminal UI and ConPTY implementation.

Single session owner
- WorkspaceTerminalCoordinator is the only component that creates sessions requested by WorkspaceControl and DevelopmentControl.
- Project-center terminal actions now use the same coordinator instead of opening TerminalDrawerControl directly.
- WorkbenchEnhancer retains only terminal container show/hide behavior; it no longer creates workspace, environment or shortcut sessions.

Continuity
- AtlasDesk remembers only the last terminal shell, valid working directory and display title.
- Ctrl+Shift+T explicitly creates a new default terminal using the current workspace context.
- Ctrl+Shift+R explicitly reopens the last terminal context.
- No terminal process is restored during startup, page load or visibility changes.
- Existing sessions remain alive when the workspace or main page changes.

Privacy and safety
- Commands, output and shell history are not persisted by this feature.
- An invalid remembered directory is discarded during settings normalization.

Regression protection
- New smoke gates require workspace, development and project paths to use WorkspaceTerminalCoordinator and prohibit direct creation in the base shell.
- Existing ConPTY, terminal frontend recovery, development lazy loading, window residency, Runtime/Data and security checks remain active.

Known limitation
- Close Zotero before opening the AtlasDesk library where the live database cannot be shared safely.
