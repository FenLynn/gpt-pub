AtlasDesk v0.8.2

This maintenance release stabilizes Python environment discovery in the Development workspace after the v0.8.1 terminal and Dashboard repairs.

Python environment discovery
- The optional Windows Python Launcher is now located before execution. Systems without py.exe no longer produce a Win32Exception stack trace during normal discovery.
- PATH Python, Python Launcher, Conda and workspace environments are de-duplicated by their resolved interpreter path.
- The workspace root and each immediate project directory are checked for .venv, venv and .python environments.
- Generated and dependency directories such as node_modules, bin, obj, build and caches are excluded from project environment scanning.
- Interpreter version checks use bounded parallelism so a machine with many Conda environments does not make the page unnecessarily slow.

Refresh behavior
- Environment discovery is cancellable and a repeated refresh cancels the previous pass before starting a new one.
- The Refresh button and environment list are temporarily locked while detection is active.
- A compact indeterminate progress indicator shows that discovery is running.
- The previously selected environment is preserved after refresh when it is still available.
- Settings are saved only when newly discovered Conda or uv paths actually change the configuration.

Verification
- Added executable smoke coverage for Python Launcher output parsing, duplicate removal, root and immediate-project virtual environments, and generated-directory exclusion.
- Added source-boundary checks preventing a return to direct optional py.exe execution.
- No Runtime/Data or security boundary changes were made.
