AtlasDesk v0.8.4

This maintenance release prevents a large or busy Zotero database from blocking the AtlasDesk WPF interface.

Zotero responsiveness
- Zotero database reads are no longer connected to ZoteroLibraryControl visibility changes. Reparenting, layout and page visibility transitions cannot start SQLite work.
- The current library surface loads only after the user explicitly selects the Library navigation item or requests refresh/search.
- Microsoft.Data.Sqlite exposes async-shaped methods while SQLite still performs the database work synchronously. AtlasDesk now enters all snapshot, search and item-detail reads through a dedicated Task.Run scheduler so the WPF Dispatcher remains responsive.
- A single SemaphoreSlim gate serializes AtlasDesk Zotero reads. Descendant collection searches no longer open a Task.WhenAll batch of read connections against the live Zotero database.
- Slow snapshot, search and detail work now keeps the interface interactive and shows background-reading status instead of making the main window appear hung.
- Stale list and item-detail results are discarded when the selection or library configuration changes.

Regression protection
- Smoke tests verify that Zotero reads execute on a worker thread, visibility-triggered loading is absent, collection reads remain serial, and Library navigation is the explicit owner of initial loading.
- Existing v0.8.3 startup residency, development lifecycle, Dashboard, terminal, Runtime/Data and security boundaries remain unchanged.
