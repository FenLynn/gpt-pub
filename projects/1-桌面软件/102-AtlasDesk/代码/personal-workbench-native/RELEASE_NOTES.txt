AtlasDesk v0.8.3

This emergency maintenance release removes the v0.8.2 startup regression reported on a real Windows installation.

Startup and development lifecycle
- Environment discovery is no longer connected to DevelopmentControl visibility changes. Reparenting the control while the three development tabs are assembled cannot start Conda or Python tools during application startup.
- The retained legacy MainWindow Python page is explicitly disabled after the current project/environment/terminal development surface attaches. Selecting Development now has one environment-discovery owner instead of two concurrent paths.
- Environment discovery returns to the proven serial and bounded v0.8.1 sequence. The v0.8.2 parallel interpreter probing, project-directory scanning and refresh cancellation chain have been removed.
- Environment detection starts only after the user selects the Environment tab or presses Refresh.

Python Launcher
- py.exe remains optional. AtlasDesk resolves it through PATH before execution and silently skips the Launcher when it is not installed.
- Launcher output parsing and interpreter-path de-duplication remain covered by smoke tests.

Diagnostics and verification
- The log now records the WPF Application Exit event, CLR ProcessExit event, and MainWindow Closing/Closed events so a future native or external termination can be distinguished from a normal close.
- The Windows smoke probe now shows the real MainWindow, attaches the complete feature pipeline, enters Development > Environment, pumps the Dispatcher while discovery runs, and fails if the window closes.
- No Runtime/Data, WebView2 profile, terminal, vault or security boundary changes were made.
