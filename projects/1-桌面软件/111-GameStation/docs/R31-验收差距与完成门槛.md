## 3.2 AI 棋力

当前部分游戏已有不同搜索预算或决策策略，但尚未形成统一自对弈基准。后续应记录胜率、失误类型、搜索耗时和资源使用；不得只凭策略名称或搜索深度宣称“困难 AI 已校准”。

### 3.3 需要冻结的规则范围

- 五子棋：当前为自由规则；是否增加 Renju 禁手模式待确认。
- 中国象棋：已覆盖主要走法、循环和连续长将判罚；长捉、自然限着和完整竞赛棋例需继续研究。
- 麻将：当前为 136 张基础牌，不含花牌；地方规则、番种和计分待确定。
- 三国杀：当前为四人固定身份局、有限基础牌和小乔技能；需确定采用的版本、扩展包和武将范围。
- 泡泡堂风格原创游戏：仅完成可行性评估，尚未批准作为第 25 款游戏。

### 3.4 存档范围

当前 JSON 备份覆盖统计、收藏、界面字号和首次使用时间；不包含对局中状态、单款游戏关卡进度或跨浏览器自动同步。若要实现完整存档，需逐款定义版本化状态接口，不能将宿主统计备份误称为游戏进度存档。

### 3.5 真实离线实机

CI 已在 Chromium 中直接通过 file:// 运行；仍需在用户 Windows 设备上断网启动 Chrome/Edge，检查文件权限、键盘焦点、全屏、长时间运行和各款游戏实际交互。

## 4. 项目完成门槛

1. **UI 门槛**：首页、游戏库、24 款游戏桌面布局及统一生命周期回归通过。当前自动化门槛已通过。
2. **规则门槛**：24 款游戏分别具有可重复的合法动作、非法动作、边界条件和胜负判定测试；复杂规则需有对应专项测试。
3. **AI 门槛**：人机游戏的难度差异通过固定局面或自对弈验证；没有校准的数据不得宣称竞技级棋力。
4. **数据门槛**：明确统计备份与游戏进度存档的区别；若要求进度恢复，则完成各模块状态版本化和跨重启回归。
5. **离线门槛**：Chromium CI 通过，并由用户完成 Windows Chrome/Edge 真实断网验收。
6. **交付门槛**：上述门槛通过后才创建 p111-stable 候选；PR #476 是否合并由用户最终决定。

## 5. 继续开发的顺序

1. 建立 AI 自对弈和固定局面基准，记录胜率、失误类型、耗时和资源占用。
