## 2｜状态语义

- **基础可玩**：模块具备可运行的主要回合/操作循环，但不代表所有高级规则、AI 难度或长期数据功能均已完成。
- **体验原型**：入口、主要界面或部分规则已实现，仍存在关键规则、AI 或素材缺口。
- **待完善**：明确记录未实现部分，不允许仅因入口存在就标记为完成。
- 人机游戏的简单/中等/困难必须由搜索预算、策略或经过校准的失误率形成真实差异；不能只改变显示标签。
- 不完全信息游戏 AI 只能使用当前玩家合法可见的信息，不得读取其他玩家隐藏手牌或未来随机结果。

## 3｜模块架构

每款游戏必须有独立目录、入口 HTML 和 game.js；由宿主 iframe 隔离运行。共享 CSS、桥接协议和无状态工具允许放在 games/shared/，但不能把所有游戏规则塞进一个巨型脚本。

~~~text
app/
├── index.html
├── css/app.css
├── js/app.js
└── games/
    ├── shared/bridge.js
    ├── shared/game.css
    ├── gomoku/
    ├── xiangqi/
    ├── reversi/
    ├── connect4/
    ├── battleship/
    ├── checkers/
    ├── chess/
    ├── minesweeper/
    ├── 2048/
    ├── memory/
    ├── sudoku/
    ├── sokoban/
    ├── tetris/
    ├── snake/
    ├── pong/
    ├── contra/
    ├── mario/
    ├── tank/
    ├── solitaire/
    ├── doudizhu/
    ├── mahjong/
    └── sanguosha/
~~~

每个模块入口加载共享桥接后注册 `GameBridge.register({ init, newGame, pause, resume, dispose })`。模块不得直接修改宿主 DOM 或访问其他游戏的数据。

## 4｜通信协议

消息包统一结构：

~~~json
{
  "channel": "gamestation",
  "protocolVersion": 1,
  "gameId": "gomoku",
  "sessionId": "current-session",
  "type": "READY",
  "payload": {}
}
~~~

- 宿主 → 游戏：INIT、NEW_GAME、PAUSE、RESUME、SET_DIFFICULTY、SET_OPTIONS、LOAD_STATE、DISPOSE。
- 游戏 → 宿主：READY、STATE、SAVE_REQUEST、SCORE、GAME_OVER、FULLSCREEN_REQUEST、ERROR。
- 宿主校验 event.source、gameId、协议版本和 sessionId；旧 iframe 的迟到消息不得覆盖新游戏状态。
- 退出模块必须清理计时器、动画循环、Worker、音频和事件监听。

## 5｜离线与许可证

- 发行目录不得包含远程脚本、CDN、在线字体、图片、API、遥测或联网服务。
- 每个第三方代码依赖必须固定版本/提交并登记许可证、NOTICE 和实际文件范围。
- 不随程序分发魂斗罗 ROM；当前横版射击模块使用原创几何素材和原创玩法。
- 三国杀角色、卡牌、技能文本与立绘分别核验权利；不得把代码许可证当作美术素材授权。
- GPL/LGPL/AGPL 依赖不直接混入主程序，除非完成独立许可证决策。

## 6｜阶段验收

- 断网双击 app/index.html，22 款游戏入口全部可加载；外部请求为零。
- 逐款检查新局、暂停/继续、退出清理、键盘焦点和缩放。
- 棋类验证合法走法、胜负/平局、悔棋和 AI 难度差异。
- 单人游戏验证边界条件、计分、暂停和终局。
- 牌类验证牌型、回合顺序、隐藏信息公平和异常手牌。
- GitHub Pages 只用于在线体验，不能替代 file:// 离线验收。
