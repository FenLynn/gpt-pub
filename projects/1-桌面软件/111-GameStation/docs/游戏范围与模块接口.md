## 2｜统一模式与难度语义

### 对战游戏

- 本机双人：同一台设备轮流操作，不提供网络联机。
- 人机：一名玩家与一个或多个本地 AI 对局。
- AI 观察/机机对战：仅用于开发校准和测试，默认不作为主菜单功能。
- AI 难度固定显示为简单、中等、困难；具体搜索预算和策略由游戏独立实现。

### 单人游戏

单人游戏不强行设置“AI 难度”。使用与玩法相关的参数：

- 扫雷：棋盘大小、雷数、首次点击安全。
- 纸牌：抽一张/抽三张、计分方式、发牌规则。
- 俄罗斯方块：重力速度、软降速度、锁定延迟等。
- 贪吃蛇：移动速度、棋盘尺寸、障碍密度。
- 魂斗罗：关卡、生命和难度选项；不得把未经授权的原作资源打包进程序。

### 三档 AI 的质量要求

- 简单：允许一定策略失误，但必须遵守规则、不会故意非法走棋。
- 中等：能识别基本威胁、机会和常见组合。
- 困难：采用更深搜索或更完整的概率/策略评估；不得通过读取隐藏信息作弊。
- 难度差异必须用基准局面、机机对战或足够样本的胜率验证；不能只改变思考延时或随机数。

## 4｜游戏注册清单

宿主注册表每项至少包含：

~~~json
{
  "gameId": "gomoku",
  "title": "五子棋",
  "category": "board",
  "entry": "games/gomoku/index.html",
  "moduleVersion": "0.1.0",
  "dataSchemaVersion": 1,
  "modes": ["human-vs-human", "human-vs-ai"],
  "difficulty": ["easy", "normal", "hard"],
  "capabilities": ["new-game", "undo", "save", "load", "fullscreen"],
  "licenseRef": "third-party-notices"
}
~~~

gameId 建立后保持稳定；标题、图标和分类可以调整。宿主按 capabilities 显示按钮，不假定每款游戏都支持悔棋或存档。

## 5｜消息协议草案

消息包统一结构：

~~~json
{
  "channel": "gamestation",
  "protocolVersion": 1,
  "gameId": "gomoku",
  "type": "READY",
  "requestId": "optional",
  "payload": {}
}
~~~

| 方向 | 消息 | 作用 |
|---|---|---|
| 宿主 → 游戏 | INIT | 模式、难度、规则和必要配置 |
| 宿主 → 游戏 | NEW_GAME | 新开一局 |
| 宿主 → 游戏 | PAUSE / RESUME | 暂停/继续 |
| 宿主 → 游戏 | SET_DIFFICULTY | 切换 AI 难度 |
| 宿主 → 游戏 | SET_OPTIONS | 更新本局规则选项 |
| 宿主 → 游戏 | LOAD_STATE | 恢复存档 |
| 宿主 → 游戏 | DISPOSE | 退出并清理资源 |
| 游戏 → 宿主 | READY | 初始化完成 |
| 游戏 → 宿主 | STATE | 能力和可保存状态 |
| 游戏 → 宿主 | SAVE_REQUEST | 请求保存序列化状态 |
| 游戏 → 宿主 | SCORE | 成绩、胜负和统计摘要 |
| 游戏 → 宿主 | GAME_OVER | 对局结束 |
| 游戏 → 宿主 | FULLSCREEN_REQUEST | 请求沉浸/全屏 |
| 游戏 → 宿主 | ERROR | 可展示的错误信息 |

协议必须做 schema 校验。每次加载游戏创建新的会话标识；旧 iframe 的迟到消息不得覆盖新游戏状态。退出游戏必须清理计时器、Worker、音频和事件监听。

## 6｜存档与数据接口

游戏模块只返回可序列化对象，不直接选择宿主的数据目录：

~~~json
{
  "gameId": "gomoku",
  "dataSchemaVersion": 1,
  "savedAt": "local-iso-time",
  "state": {}
}
~~~

宿主按 gameId 保存最高分、胜负、设置和可恢复状态。游戏升级时由模块提供迁移函数或明确拒绝不兼容旧存档；不得静默丢弃数据。

首版必须提供全局 JSON 导出/导入。IndexedDB 作为本地缓存方案，只有在 file:// 关闭浏览器后读回测试通过才可启用为默认持久化。

## 7｜阶段验收

### 阶段 0：宿主原型

- 彻底断网双击打开 index.html。
- 左侧切换至少两个本地测试游戏。
- 宿主与 iframe 双向消息可靠，旧页面消息被丢弃。
- 键盘焦点不串扰；退出游戏后后台不再运行。
- 沉浸模式、浏览器全屏和 Esc 退出正常。
- Worker 兼容性、IndexedDB 跨重启和 JSON 备份通过。
- 网络请求为零。

### 阶段 1：首批游戏

- 五子棋：中国规则/胜负/平局/悔棋和三档 AI。
- 中国象棋：完整合法走法、将军/将杀/困毙、悔棋、棋谱和三档 AI。
- 扫雷：首次点击安全、雷数正确、胜负和计时。
- Klondike：合法移动、抽牌、胜负、撤销和规则选项。
- 俄罗斯方块：旋转、碰撞、消行、等级和最高分。
- 贪吃蛇：方向约束、食物、碰撞、速度和暂停。
- 所有游戏均通过重复开局、缩放、暂停恢复、退出清理和断网测试。

### 阶段 2 及以后

斗地主和麻将先完成规则引擎、AI 基准与公平性测试，再开发 UI。三国杀和魂斗罗先关闭版本/素材/ROM/许可证待决策项，再进入实施。
