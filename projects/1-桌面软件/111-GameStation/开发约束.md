# P111｜GameStation 开发约束

> 约束层级：C｜项目级  
> 适用范围：projects/1-桌面软件/111-GameStation/ 及其将来明确建立的本项目 CI  
> 上位规则：A｜/GPT_RULES.md；B｜projects/1-桌面软件/开发约束.md  
> 本文件只能补充或收紧上位规则，不构成例外。

## C-01｜运行时完全离线

- 发行目录中的主页、游戏、AI、字体、图像、音效、WASM 和其他资源必须全部本地提供。
- 正常启动和游玩不得访问 CDN、远程 API、在线字体、在线图片、远程脚本、在线模型、账号、广告、遥测或网络排行榜。
- 不得把 Service Worker 首次联网缓存、GitHub Pages、Cloudflare Pages、localhost 或常驻服务器作为正常运行条件。
- 任何第三方游戏中残留的联网请求、更新检查、统计、远程素材和外链必须移除或明确禁用，并经离线抓包/请求审计验证。
- 不提供在线对战、云存档或自动更新；程序升级通过用户替换本地程序目录完成，数据另行保留。

## C-02｜file:// 是首要交付环境

- app/index.html 必须优先支持 Chrome / Edge 直接通过 file:// 打开。
- 不能满足 file:// 的模块必须改造、替换或暂缓；不得要求用户启动本地服务器作为隐性补救。
- 运行时优先使用传统 script、相对路径和经典 Worker；ES Module、动态 import、Service Worker、跨源隔离和 SharedArrayBuffer 不得未经验证成为必要依赖。
- Worker、WASM、iframe、文件选择、全屏和 IndexedDB 的兼容性必须在真实 Chrome / Edge file:// 环境测试，不以 HTTP 预览测试代替。
- 如果浏览器限制导致某能力无法实现，必须明确降级或停止该模块，不得悄悄引入网络或服务器。

## C-03｜游戏模块隔离

- 主页只负责导航、注册、统一控制、工作区布局、本地数据和模块生命周期；游戏规则、AI、渲染和游戏内交互必须留在各自模块。
- 每款游戏拥有独立目录、入口和命名空间，不得污染主页面或其他游戏的全局变量、样式和键盘事件。
- 首选独立 HTML + iframe 工作区；iframe 沙箱属性、file:// 相对路径、Worker 和全屏权限必须先通过原型验证。
- 若 iframe 沙箱与 file:// 兼容性冲突，可改用同文档隔离命名空间的经典脚本适配器；不得为了 iframe 方便而要求 localhost。
- 游戏模块不得直接读写其他模块的数据或修改主页 DOM。

## C-04｜模块通信与权限边界

- 主程序与游戏模块通过版本化消息接口通信，不依赖跨 iframe 直接访问 DOM、函数或变量。
- 每条消息必须带协议版本、gameId、消息类型和必要的 requestId；宿主必须检查消息来源窗口、gameId 和 payload 结构。
- file:// 或 sandbox iframe 可能呈现 opaque origin（例如 origin 为 null）；不得只凭 origin 字符串判断可信来源。应同时校验 event.source 是否为当前游戏 iframe 的 contentWindow。
- 对 opaque origin 使用 postMessage 时，必要时可使用 targetOrigin 为 *，但必须严格校验来源窗口和消息结构；不得把这当作可加载不可信第三方代码的安全边界。
- 全屏由宿主统一管理；游戏模块只能请求，不得自行改变整个应用的导航和工作区状态。

## C-05｜本地数据与恢复

- 游戏设置、最高分、胜负记录和可恢复进度由宿主统一管理；每款游戏声明自己的 dataSchemaVersion。
- IndexedDB 可作为首选本机存储候选，但必须验证 file:// 下关闭浏览器后仍可读写；localStorage 只适合少量设置，不能未经验证宣称为可靠备份。
- 必须提供明确的 JSON 导出/导入或等价便携备份；导出完成后提示保存位置。浏览器清理站点数据、换浏览器或移动程序目录可能影响本机存储，必须说明边界。
- 用户数据、存档、导入 ROM、个人配置和真实游戏记录不得提交 Git、CI Artifact 或公开演示数据。
- 代码升级不得自动清空或覆盖玩家数据；schema 迁移必须可校验、可恢复。

## C-06｜AI 难度与公平性

- 适合人机对战的游戏应尽量提供简单、中等、困难三档；人机双人游戏同时支持本机双人轮流操作。
- 三档必须通过算法预算、搜索深度、策略启用程度或受控失误率形成真实差异，并用机机对战、基准局面或胜率测试校准。
- 不得只改变显示标签、思考延时或随机数就宣称棋力不同。
- 不完美信息游戏（斗地主、麻将、三国杀）必须遵守信息公平：AI 只能使用当前玩家合法可见的信息，不得读取其他玩家隐藏手牌、身份或未来随机结果。
- 单人游戏使用清晰的难度预设（速度、地图、密度、计分规则等），不强制设置虚假的 AI 难度。

## C-07｜第三方代码、素材与 ROM

- 每个第三方代码依赖必须登记仓库、固定版本或提交、许可证、原始版权声明、修改内容、文件范围和本地化验证。
- MIT、BSD、Apache 等宽松许可证也必须保留要求的版权和许可文本；不得只登记仓库链接而省略实际随包的 NOTICE。
- GPL/LGPL/AGPL 等强 copyleft 代码不得直接混入或编译进 GameStation 主程序，除非先完成许可证兼容性审查、确定相应源代码提供和分发方式，并取得用户明确的项目级决策。
- 游戏代码许可证不代表立绘、卡牌图片、字体、语音、音乐、音效、商标或 ROM 自动获得再分发授权。
- 三国杀武将/卡牌素材只使用明确授权或原创素材；魂斗罗模拟器不附带 ROM，用户只能自行选择其有权使用的本地 ROM。
- 不得通过网络获取或自动下载任何游戏素材、ROM、模型或扩展包。

## C-08｜运行质量与性能

- 首版以 2D Canvas、SVG 和 DOM 为主；不把 WebGL、Three.js、独显、SharedArrayBuffer 或多线程 WASM 作为基础运行条件。
- AI 搜索和耗时计算优先放入可离线加载的 Worker；Worker 不可用时必须有可控的主线程回退或明确提示。
- 切换游戏时必须停止计时器、动画循环、音频和 Worker，释放事件监听，避免后台游戏继续占用资源。
- 游戏必须支持窗口缩放、键盘焦点、鼠标操作和合理的暂停/继续；不允许全局快捷键抢占游戏自身按键。

## C-09｜验证门禁

- 必须在彻底断网的 Chrome / Edge 中双击 app/index.html 验证启动、切换和完整游玩。
- 测试覆盖网络请求为零、iframe 通信、键盘焦点、全屏、窗口缩放、存档读写、关闭重开和程序目录替换。
- AI 游戏必须验证三档难度差异、合法走法、终局判定和无隐藏信息作弊。
- 每款游戏必须执行规则回归、异常输入、重复开局、暂停恢复、退出清理和长时间运行检查。
- 规划文档、静态检查或 HTTP 预览均不能代替真实 file:// 离线验收；未验证的功能必须明确标记待验证。


## C-09｜公共 UI 基线不可回退

- 游戏标题栏只允许一套，位于各游戏 iframe 内；宿主外层不得重复显示游戏模式、难度、计时或操作按钮。
- 页面最上方宿主标题栏正中央独占本局计时器；游戏内部工具栏单行排列，游戏名称靠左，模式/难度为分段切换按钮，开始/结束、暂停/继续、新局、工具、帮助在同一行，禁止重复显示计时器。
- 禁止将已确认的分段切换控件替换为原生下拉框、select 或左右箭头；禁止未经确认重排公共按钮。
- 游戏工作区不设置常驻左右说明栏/状态栏；玩法说明只进入可拖动帮助面板，且仅能通过 X 关闭。
- 游戏画布必须使用工作区全部可用高度和宽度，保留少量安全边缘，严格保持游戏自身长宽比，不得用固定小画布或固定像素宽度限制主画面。
- 游戏通知/状态必须在游戏主画面内部顶部悬浮；普通通知自动消失，暂停/结束状态持续到恢复/新局；不得使用外部 toast 或浏览器弹窗。
- 游戏区必须接管右键上下文菜单；Enter 统一切换暂停/继续。
- 首页 Hero 文案与装饰图不得重叠；窄屏优先隐藏装饰，不得遮挡文字。

## C-10｜视觉回归是独立验收门禁

- UI 变更必须同时执行 1366×768 和 1440×1000 的真实 Chromium file:// 回归；逐一打开 24 款游戏并保存截图。
- 每款游戏必须验证：标题栏居中计时、分段控件、按钮同一行、通知位置、帮助打开/拖动/X 关闭、右键拦截、Enter 暂停/继续、游戏画布边界与可用高度。
- 画布验收按游戏类别设置比例与最小高度利用率；不得仅以主工作区外框占满作为画布通过证据。
- 扫雷必须单独验证数字字号和旗帜/地雷 SVG 图标相对格子的尺寸。
- 首页必须验证 Hero 文案与装饰图形不相交。
- CI 失败不得通过删除断言或降低阈值掩盖；必须查明真实原因并修复实现或修正无效测试用例。
- UI/规则/AI/离线运行分别记录状态；入口截图通过不得标记游戏规则完整。
