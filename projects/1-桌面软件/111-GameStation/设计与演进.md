# P111｜GameStation 设计与演进

> 本文记录影响多个游戏和长期维护的架构决定。当前内容属于已确认的产品方向与待验证的技术方案，不代表已有实现。

## D-01｜产品定位

GameStation 是一个个人本地游戏中心，不是在线游戏平台，也不是把多个游戏网站嵌入一个页面。

目标体验：

- 打开一个主页即可看到游戏库、分类、最近游玩和收藏。
- 左侧栏选择游戏，右侧主工作区运行游戏。
- 统一提供新游戏、暂停、继续、重开、规则、难度、声音和窗口控制。
- 游戏可以独立更新和测试，不要求主页理解每款游戏的内部规则。
- 所有游戏、AI 和素材随程序本地提供，断网不影响任何已安装游戏。

## D-02｜界面与窗口模式

主页建议采用克制的桌面工作台布局：

- 左侧：主页、最近游玩、收藏、棋类、牌类、益智、街机等分类。
- 右侧：当前游戏工作区，游戏标题和统一控制位于工作区顶部。
- 主页：分类入口、最近游玩、收藏和游戏卡片。
- 设置：统一声音、主题、快捷键、存档和数据备份入口。

显示状态明确分为三种：

1. 普通工作区：保留左侧导航，游戏占据右侧工作区。
2. 沉浸工作区：隐藏导航和非必要工具栏，游戏占据应用可用区域。
3. 浏览器全屏：由宿主对应用根容器调用 Fullscreen API；退出由浏览器或 Esc 处理。

网页不能直接控制操作系统窗口最大化按钮。产品文案使用“沉浸工作区”和“浏览器全屏”，不混称系统窗口最大化。

## D-03｜主程序与游戏模块

当前首选架构：

~~~text
GameStation
├── Host Shell
│   ├── Home / Sidebar / Workspace
│   ├── Game Registry
│   ├── Game Bridge
│   ├── Fullscreen Controller
│   ├── Local Storage / Backup
│   └── Settings / History
│
└── Games
    ├── gomoku/
    ├── xiangqi/
    ├── sanguosha/
    ├── contra/
    ├── doudizhu/
    ├── mahjong/
    ├── minesweeper/
    ├── solitaire/
    ├── tetris/
    └── snake/
~~~

每款游戏拥有独立入口 HTML、样式、逻辑、可选 Worker 和本地资源。主页不复制游戏代码，也不把所有游戏写成一个巨型 JavaScript 文件。

首选用 iframe 加载独立游戏页面，以隔离 CSS、全局变量和键盘事件。由于 file://、sandbox、Worker 和 Fullscreen 的浏览器边界可能相互影响，iframe 沙箱参数尚未最终冻结，必须先做最小原型。若不稳定，回退到同文档经典脚本 + 独立命名空间适配器；不得回退为必须运行本地服务器。

## D-04｜游戏注册清单

宿主通过静态注册表发现游戏。每款游戏至少声明：

- gameId：永久稳定的英文 ID。
- title、category、description、icon：主页展示资料。
- entry：相对 app 目录的本地入口。
- moduleVersion、dataSchemaVersion：程序和存档版本。
- modes：single-player、human-vs-human、human-vs-ai 等模式。
- difficulty：AI 游戏的 easy / normal / hard，或单人游戏的预设难度。
- capabilities：new-game、pause、resume、undo、save、load、fullscreen、sound 等能力。
- licenseRef：第三方代码与素材许可记录的引用。

宿主只展示模块声明支持的能力，不给不支持的游戏显示无效按钮。

## D-05｜宿主与游戏通信协议

宿主与游戏通过版本化 postMessage 通信，不直接访问 iframe 内部 DOM 或游戏全局变量。

统一消息包：

~~~json
{
  "channel": "gamestation",
  "protocolVersion": 1,
  "gameId": "gomoku",
  "type": "READY",
  "requestId": "optional-id",
  "payload": {}
}
~~~

宿主发送的消息类型：

- INIT：传递当前模式、难度、规则配置和必要的游戏设置。
- NEW_GAME：开始新局。
- PAUSE / RESUME：暂停或继续。
- SET_DIFFICULTY：设置 AI 难度。
- SET_OPTIONS：设置游戏规则或单人难度参数。
- LOAD_STATE：恢复指定游戏的存档。
- DISPOSE：退出游戏，要求清理计时器、Worker、音频和事件监听。

游戏发送的消息类型：

- READY：游戏初始化完成。
- STATE：回传当前可保存状态或能力状态。
- SAVE_REQUEST：请求宿主保存序列化数据。
- SCORE：回传成绩、胜负或统计摘要。
- GAME_OVER：通知终局。
- FULLSCREEN_REQUEST：请求宿主进入沉浸或全屏。
- ERROR：报告可显示给用户的错误。

宿主必须校验消息来源窗口、gameId、协议版本和 payload 结构。sandbox iframe 的 origin 可能为 null；不能只依赖 origin 字符串。使用 opaque origin 时，targetOrigin 可能需要为 *，但仍须校验 event.source 为当前 iframe 的 contentWindow。

## D-06｜本地数据

玩家数据由宿主统一保存，游戏模块只提供可序列化状态：

- 全局：主题、声音、最近游玩、收藏和快捷键。
- 单款游戏：最高分、胜负、难度、规则设置、可恢复对局。
- 每款游戏的存档包含自己的 dataSchemaVersion。
- 宿主负责备份、恢复、迁移和损坏提示。

IndexedDB 是首选本机存储候选，但 file:// 下的跨重启持久性必须实测。必须提供 JSON 导出/导入；若后续引入 ZIP，需单独审查离线压缩库和数据完整性。浏览器清理数据或换浏览器后不能保证缓存仍在，用户备份才是可迁移副本。

可选的 File System Access API 目录保存只作为增强能力，必须先验证 Chrome / Edge 的 file:// 权限行为，不作为首版启动前提。

## D-07｜运行时兼容

- 首选传统 script 和相对路径；不把 ES Module 动态导入作为 file:// 运行前提。
- Worker 优先经典 Worker 或 Blob Worker；ES Module Worker 需要改造或打包。
- WASM 只有在可内嵌或本地可读取、无需服务器响应头、无需跨源隔离时才考虑。
- 不依赖 Service Worker、PWA 安装、COOP / COEP、SharedArrayBuffer 或在线缓存。
- 首版以 2D Canvas / SVG / DOM 为主，避免不必要的 WebGL 和 3D 场景。
- AI 搜索不得阻塞主界面；对 Worker 受限的环境提供有上限的主线程回退。

## D-08｜AI 难度模型

AI 难度统一命名为简单、中等、困难，但每款游戏独立实现：

- 完全信息棋类：通过搜索深度、时间预算、评估函数和受控失误率调节。
- 不完全信息牌类：通过牌型规划、公开信息记牌、概率估计、队友协作和残局策略调节。
- 三国杀：通过身份推断、公开行为建模、技能组合和行动价值评估调节。
- 单人街机/益智：通过速度、地图规模、障碍密度、提示次数或规则预设调节，不伪装成 AI 对手。

难度校准必须使用基准局面、机机对战或胜率数据；不得读取对手隐藏信息或未来随机结果。

## D-09｜首批与后续范围

首批可玩范围：

1. 五子棋：本机双人、人机，简单/中等/困难。
2. 中国象棋：本机双人、人机，简单/中等/困难。
3. 扫雷：初级/中级/高级与自定义棋盘。
4. Windows 经典纸牌：首版按 Klondike 规则，支持抽一张/抽三张和计分选项。
5. 俄罗斯方块：速度等级、下一个方块预览、暂停和最高分。
6. 贪吃蛇：速度等级、暂停、最高分和可选障碍。

低成本扩展：2048、记忆翻牌、数独、推箱子、Pong。

后续复杂游戏：

- 斗地主：1 名人类 + 2 名 AI；简单/中等/困难，必须遵守隐藏手牌信息边界。
- 麻将：1 名人类 + 3 名 AI；先确定一个基础规则集，再逐步增加规则开关和独立地方规则包。
- 三国杀：先做有限身份局、基础牌堆和明确指定的小乔版本；技能、扩展包和素材逐项核验。
- 魂斗罗：模拟器与 ROM 分开；不随程序分发游戏 ROM，使用者自行选择其有权使用的本地 ROM。

## D-10｜尚未冻结的关键决策

- iframe sandbox 与 file:// Worker 的兼容性：由阶段 0 原型决定。
- 本机存档主路径：由 IndexedDB、JSON 备份和可选目录保存的真实测试决定。
- 中国象棋强 AI：优先评估 MIT 的规则/引擎组合；GPL Pikafish 仅作为单独许可证决策项。
- 麻将：需要确定首版基础规则，不能把多个地方规则误做成一组简单开关。
- 三国杀：需要确认“小乔”具体版本、扩展包范围及可合法使用的卡牌/武将素材。
- 魂斗罗：需要确认采用用户本地 ROM 还是开发原创横版射击游戏。

以上待决策项未关闭前，不应把相应游戏标记为已选依赖或已完成。
