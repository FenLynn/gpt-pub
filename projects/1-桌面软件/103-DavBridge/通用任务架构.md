# DavBridge v0.2 通用任务架构

## 1. 产品重新定位

DavBridge 从 v0.2 开始不再等同于“InfiniCLOUD 到坚果云的 Zotero 迁移器”。

新的产品定位是：

> 面向 Windows 的可靠、低速、可恢复、强校验的单向数据迁移、备份和镜像任务管理器。

明确不进入双向同步领域。当前阶段不实现删除传播、双向冲突合并、双向 rename detection 或循环同步。

## 2. 第一阶段基线不可破坏

`main` 上的 v0.1.7 是第一阶段已实机验证的稳定基线。v0.2 通用化必须满足：

1. InfiniCLOUD 源端只读语义不退化；
2. 目标重新 GET 和 SHA-256 强校验不退化；
3. GoodSync 既有副本一致时零上传接管，不一致时不自动覆盖；
4. 配额、限速、断点恢复、托盘后台、暂停恢复语义保持；
5. `.zip + .prop` 的 Zotero 成组规则必须继续作为固定模板存在；
6. 在通用任务模型达到行为等价前，v0.1.7 运行引擎继续保留，不以抽象重构替换已验证链路。

## 3. 核心抽象

### 3.1 Task

一个 `TransferTaskDefinition` 表示一项独立任务。任务类型当前只允许：

- Migration，单向转移；
- Backup，单向备份；
- Mirror，单向镜像。

Mirror 仍然不是双向同步。默认不传播源端删除，也不自动删除目标端额外对象。

### 3.2 Endpoint

一个 `EndpointDefinition` 表示源或目标端。

第一批端点：

- WebDAV；
- LocalFolder，作为后续扩展入口。

端点与服务商策略分离。WebDAV 是协议，InfiniCLOUD 和坚果云是 Provider Profile。

### 3.3 Policy

`TransferPolicyDefinition` 负责通用行为：

- 单文件或逻辑分组；
- Strong SHA-256；
- 已有目标一致时接管，否则冲突；
- 上传限速；
- 请求间隔；
- 单文件限制；
- 上传和下载配额；
- 安全预留与周期策略。

安全默认值必须保守：不删除目标额外对象，不传播删除，不自动覆盖不可信冲突。

### 3.4 Template

模板是任务创建时的预设，不是独立运行引擎。

第一批模板：

- `generic-webdav-one-way`，普通 WebDAV 单向任务；
- `zotero-webdav-one-way`，Zotero 固定任务模板。

Zotero 模板默认启用 `.zip + .prop` 同 basename 成组，以及 v0.1.7 已验证的强校验和冲突策略。因此以后既可以 InfiniCLOUD → 坚果云，也可以坚果云 → 其他 WebDAV，或其他 WebDAV → 坚果云，只需替换端点和相应 Provider Profile。

## 4. Provider Profile

服务商特有约束不得继续散落在通用引擎中。

例如坚果云 Profile 负责：

- 上传配额；
- 下载配额；
- 普通安全预留；
- 单文件限制；
- 请求节流；
- 重置日期语义；
- 09:00 后真实上传探测；
- 750+ 目录列举显示语义。

InfiniCLOUD Profile 当前主要负责认证提示与源端只读使用方式。

Provider Profile 只提供约束和默认值，不能削弱任务自身的数据安全策略。

## 5. UI 方向

### 5.1 常规主窗口

常规打开 DavBridge 时采用紧凑主视图，类似常驻通讯工具的任务面板：

- 左侧为任务列表或窄导航；
- 右侧显示当前任务的简要状态；
- 窗口缩小时必须自适应，不允许按钮或文字遮挡；
- 主窗口关闭只隐藏到托盘，后台任务继续运行。

### 5.2 首页信息层级

首页只突出日常信息：

- 任务名称；
- 源 → 目标；
- Running / Paused / WaitQuota 等人类可读状态；
- 总体已验证进度；
- 当前周期上传与下载；
- 当前文件或暂停断点；
- 开始 / 暂停；
- 查看详情。

连接诊断、就绪扫描、首组验证、既有副本验证等首次初始化工具移入“初始化与诊断”，任务完成初始化后不再占据首页主操作区。

### 5.3 日常继续

任务完成首次安全门并已经激活后：

```text
暂停 → 继续
```

必须直接继续，不再重复弹出整套就绪扫描和长期迁移确认。只有端点、凭据、根路径、关键策略发生变化，或状态安全条件失效时，才重新要求诊断或确认。

## 6. v0.1.7 兼容方式

v0.2 第一阶段采用只读投影：

```text
旧 config.json
旧 state.json
旧 secrets.dat
      ↓ 读取
LegacyV017Adapter
      ↓
一个内置 Zotero TransferTask
```

此阶段：

- 不重写 `config.json`；
- 不重写 `state.json`；
- 不重写 `secrets.dat`；
- 不改变 DPAPI 凭据；
- 不改变已有 StrongVerified 记录；
- 不改变当前配额账本。

待多任务存储真正接管运行时前，必须先实现并通过《数据兼容与升级.md》规定的备份、迁移、回滚和等价性测试。

## 7. v0.2 分阶段实施

### Phase A，旁路任务模型

新增 Task / Endpoint / Policy / Template / Legacy Adapter，不接管 v0.1.7 运行时。

### Phase B，任务视图

新 UI 读取 Legacy Adapter，把当前单任务显示为任务卡片，但底层仍调用原运行引擎和原数据文件。

### Phase C，多任务持久化

引入新的任务清单存储。首次升级必须自动备份 v0.1.7 Data，并把旧单任务映射成固定任务。迁移成功前不删除旧文件。

### Phase D，通用端点运行

普通 WebDAV 任务和 Zotero 模板开始真正共用通用任务引擎。必须用当前 Zotero 真实行为作为回归基线。

## 8. 验收原则

通用化不是“代码看起来更抽象”就算完成。最低验收是：

> 用 v0.2 的任务模型创建一个与 v0.1.7 当前配置等价的 Zotero 任务后，真实传输、安全门、配额、GoodSync 接管、暂停恢复和强校验行为不得弱于 v0.1.7。
