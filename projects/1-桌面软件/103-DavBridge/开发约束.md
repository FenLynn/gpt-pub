# DavBridge 开发约束

> 约束层级：C｜项目级  
> 适用范围：P103 DavBridge  
> 上位规则：A｜`/GPT_RULES.md`；B｜`../开发约束.md`

本文件只保存 DavBridge 当前仍生效、后续版本不得随意破坏的长期规则。

## C-01｜项目身份与写入范围

- 产品名称固定为 **DavBridge**，项目编号固定为 **P103**。
- 正式路径固定为 `projects/1-桌面软件/103-DavBridge/`。
- 技术栈首阶段固定为 C#、.NET 8、WinForms、Windows x64。
- 长期分支为 `p103-exp`、`p103-stable` 和 `main`，提升和回流服从 B 级规则。
- P103 只允许修改 P103 项目目录、P103 活动 CI，以及确有必要的 P103 状态入口。
- 不得修改 Mediova、AtlasDesk 或其他项目的源码、CI、长期分支、版本和 Release。

## C-02｜迁移方向与源端不可破坏

- 唯一正式方向为 `InfiniCLOUD → 坚果云`。
- InfiniCLOUD 是唯一 authoritative source，正式产品代码对源端只允许读取和属性查询，不实现 DELETE、MOVE、COPY、MKCOL 或 PUT。
- 产品不是通用双向同步器，不实现自动反向覆盖。
- 任何失败、异常、冲突、额度不足或中断都不得删除或修改源端对象。
- 坚果云保存经过验证的单向镜像子集。回收站中的待确认对象是唯一受控的临时例外。
- 禁止后台自动传播源端删除。只有符合 C-14 全部条件并经过人工明确批准时，才允许从坚果云执行受控删除。
- 通用任务模型中的 `PropagateSourceDeletes` 与 `DeleteExtraneousTargetObjects` 不得因为 v0.3 回收站而直接开启。

## C-03｜Zotero 对象与分组

- `/zotero` 下所有普通资源都进入迁移 manifest，不得只复制已知扩展名。
- 同一 basename 的 `.zip` 与 `.prop` 必须识别为一个 Zotero Attachment Group，并串行完成。
- 一个 Group 只有所有成员都通过强校验后才能标记为 `GROUP_VERIFIED`。
- 某成员已强校验而另一成员失败时，Group 保持部分完成，下次只重试未完成或已失效成员。
- 删除观察、人工审查和最终删除也必须以完整 Group 为安全单位，不允许只因单个 `.zip` 或 `.prop` 暂时不可见而删除对应目标成员。
- 不为了迁移批次或规避目录列举限制，在目标 `/zotero` 下建立任意 batch 子目录。

## C-04｜成功判定与强校验

- WebDAV PUT 返回成功不等于迁移成功。
- 对新上传对象，每个目标对象至少经历：PUT 返回可接受状态、针对准确资源 URL 的存在与长度确认、从目标端重新 GET、SHA-256 与源端下载内容一致。
- 对迁移开始前已经存在于坚果云的对象，也必须重新 GET 并计算 SHA-256；只有其实际字节长度和 SHA-256 与当前 InfiniCLOUD 源对象完全一致，才能直接接管并标记为 `STRONG_VERIFIED`，且不得重复上传。
- 只有目标端重新读取的 SHA-256 与源端 SHA-256 一致，且源端在本次校验期间未发生变化，文件才能标记为 `STRONG_VERIFIED`。
- `STRONG_VERIFIED` 后保存的 Source SHA-256、Target SHA-256、目标 ETag 与 VerifiedAt 构成后续周期对账和受控删除的历史核准基线，不得被普通 metadata 扫描随意覆盖。
- 若 PUT 返回成功但后续资源不存在、长度不符、GET 失败或哈希不符，必须形成明确失败状态，不得记为成功。
- 已知单个文件的确认必须直接查询准确资源 URL，不依赖重新列举整个大目录。

## C-05｜源端变化、既有目标与冲突

- 每个真实坚果云额度周期开始后，普通 backlog 前必须先完成一次 InfiniCLOUD 源清单对账。
- 已 `STRONG_VERIFIED` 对象 metadata 未变化时不重复下载文件内容。
- 已 `STRONG_VERIFIED` 对象 metadata 变化时，只重新 GET InfiniCLOUD 并计算 SHA-256。若 SHA-256 与历史 Source SHA-256 相同，只更新源 metadata；若不同，进入 `SOURCE_CHANGED` 并优先于普通 backlog 刷新目标。
- 源对象在传输、接管或周期核验期间变化时，本轮结果不得进入最终完成状态，必须重新进入队列。
- 新增对象只加入普通 backlog，与此前尚未迁移的剩余对象同级，不提高优先级。
- 迁移开始前由 GoodSync、人工复制或其他客户端已经放在坚果云的同名对象，不因来源未知自动视为冲突。DavBridge 必须下载目标对象并与当前 InfiniCLOUD 源对象做强哈希比较。
- 既有目标对象与当前源对象字节数及 SHA-256 完全一致时，允许安全接管为 `STRONG_VERIFIED`，不执行 PUT，不消耗 DavBridge 上传额度，但目标 GET 必须计入下载账本。
- 一旦对象已经完成 `STRONG_VERIFIED`，其历史目标 SHA-256 就成为可信目标基线，不再区分最初由 DavBridge、GoodSync 还是人工复制写入。
- 源端后续版本变化时，只有能够证明当前坚果云对象仍等于上一次 `STRONG_VERIFIED` 目标基线，才允许安全覆盖旧版本。
- 无法证明目标身份、目标内容与历史基线不一致、写入结果未知或其他安全条件不成立时，必须停止自动覆盖并进入明确异常状态。

## C-06｜坚果云流量预算

- 默认上传总额度按 1,000,000,000 bytes 保守计量，允许用户校正配置。
- 每个坚果云流量周期默认永久预留 **50 MB** 给其他服务；普通迁移停止线为官方周期总额度减去 50 MB。
- 额度周期使用坚果云账户实际“流量重置”日期，不按自然月 1 日推断。
- 软件无法取得公开稳定的官方实时流量 API 时，使用“人工官方校准值 + 校准后 DavBridge 保守计量”的双层模型。
- 每次 PUT 尝试至少按完整对象大小计入本地保守上传账本，即使请求失败或最终校验失败也不得回退计量。
- 对已经存在且强校验一致的目标对象，不执行 PUT，因此不计 DavBridge 上传额度；重新 GET 校验的数据计入下载账本。
- 周期对账默认只读取 InfiniCLOUD 发生 metadata 变化的文件。不得为了例行周期维护重新下载全部坚果云历史对象。
- 删除前因目标 ETag 无法证明身份而进行的必要目标回读，必须服从下载安全额度并计入下载账本。
- 用户可以不定期输入坚果云页面显示的上传已用、下载已用和下一次重置日期，形成新的官方校准点。
- 界面必须明确区分“官方校准值”和“DavBridge 估算值”，不得把本地估算冒充官方实时流量。

## C-07｜周期末冲刺

- 默认允许在流量重置前 24 小时进入 End-of-cycle Sprint。
- 普通阶段保留 50 MB；冲刺阶段默认仍保留 5 MB 最低安全余量，除非后续真实服务验证支持更精确策略。
- 冲刺模式继续以完整 Group 为调度单位，不为了榨取剩余额度拆散逻辑分组。
- 坚果云额度耗尽时的具体 HTTP 状态码或响应正文，在真实账户验证之前不得写死为唯一判断。
- 认证失败、限流、网络错误、5xx 和额度耗尽必须尽可能区分；无法可靠区分时宁可进入可恢复失败，也不得错误宣称额度已耗尽。

## C-08｜请求频率与速度限制

- 坚果云目标端必须有独立请求节流器，默认目标不超过 450 次请求/滚动 30 分钟，并保留安全间隔。
- 上传带宽限制与请求频率限制是两套独立机制。
- 默认上传速度为 300 KB/s，可由用户调整，但不得通过提高速度绕过目标端请求安全限制。
- 429、明确限流响应和连续服务异常必须采用退避等待，不得高频重试。

## C-09｜500 MB 与迁移就绪扫描

- 开始长期迁移前必须执行 Migration Readiness Scan。
- 扫描至少统计对象数量、总大小、最大文件、`.zip/.prop` 配对异常和超过目标 WebDAV 单文件上限的对象。
- 当前用户已确认现有库不存在超过 500 MB 的单文件，但程序仍必须保留运行时检查。
- 发现超过目标上限的对象时标记为 `BLOCKED_OVERSIZE`，不得自行切片或改变 Zotero 远端格式。

## C-10｜后台运行与人工操作门

- DavBridge 是普通用户托盘程序，不实现 Windows Service。
- 支持用户可选的 Windows 登录后自动启动，无需管理员权限。
- 开机自启动时默认直接进入后台；窗口右上角关闭默认缩到托盘，只有明确执行“退出 DavBridge”才结束进程。
- 正常源端对账、源变化检测、修改优先修复、新增登记、普通迁移和周期恢复全部自动执行。
- 只有真正需要用户决定的事项才进入人工操作门，例如成熟回收站审查、Conflict、目标身份异常、认证失效或必须人工校准的流量信息。
- 存在阻塞人工项时，界面必须明显说明为什么停止、需要用户做什么以及处理后会继续什么，不得只显示模糊的“暂停”。
- 后台必须区分 `RUNNING`、`WAIT_NETWORK`、`WAIT_QUOTA`、`WAIT_RETRY`、`WAIT_USER`、`PAUSED` 和 `COMPLETE`，不得用高频死循环轮询。

## C-11｜状态持久化与私人 Data

- Runtime 与私人 Data 严格分离。
- `%APPDATA%\DavBridge` 保存轻量重要状态和配置；`%LOCALAPPDATA%\DavBridge` 保存日志、缓存和临时文件。
- WebDAV 密码或应用密码不得明文保存，使用 Windows DPAPI 或经过明确审查的等效 CurrentUser 级保护。
- 状态保存采用同目录临时文件、同步落盘、原子替换和 `.bak` 回退，不得直接截断唯一主文件后写入。
- v0.3 周期对账与回收站状态使用独立 `reconcile.json` sidecar，不替代也不破坏旧 `state.json`、`config.json` 与 `secrets.dat`。
- Runtime、源码、CI、Artifact、Release 不得包含真实凭据、真实 Zotero 文件清单、真实远端目录、Cookie、Token、用户日志或私人路径。

## C-12｜最终完成与准确表述

- 每个对象在迁移或既有目标接管时完成目标端重新 GET 和 SHA-256 强校验，避免最终一次性重新下载整个库。
- 每个真实额度周期继续执行源端对账，因此长期完成状态不是一次性冻结，而是持续维护的已验证镜像。
- 普通 backlog 清零时再执行一次全量 source manifest 与账本闭合检查，但不得因此重新下载整个坚果云。
- 活动镜像中所有对象必须对应当前 InfiniCLOUD 对象；回收站中仍保留在坚果云的待确认对象必须单独统计，不得伪装成活动镜像成员。
- 若只能证明“当前源端所有已知对象在目标端存在且曾强校验”，只能表述为 `Content Complete`。
- 只有目标端完整枚举也经过验证、没有未知额外对象且回收站例外被明确披露，才能表述为 `Exact Mirror`。
- 坚果云 750 项后的实际分页协议细节在真实服务验证前属于待验证能力，不得凭猜测实现后宣称完成。

## C-13｜测试与完成判定

自动测试至少覆盖：

- zip/prop Group 生成和部分完成恢复；
- 50 MB 普通预留与 24 小时冲刺策略；
- PUT 成功但目标不存在；
- 长度不符和哈希不符；
- 源端传输期间变化；
- 迁移前已存在且与源端字节完全一致的目标对象可安全接管，并且不得重复 PUT；
- 迁移前已存在但与源端不同的未知目标必须冲突且不得覆盖；
- 请求限流和退避；
- 状态文件损坏后 `.bak` 回退；
- 关机或异常退出后的断点恢复；
- 超过 500 MB 的阻塞；
- 数千至一万以上对象的 manifest 和分组；
- Cycle ID 使用真实重置日期的 `yyMMdd`，且不得受 CI 或运行机器时区换日影响；
- 首次缺失只观察，跨后续已确认额度周期后才进入人工审查；
- 本周期人工保留只解除当前周期阻塞，下个周期仍缺失时必须重新审查；
- 回收站 DELETE 永远不能由后台自动触发；
- 删除前源恢复、目标身份变化和删除结果不确定都必须安全停止或协调，不得盲目继续。

CI 和 Mock WebDAV 只能证明本地实现逻辑，不能替代真实 InfiniCLOUD、坚果云账户行为。真实服务未验证的能力必须保留“待验证”状态。

## C-14｜v0.3 周期对账与受控回收站

- Cycle ID 使用启动当前额度周期的真实重置日期，格式固定为 `yyMMdd`。例如 2026-09-07 重置后启动的周期记为 `260907`。
- 只有真实重置探测确认成功后，才进入新的 Cycle。不得因为本地日期到了就提前推进 Cycle。
- 每个新 Cycle 普通上传前先自动读取 InfiniCLOUD manifest，并与历史 `STRONG_VERIFIED` 账本对账。
- 修改项优先修复；新增项只进入普通 backlog。
- 一个历史完整 `STRONG_VERIFIED` Group 第一次从源 manifest 消失时，只记录 `FirstMissingCycleId`，坚果云内容不移动、不重命名、不删除。
- 只有后续已确认 Cycle 中该 Group 仍然不存在，才进入人工删除审查。
- 用户选择“本周期保留”后，该对象继续存在于回收站，本周期普通迁移可以继续；下个 Cycle 若仍不存在，再次进入人工审查。对象可以跨多个 Cycle 持续保留。
- 永远不存在超时默认删除、后台自动删除或批量无确认删除。
- 用户点击删除后，DavBridge 必须再次确认源端仍不存在，并核对目标大小、ETag 或必要时目标 SHA-256，确认它仍是历史核准对象后才执行 DELETE。
- 删除失败、连接中断或结果不确定时，不允许盲目重复 DELETE。必须重新查询准确目标路径，并在无法安全证明时回到人工审查。
- 已人工删除的对象若后来重新出现在 InfiniCLOUD，必须作为源端变化优先恢复到坚果云并重新 `STRONG_VERIFIED`。
