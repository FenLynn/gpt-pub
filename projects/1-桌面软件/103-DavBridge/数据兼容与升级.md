# DavBridge 数据兼容与升级契约

## 1. 目标

本文件约束 v0.1.7 之后所有涉及本地 Data 的升级。核心原则是：用户正在运行的迁移状态优先于代码重构便利性。

## 2. v0.1.7 Data 事实

当前用户数据位于 Windows 用户目录，不属于 Runtime，也不得进入 GitHub：

- `%APPDATA%/DavBridge/config.json`
- `%APPDATA%/DavBridge/state.json`
- `%APPDATA%/DavBridge/state.json.bak`
- `%APPDATA%/DavBridge/secrets.dat`
- `%LOCALAPPDATA%/DavBridge/Temp/`

其中 `secrets.dat` 使用 Windows DPAPI CurrentUser 保护。

## 3. 硬规则

1. 新版本不得因为“模型升级”直接删除或覆盖旧 Data；
2. 迁移前必须生成可识别版本的备份副本；
3. 迁移操作必须可重复执行，重复执行不能继续破坏数据；
4. 迁移失败时必须继续允许旧版 v0.1.7 读取原数据；
5. StrongVerified 记录、配额账本、安全门状态和暂停语义不得丢失；
6. DPAPI 凭据不得转成明文，不因架构升级要求用户重新输入，除非 Windows 本身无法解密；
7. 任何 SchemaVersion 提升必须提供旧版本加载测试；
8. Runtime 更新与 Data 迁移必须分离，单纯替换 EXE 不得自动执行不可逆转换；
9. 如果内建迁移不足以安全完成，必须同时提供独立一次性转换工具或脚本；
10. 不允许要求用户手工编辑 JSON 来完成正常升级。

## 4. v0.2 兼容策略

v0.2 不迁移也不改写 v0.1.7 三个核心 Data 文件。

新版通过 `LegacyV017Adapter` 只读读取旧配置并投影成一个固定 Zotero 任务。原迁移引擎继续直接使用旧 `DavBridgeConfig`、`MigrationState` 和 DPAPI 凭据。

v0.2 允许新增一个独立、可安全删除的旁路文件：

```text
%APPDATA%/DavBridge/v2-compat.json
%APPDATA%/DavBridge/v2-compat.json.bak
```

它只记录 v0.2 UI 与任务壳需要的兼容信息，例如当前旧任务的端点安全指纹。它不保存密码、不保存 TransferRecord、不保存配额账本，也不替代 `state.json`。

删除该 sidecar 后，v0.1.7 仍可完全按原方式运行。因此它不是不可逆数据迁移。

### 4.1 端点身份保护

已有迁移记录的旧任务中，以下字段共同定义任务端点身份：

- 源 Base URL；
- 源 root；
- 源用户名；
- 目标 Base URL；
- 目标 root；
- 目标用户名。

一旦已有 TransferRecord，v0.2 及后续版本不允许通过“设置”直接把这些字段改成另一套端点。以后从坚果云迁到其他位置应创建新的 Zotero 任务，从而天然隔离旧任务的 StrongVerified 和断点记录。

密码、限速、额度预留、自动启动等不改变端点身份的参数仍可正常修改。

## 5. v0.3 周期对账 sidecar

v0.3 新增：

```text
%APPDATA%/DavBridge/reconcile.json
%APPDATA%/DavBridge/reconcile.json.bak
```

该文件只保存周期对账和逻辑回收站状态，包括：

- 当前 Cycle ID；
- 最后完成对账的 Cycle ID 与时间；
- 最近一次源 manifest 统计；
- 首次缺失 Cycle；
- 本周期人工保留 Cycle；
- 已人工删除 Cycle 与时间；
- 删除安全检查产生的阻止原因。

它不保存密码，不替代 `state.json` 中的 TransferRecord、StrongVerified SHA-256、流量账本或迁移断点。

Cycle ID 固定使用启动当前坚果云额度周期的真实重置日期，格式 `yyMMdd`。例如 2026-09-07 重置后启动的周期记为 `260907`。Cycle 日历日期不得因为运行机器或 CI 时区换算而改变。

### 5.1 sidecar 丢失时的安全方向

`reconcile.json` 丢失或损坏不得导致自动删除风险。

如果主文件和 `.bak` 都不可读：

1. 新建空的 ReconciliationState；
2. 保留所有 `state.json` StrongVerified 与迁移进度；
3. 所有历史删除观察期视为尚未建立，不允许据旧记忆直接删除；
4. 从当前 Cycle 重新建立首次缺失观察；
5. 旧版 v0.1.7 仍可继续读取原三项核心 Data。

因此丢失 `reconcile.json` 的后果只能是“删除资格变得更保守”，不能变成“更容易删除”。

### 5.2 v0.3 不执行核心 Data 迁移

v0.3.0 仍保持 `MigrationState.SchemaVersion = 1`。新增 `EngineState.WaitUser` 只能追加枚举值，不允许改变既有枚举的数值映射。

直接替换 EXE 后：

- `config.json` 原样继续使用；
- `state.json` 原样继续使用；
- `state.json.bak` 原样继续使用；
- `secrets.dat` 原样继续使用；
- `reconcile.json` 按需首次创建。

因此 v0.3 的周期维护能力通过旁路状态扩展，而不是对用户已经积累的迁移账本做不可逆转换。

## 6. v0.4.4 产品体验 sidecar

v0.4.4 新增可再生的本地 UI 辅助状态：

```text
%LOCALAPPDATA%/DavBridge/product-experience.json
%LOCALAPPDATA%/DavBridge/product-experience.json.bak
```

该 sidecar 只允许保存连接诊断/就绪扫描是否通过、最近观察 Cycle、最近 EngineState 和有限数量的通用活动事件。它禁止保存 WebDAV 凭据、真实 Zotero 文件名、远端 root、TransferRecord、StrongVerified SHA-256、配额迁移账本或删除资格。

删除或损坏该文件只会让 UI 辅助状态重新建立，不得改变 `config.json`、`state.json`、`reconcile.json`、`secrets.dat` 或任何 Core 安全判定。

从 v0.4.5 起，product-experience sidecar 的读取顺序为主文件优先、`.bak` 备份回退。若主文件损坏且备份可解析，会从备份恢复并修复主文件。该恢复仍只影响 UI 辅助状态。

v0.4.4 的脱敏诊断 ZIP 是排障材料，不是 Data 备份。它不得包含密码、真实文件名、远端目录、私人本机路径、TransferRecord 内容或 StrongVerified SHA。

## 7. v0.4.6 运行会话 marker

v0.4.6 新增：

```text
%LOCALAPPDATA%/DavBridge/runtime-session.json
```

该文件是可再生的活动会话 marker，仅允许保存会话 ID、启动时间、最后心跳、clean exit 时间、产品版本、构建短 SHA 和通用 EngineState。它禁止保存真实文件名、远端路径、URL、WebDAV 用户名/密码、TransferRecord 或 StrongVerified SHA。

正常退出时 marker 会被删除。若进程异常终止，marker 留存仅用于下一次启动判断“上次异常中断”。它不得作为任何迁移安全判定或恢复账本。

TempRoot 中的异常中断残留 `*.part` 与 `reset-probe-state.json` 可在下次启动、迁移尚未开始时删除。核心恢复仍完全依赖 Roaming Data 下的持久化状态文件。

## 8. v0.4.8 窗口布局 sidecar schema

`%LOCALAPPDATA%/DavBridge/window.json` 仍只保存窗口 X/Y、宽高和最大化状态，不属于核心迁移 Data。

从 v0.4.8 起，该文件增加 `SchemaVersion=2`。没有 SchemaVersion 的旧记录被视为旧扁窗口布局，并在首次启动时一次性迁移为 4:3：保持原宽度，目标高度为 `width × 3/4`。显示器工作区不足时才按 4:3 等比例缩小。迁移完成后立即写回 schema v2。

schema v2 以后，用户主动拖动或调整的窗口尺寸继续按原尺寸保存和恢复，不再每次启动强制改成 4:3。

该窗口 sidecar 的损坏或删除不得影响 config、state、reconcile、secrets 或任何迁移安全判定。

## 9. v0.4.19 product-experience sidecar schema 2

v0.4.19 只升级可再生的 UI 辅助 sidecar：

```text
%LOCALAPPDATA%/DavBridge/product-experience.json
%LOCALAPPDATA%/DavBridge/product-experience.json.bak
```

其 `SchemaVersion` 从 1 提升为 2，并新增：

```text
OperationalLedgerStartedAt
OperationalEvents[]
```

每条 OperationalEvent 只允许包含时间戳与匿名类别。目前类别固定为 `warning`、`network`、`pause`、`complete`。

明确禁止在该账本中写入：

- 真实 Zotero 文件名或 GroupKey；
- 本地或远端路径；
- URL；
- WebDAV 用户名或密码；
- TransferRecord；
- StrongVerified SHA-256；
- 上传/下载核心配额账本；
- DELETE 资格。

### 9.1 升级语义

旧 schema 1 可以直接反序列化。首次由 v0.4.19 初始化时：

```text
读取旧 sidecar / .bak
→ 建立 OperationalLedgerStartedAt = 当前升级时刻
→ 将仍保留的通用活动投影为可识别匿名事件
→ SchemaVersion = 2
→ 原子保存主文件并继续保留 .bak
```

由于旧 sidecar 最多只有有限数量近期活动，升级时刻之前的 24 小时历史不能证明完整，因此完整窗口从 `OperationalLedgerStartedAt` 开始计算。升级后的前 24 小时 UI 必须明确表示健康账本仍在建立，不能声称已有完整 24 小时统计。

### 9.2 持久化与清理

OperationalEvents 只在原本就会记录通用产品活动的低频状态事件发生时同步写入，不增加定时高频采样。

匿名事件只保留最近 8 天。该账本属于 UI 观察信息，不参与迁移正确性判定。

删除或损坏 schema 2 sidecar 的后果只能是：

```text
产品体验状态与健康统计重新建立
```

不得改变：

```text
config.json
state.json
secrets.dat
reconcile.json
StrongVerified
quota / Cycle
DELETE 安全门
```

### 9.3 自动验证

native self-test 必须覆盖：

1. schema 1 sidecar 可读取；
2. 自动升级为 schema 2；
3. 匿名事件按已有活动正确投影；
4. 保存后重新加载字段完整；
5. 再次执行升级不会重复计数；
6. 账本不足 24 小时时 WindowComplete=false。

### 9.4 v0.4.20 运行观察连续性

v0.4.20 不提升 product-experience 的 schema 版本，只在 schema 2 中增加两个可选字段：

```text
LastObservationGapAt
LastObservationGapSeconds
```

它们只用于判断 About 页的健康统计是否拥有连续观察覆盖。正常退出后到下一次启动的间隔超过 15 分钟，或异常中断后最后一次 runtime heartbeat 到下一次启动的间隔超过 15 分钟时，会写入最近一次观察空窗。

15 分钟以内的短重启不记为明显空窗。该阈值只用于健康摘要展示，不参与迁移、安全暂停、StrongVerified、quota、Cycle、Reconciliation 或 DELETE。

旧 v0.4.19 sidecar 没有这两个字段时按 null 和 0 读取，行为等价于尚未发现观察空窗，因此属于向后兼容的可选字段扩展。删除 sidecar 仍只会重建产品体验和健康摘要，不影响核心 Data。

## 10. v0.5.0 可迁移 DataRoot 与备份恢复

v0.5.0 不改变 `DavBridgeConfig`、`MigrationState`、ReconciliationState 或 TransferRecord 的核心 schema。它改变的是这些持久文件“从哪里读取”的入口模型。

### 10.1 唯一持久数据根目录

默认 DataRoot 仍为：

```text
%APPDATA%\DavBridge
```

新增固定 bootstrap：

```text
%LOCALAPPDATA%\DavBridge\bootstrap.json
%LOCALAPPDATA%\DavBridge\bootstrap.json.bak
```

bootstrap 只允许保存当前 DataRoot，不保存迁移状态、文件清单、凭据或 SHA。

主、备 bootstrap 必须始终指向同一个当前 DataRoot。主文件损坏时允许从 `.bak` 恢复。主、备同时存在但都不可读时，程序必须停止自动回退，不能静默切换到默认 `%APPDATA%\DavBridge`，因为那可能让用户误读一套过期状态。

### 10.2 DataRoot 中的持久文件

当前 DataRoot 包含：

```text
config.json
config.json.bak
state.json
state.json.bak
reconcile.json
reconcile.json.bak
v2-compat.json
v2-compat.json.bak
secrets.dat
Backups\
```

`secrets.dat` 继续使用 Windows DPAPI CurrentUser，不转明文。

### 10.3 固定本机运行目录

以下内容继续固定在：

```text
%LOCALAPPDATA%\DavBridge
```

其中包括：

```text
bootstrap.json(.bak)
product-experience.json(.bak)
window.json
runtime-session.json
backup-status.json
startup-error.log
Temp\
WebView2\
WebUi\
```

这些文件中只有 `product-experience.json(.bak)` 会进入 v0.5 手动数据备份。窗口位置、runtime marker、缓存、Temp 和 WebView2 不属于需要迁移的核心数据。

### 10.4 更改 DataRoot

正常更改流程固定为：

```text
用户选择新的空目录
→ 安全暂停当前迁移
→ 检查新目录可写
→ 拒绝非空目录
→ 复制当前持久文件
→ 每个复制文件做 SHA-256 核对
→ 复制 Backups 目录并逐文件核对
→ 原子更新 bootstrap 主文件
→ 写入指向同一新 DataRoot 的 bootstrap.bak
→ 旧 DataRoot 原样保留
→ 重启 DavBridge
```

新旧 DataRoot 不能互相嵌套，也不能把持久 DataRoot 放进 DavBridge 的 LocalAppData 运行目录。

任何复制或校验失败都不得切换 bootstrap。

### 10.5 手动备份包

v0.5 手动备份 ZIP 必须包含 `manifest.json`。manifest 至少记录：

- 备份格式版本；
- DavBridge 产品版本；
- 创建时间；
- 每个条目的相对路径；
- 文件大小；
- SHA-256；
- 是否属于当前 Windows 用户绑定的数据。

备份创建完成后必须重新打开 ZIP 并逐项验证 manifest、大小和 SHA-256，验证失败不能把该包登记为最近成功备份。

默认备份目录为当前 DataRoot 下的 `Backups\`，但用户可以通过保存对话框选择其他位置。

### 10.6 恢复

恢复固定顺序：

```text
选择 DavBridge 备份 ZIP
→ 完整读取并验证 manifest
→ 安全暂停迁移
→ 自动创建恢复前当前数据安全快照
→ 解压到 Temp\RestoreStaging
→ 对 staging 文件再次做 SHA-256
→ 原子替换备份包明确包含的目标文件
→ 替换后再次做 SHA-256
→ 清理 staging
→ 重启 DavBridge
```

恢复不能删除备份包中没有包含的核心文件。

`secrets.dat` 如果在当前 Windows 用户下无法通过 DPAPI 解密，必须跳过该凭据文件并要求用户重新输入密码，不能硬恢复不可用密文。

### 10.7 从 v0.5.0 回退 v0.4.26

这是一个容易被遗忘的兼容边界。

v0.4.26 不读取 `bootstrap.json`，它始终从 `%APPDATA%\DavBridge` 读取持久 Data。

如果用户从未修改 DataRoot，直接回退 v0.4.26 仍然读取同一默认目录。

如果用户已经把 v0.5.0 DataRoot 迁移到其他位置，则**不能**直接启动 v0.4.26。正确回退顺序是：

```text
退出 v0.5.0
→ 对当前自定义 DataRoot 做完整备份
→ 把当前 config/state/reconcile/v2-compat/secrets 及对应 .bak 安全复制回 %APPDATA%\DavBridge
→ 核对文件数量与 SHA-256
→ 再启动 v0.4.26
```

旧 DataRoot 不应自动删除。回退操作必须优先保留两边副本，直到用户确认旧版读取的状态正确。

### 10.8 自动验证

Windows native-host self-test 必须覆盖：

1. bootstrap 能创建并读取；
2. bootstrap 主文件损坏时能从当前 `.bak` 恢复；
3. 主、备不会因为 DataRoot 迁移而指向不同目录；
4. 备份 ZIP 能创建并通过 manifest 与 SHA-256 校验；
5. DataRoot 能迁移到空目录并保持 state 等文件一致；
6. 恢复能把被修改的测试文件恢复为备份内容。

v0.5.0 功能代码 head `488697e2d7b490a3d681750ae2810a194477a6d4` 的 Windows self-test 已返回 `dataPortabilityV050=true`。

## 11. 将来多任务格式的迁移顺序

如果后续真正引入多任务持久化，迁移顺序固定为：

```text
检测 v0.1.7 Data
→ 校验旧文件可读取
→ 暂停任务并关闭写入
→ 创建带时间戳的完整备份目录
→ 生成新的任务清单和任务状态
→ 校验对象数、StrongVerified 数、额度、断点、安全门和凭据引用
→ 写迁移完成标志
→ 新版切换到新格式
```

任何一步失败：

```text
停止升级
→ 保留错误日志
→ 不删除旧 Data
→ 不写迁移完成标志
→ 允许继续使用 v0.1.7
```

## 12. 迁移备份

建议未来统一放在：

```text
%APPDATA%/DavBridge/UpgradeBackups/<timestamp>-v017/
```

至少包含：

- config.json
- state.json
- state.json.bak，如果存在
- secrets.dat
- migration-manifest.json，记录文件大小和 SHA-256

如果升级时 `reconcile.json` 已经存在，也应一并进入备份，但不得因为缺失该 sidecar 而阻止旧 Data 回滚。

备份不得复制 `%LOCALAPPDATA%/DavBridge/Temp` 中可再生的临时 `.part` 文件。

## 13. 等价性检查

v0.1.7 → 多任务格式迁移必须逐项核对：

- 源 Base URL 和 root；
- 目标 Base URL 和 root；
- 上传与下载额度；
- 普通预留与冲刺预留；
- 上传限速；
- 请求间隔；
- 单文件限制；
- 下次重置日期；
- 人工校准基线；
- 校准后上传累计；
- 校准后下载累计；
- MigrationEnabled；
- AutoResume；
- ExistingReplicaValidationPassed；
- CurrentGroupKey；
- 每一条 TransferRecord；
- 每条记录的 Source/Target SHA-256、状态和 VerifiedAt。

缺一项都不能标记迁移成功。

## 14. 回滚

新格式接管后的首个正式阶段仍应保留旧备份。若用户报告新版本异常，应优先提供：

1. 退出新版；
2. 恢复旧 Data；
3. 使用 main 固化的 v0.1.7 EXE；
4. 继续原任务。

v0.3.0 若只需回到旧版本，可以先退出新版并保留或移走 `reconcile.json`，旧版不会依赖该 sidecar。

在新格式经过足够长时间真实验证前，不提供自动删除旧备份功能。
