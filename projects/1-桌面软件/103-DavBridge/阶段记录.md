## v0.1.5 当前设计基线

- Windows x64，C# / .NET 8 / WinForms；
- framework-dependent 单文件发布；
- InfiniCLOUD 正式产品代码只读，坚果云为唯一目标写端；
- `.zip` 与 `.prop` 成组处理；
- PUT 成功后必须针对准确资源做 `PROPFIND Depth:0` 独立确认，并从坚果云重新 GET 与源端做 SHA-256 强校验；
- GoodSync 或其他客户端已经存在于目标端的文件允许经过 GET 与 SHA-256 后安全接管，完全一致时不重复 PUT；
- 既有目标与源端不同且无法证明是 DavBridge 自己写入的旧版本时必须进入冲突，不自动覆盖；
- 普通周期预留 50 MB，重置前 24 h 可进入冲刺；
- 上传 1 GB 与下载 3 GB 都进入安全额度模型，人工校准值与 DavBridge 后续保守计量叠加；
- 已有目标文件的接管校验计入下载账本，不消耗上传账本；
- 登录后可以自动启动和托盘静默运行，暂停状态持久化；
- 设置页已保存密码按真实长度显示为 `*`，眼睛按钮可临时显示明文；
- 坚果云目录列举达到 750 项时只表述为 `750+` 或“本次列举达到上限”，不把它当作目标总数；
- 完整源码统一以 `代码/DavBridge.sln` 恢复，开发期源码事实源为远端 `p103-exp`；
- v0.1.5 提供首组验证安全门。长期迁移在首个完整 Group 两成员都达到 `StrongVerified` 前保持锁定；
- 首组通过后，长期迁移启用前仍重新执行就绪扫描并要求用户明确确认；
- 最终 `Content Complete` 与 `Exact Mirror` 分开判定。

### 首个真实 Group 强校验

v0.1.5 在用户 Windows 11 上完成了首个真实小型 Zotero Group 验证。为避免把真实 Zotero storage key 写入公开仓库，这里不记录组名。

```text
组成员：1 个 .zip + 1 个 .prop
组总量：132 B
验证前目标已有成员：0 / 2
实际 PUT：132 B
目标强校验 GET：132 B
结果：两个成员均 StrongVerified
异常：0
```

这次实测真实覆盖了以下链路：

```text
InfiniCLOUD GET + SHA-256
→ 坚果云 PUT
→ 对准确目标 URL 执行 PROPFIND Depth:0
→ 确认目标存在并核对长度
→ 坚果云重新 GET + SHA-256
→ 与源端 SHA-256 比较
→ 再检查 InfiniCLOUD 源端元数据未在传输期间变化
→ StrongVerified
```

因此，真实坚果云准确资源 `Depth:0`、真实 PUT、重新 GET 与 SHA-256 强校验链已经验证通过。此次首组验证后软件保持 Paused，没有顺势启动第二组或整库迁移。
