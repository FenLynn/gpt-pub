## v0.1.2 当前设计基线

- Windows x64，C# / .NET 8 / WinForms；
- framework-dependent 单文件发布，保持 Runtime 轻量；
- InfiniCLOUD 正式产品代码只读，坚果云为唯一目标写端；
- InfiniCLOUD Basic Auth 同时支持凭据处理器与预认证头，401 错误携带实际请求 URL 和认证 challenge 信息；
- `.zip` 与 `.prop` 成组处理；
- PUT 成功后必须针对准确资源确认，并从坚果云重新 GET 与源端做 SHA-256 强校验；
- GoodSync 或其他客户端已经存在于目标端的文件允许经过 GET 与 SHA-256 后安全接管，完全一致时不重复 PUT；
- 既有目标与源端不同且无法证明是 DavBridge 自己写入的旧版本时必须进入冲突，不自动覆盖；
- 普通周期预留 50 MB，重置前 24 h 可进入冲刺；
- 上传 1 GB 与下载 3 GB 都进入安全额度模型，人工校准值与 DavBridge 后续保守计量叠加；
- 已有目标文件的接管校验计入下载账本，不消耗上传账本；
- 组级上传预判只计算目标端缺失成员，已有成员先校验；每个实际 PUT 前再次执行上传额度安全检查；
- 登录后可以自动启动和托盘静默运行；
- 首次仅保存连接信息不会自动开始迁移，长期迁移必须经过用户显式启用；
- 首次目标目录允许存在既有 GoodSync 文件，启用前会明确说明一致文件接管和不一致文件冲突策略；
- 暂停状态持久化，重新登录 Windows 不得擅自恢复用户已暂停的迁移；
- 最终 `Content Complete` 与 `Exact Mirror` 分开判定。

## 自动验证证据

v0.1.2 当前自动候选已覆盖并验证：

- P103 PR 范围门禁；
- 13 项以上核心 smoke，包括正常强校验、PUT 假成功、源端变化、既有目标一致接管、既有目标不一致冲突、下载额度保护、崩溃恢复、部分 Group 恢复、单文件上限和大清单；
- 6000 个 Zotero Attachment Group / 12000 个 WebDAV 对象的大清单分组；
- Windows x64 .NET 8 restore 与 publish；
- framework-dependent 单 EXE Runtime 边界检查；
- 隔离 `%APPDATA%` / `%LOCALAPPDATA%` 的 Windows 自检；
- 候选 EXE SHA-256 生成；
- GitHub Actions Windows Artifact 生成。

这些证据证明当前实现和本地故障模型可以工作，不证明真实云服务已经符合模型。
