# DavBridge 用户手册

本文描述 DavBridge v0.4.x 的长期工作原则和当前界面语义。运行行为以源码、状态文件和准确 CI 为准，最终视觉事实以用户真实 Windows 为准。

## 1. 使用概览

DavBridge 用于长期维护 Zotero 附件从 InfiniCLOUD 到坚果云的单向强校验镜像。

日常情况下不需要人工干预。真实额度周期开始后，程序先对账，再处理历史修改，最后使用剩余额度继续普通迁移。只有回收站成熟候选、冲突、认证异常等无法安全自动决定的事项才要求人工处理。

## 2. 镜像原则

InfiniCLOUD 是唯一权威源，并且始终只读。

坚果云保存已经验证或正在迁移的镜像子集。新增源对象进入普通任务池，不插队。已验证对象如果源端发生真正内容变化，则优先修复。

DavBridge 不做双向同步，也不会把坚果云变化反写到 InfiniCLOUD。

## 3. StrongVerified

`StrongVerified` 表示文件在核准时刻已经完成源端 SHA256 与目标端重新下载 SHA256 的一致性确认。

该 SHA256 是后续维护的历史核准基线。普通 metadata 扫描不会随意覆盖它，只有重新完成强校验后才建立新基线。

## 4. Cycle 与额度

Cycle ID 使用启动当前坚果云额度周期的真实重置日期，格式固定为 `yyMMdd`。例如 2026-09-07 对应 `260907`。

程序不会仅按自然月或午夜盲目重置账本。到达配置重置日以后，会在 09:00 以后通过真实探测确认新的服务周期已经开始。只有确认成功后才进入新 Cycle，并优先执行源端对账。

## 5. 源端对账

每个已确认新 Cycle 开始后，DavBridge 自动读取 InfiniCLOUD 当前清单，并与历史 StrongVerified 账本比较。

源 metadata 未变化时不读取文件内容。metadata 发生变化时，只重新读取 InfiniCLOUD 并计算 SHA256：

- SHA256 没变，只更新源 metadata；
- SHA256 真改变，文件组进入 `SourceChanged`；
- `SourceChanged` 优先于普通任务刷新目标；
- 新目标重新 StrongVerified 后才建立新的核准基线。

## 6. 转移优先级

任务只有两个逻辑层级。

第一层是优先修复，即源端内容真正改变的历史 StrongVerified 组。

第二层是普通任务，包括既有 backlog 和本周期新增对象。

新增文件与历史未迁移对象同级，不额外插队。只要优先修复仍存在，普通任务就等待。

## 7. 回收站

源端删除采用跨周期逻辑回收站。

第一次发现一个历史 StrongVerified 组在 InfiniCLOUD 完全消失，只记录首次缺失 Cycle，坚果云内容完全不动。

至少跨到后续已确认额度周期仍然缺失，才进入待审查。待审查对象永远不会自动 DELETE，用户必须人工选择删除或本周期继续保留。

继续保留的对象如果下个周期仍缺失，会再次进入审查，因此回收站可以同时存在本月、上月以及更早周期留下的对象。

## 8. 删除安全

人工点击删除以后仍不会直接无条件 DELETE。

DavBridge 会再次：

1. 检查 InfiniCLOUD 准确成员路径；
2. 确认整个 Zotero `.zip + .prop` 组仍然缺失；
3. 检查坚果云目标仍然对应历史 StrongVerified 身份；
4. metadata 无法安全证明身份时，仅在下载安全额度允许时重新读取目标并比对历史 SHA256；
5. DELETE 后再次查询准确目标路径；
6. 网络或超时导致结果未知时先 reconciliation，绝不盲目重复 DELETE。

源端如果只恢复 `.zip` 或只恢复 `.prop`，属于组结构异常，禁止自动删除。

## 9. v0.4 主界面

当前一级入口为：

```text
总览 | 转移 | 回收站 | 文档
```

v0.4.3 采用固定左侧栏。设置和关于位于左侧栏下部，最底部显示当前运行状态与 Cycle。

### 总览

总览只回答最重要的运行问题：

- 从哪里迁到哪里；
- 当前处于哪个阶段；
- StrongVerified 覆盖率是多少；
- 当前正在处理什么；
- 本 Cycle 上传和下载额度用了多少；
- 现在需要暂停、继续还是人工审查。

StrongVerified、Cycle、阶段和端点角色等解释通过悬浮提示补充，避免长期占用主界面空间。

### 转移

查看当前迁移活动和任务细节。普通用户不需要在这里手工干预调度。

### 回收站

只处理跨周期成熟的人工审查对象。默认不自动选择对象，不存在后台自动删除。

### 文档

在程序内解释长期安全语义和常见状态。

### 设置与关于

设置仍由 C# 原生窗口承载敏感配置和 Windows 级设置。关于页只显示产品信息，不扩大 Web UI 权限。

## 10. 打开、托盘与主操作

显式打开 DavBridge 的行为统一为显示主窗口并回到总览：

- Windows 登录自启动使用 `--background`，可直接进入托盘；
- 用户手工双击 EXE 时显示主窗口总览；
- 程序已运行时再次双击 EXE，应激活已有窗口并切回总览；
- 托盘双击或托盘菜单“打开 DavBridge”也应恢复主窗口并显示总览。

主操作根据真实状态动态变化。运行中可暂停，暂停后可继续；需要人工时进入对应人工入口；额度或网络等待时应显示真实等待原因。

## 11. Web UI 安全边界

Vue 界面没有权限直接读取凭据或执行 WebDAV 写入。

当前前端命令仅通过 C# bridge 白名单进入既有逻辑。密码、DPAPI、原始 state/reconcile 文件和 WebDAV 客户端不进入 JavaScript。

DELETE 的前端确认也不是最终授权，仍会进入 C# 原生确认和既有删除安全链。

## 12. 界面设计原则

当前 UI 坚持：

- 左侧导航稳定；
- 总览结构稳定；
- 状态、数字和操作一眼可辨；
- 长解释进入 tooltip 或文档；
- 不为了压缩信息破坏页面结构；
- 不为了现代 UI 重写已经验证的 Core；
- 自动截图和浏览器预览只做前置检查，最终视觉事实以用户真实 Windows 为准。

v0.3.x 的 WinForms 布局试验保留在 Git 历史和源码中用于追溯，但不再是当前运行 UI 的设计准则。

## 13. 常见问题

### 为什么校核时坚果云流量可能几乎不变？

很多校核只执行 PROPFIND 或 metadata 探测，只有需要内容级身份确认时才会 GET 文件。

### 为什么新文件不优先？

新增文件与已有 backlog 角色相同。系统先保证已有镜像仍然正确，再扩大镜像覆盖范围。

### 为什么删除要等一个周期？

跨周期观察用于过滤临时不可见、服务故障和短期误判。即使跨周期确认，最终 DELETE 仍必须人工批准。

### 为什么坚果云不需要反复全库下载？

StrongVerified 已经保存历史双端 SHA256 核准基线。正常长期维护优先检查当前源端变化，并以目标 metadata 和历史核准证据维持可信链。只有目标身份存在异常时才按需重新读取目标内容。

### 为什么 v0.4 仍能看到一些 WinForms 历史源码？

它们用于历史回滚和追溯。当前业务 UI 已经由 Vue/WebView2 承担，WinForms 只保留 Windows 原生宿主职责。
