# DavBridge v0.4 开发约束补充

> 约束层级：C｜项目级补充  
> 适用范围：P103 DavBridge v0.4 及其后续 UI 迁移阶段  
> 本文件只修订原 `开发约束.md` 中“技术栈固定为 WinForms”的 UI 实现部分。原文件所有数据安全、WebDAV、StrongVerified、Cycle、额度、回收站和 DELETE 约束继续完整生效。

## C-01A｜v0.4 UI 技术栈

用户已明确批准 v0.4 将显示层从 WinForms 控件 UI 迁移为：

```text
Vue 3 + TypeScript + Vite
→ Microsoft WebView2
→ C# / .NET 8 极薄 Windows 宿主
→ 既有 DavBridge.Core 与 C# 安全链
```

原 `C-01` 中“WinForms”只保留为 Windows 原生宿主能力，不再作为主业务页面 UI 框架。

## C-01B｜只换 UI，不动逻辑

本次迁移是 UI replacement，不是产品逻辑重构。

禁止因为前端迁移而修改或重新实现：

- `DavBridge.Core` 迁移与校验逻辑；
- WebDAV 客户端；
- StrongVerified；
- SourceChanged；
- WriteUnknown；
- 412 协调；
- Quota 与 Cycle；
- 每周期源端对账；
- 回收站状态机；
- `ReconciliationRemovalV030` 删除安全链；
- DPAPI 与 Data 文件格式。

如果 UI 需求与既有安全逻辑冲突，必须调整 UI，不得为了 UI 方便降低核心安全门。

## C-01C｜Web UI 最小权限

Web UI 无权直接访问凭据、私人 Data、WebDAV 写操作或删除操作实现。

所有动作必须通过 C# 宿主固定白名单命令进入既有逻辑。新增 bridge command 必须先说明为什么现有命令不足，并审查其是否扩大前端权限。

危险操作必须保留原生最终确认。前端确认不能替代 C# 安全确认。

## C-01D｜验收

每次 UI 候选至少满足：

1. 原 Core Smoke 全通过；
2. Git diff 不出现未经用户批准的 Core / Reconciliation / WebDAV / Data 逻辑修改；
3. Vue typecheck 与 production build 通过；
4. Windows 单 EXE publish 通过；
5. Web UI 至少在默认 900×620 尺寸完成视觉检查；
6. 最终视觉事实以用户真实 Windows 为准。

未经用户真实机器验收，不得把 v0.4 提升到 `p103-stable` 或 `main`。

## v0.4 最终收束约束

1. v0.4.24 起，生产业务 UI 唯一入口为 Vue + WebView2。旧 `UiShellV030`、`UiShellV032`、旧 Dashboard 及其他历史 WinForms 业务 UI 文件只允许作为历史实现和回滚参考存在，不得重新挂回 `Program.cs` 或 `MainForm.cs` 的生产业务路径。
2. `overview.css` 不得重新引入已经废弃的 `.about-ops` 和 `.about-health-strip`。About 当前结构由活动 Vue DOM 与当前 CSS 直接维护，不再叠加历史版本 selector。
3. 每个 v0.4 稳定候选必须通过生产 UI 所有权检查、Vue typecheck/build、跨页面视觉预览、Core Smoke、Windows single EXE、Runtime 私人数据边界和 native-host self-test。
4. Core Smoke 的持久化暂停与重启收敛测试不得删除。它是安全暂停、状态落盘、重复恢复和幂等 PUT 的长期回归门。
5. 自动截图不能替代真实 Windows。stable/main 提升前仍要求用户真实 WebView2、DPI、睡眠恢复、网络恢复与长期后台运行终验。
6. v0.4 不再新增普通功能。若出现真正的新产品主题，进入 v0.5 评估，不在 v0.4 上继续叠加页面和状态。
