连接诊断与就绪扫描的源端数量相差 1，是因为连接诊断统计目录响应中的所有可见条目，而就绪扫描只把普通文件纳入迁移对象。当前真实库没有发现 500 MB 阻塞，也没有发现 zip/prop 配对异常。

当前 750 只能表述为“本次响应达到 750 项”或“至少 750 项”，不能表述为目标端总文件数。单文件直接 URL 校验与迁移核心仍不依赖完整目录枚举。

## v0.1.5 首组验证行为

```text
长期迁移保持 Paused
→ 要求已完成流量校准
→ 从源端完整 zip + prop Group 中选择较小且尚未验证的一组
→ 对两个目标准确路径分别做 metadata 检查
→ 弹窗展示组成员、大小、目标已有成员数量、最大可能上传量、预计校验下载量
→ 用户明确确认
→ 仅向 MigrationEngine 暴露这一组
→ 已有目标先 GET + SHA-256，比对一致则直接接管
→ 缺失目标才 PUT，再做准确资源确认和目标 GET + SHA-256
→ 两成员均 StrongVerified 才判定首组通过
→ 强制恢复 Paused，绝不继续第二组
```

“开始 / 继续”在首组通过前有独立代码门禁，不得绕过首组测试直接开始整库迁移。

## 当前自动验证基线

P103 CI 当前要求：

```text
范围门禁
→ DavBridge.sln 三工程成员完整性检查
→ .NET 8 Core / Smoke restore
→ 核心 smoke
→ Windows x64 restore / publish
→ framework-dependent 单 EXE Runtime 检查
→ 隔离 APPDATA / LOCALAPPDATA 自检
→ SHA-256
→ Windows 候选 Artifact
```

当前 smoke 至少覆盖：

1. zip/prop 逻辑分组；
2. 50 MB 普通预留与 24 h 冲刺；
3. `state.json` 损坏后的 `.bak` 回退；
4. 正常端到端强校验；
5. PUT 返回成功但目标实际不存在；
6. 传输期间源端变化；
7. GoodSync 既有目标内容一致时安全接管；
8. 既有目标内容不一致时冲突且不覆盖；
9. 既有目标校验受下载额度保护；
10. PUT 后崩溃恢复且不重复上传；
11. zip 已完成时只处理剩余 prop；
12. 超过单文件上限安全阻塞；
13. 6000 个 Zotero 附件 / 12000 个对象的大清单分组。
