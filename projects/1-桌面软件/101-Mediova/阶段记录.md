## 当前架构结论

### 本地媒体结果闭环

- 软件不修改或删除源媒体。
- 每个输入必须形成明确结果。
- 只有真实存在并通过最低完整性检查的输出才能记为成功。
- 硬件编码失败时安全回退 CPU，不能让整个批次静默失效。
- 同名输出使用原子占用或等效机制，防止并发任务写入同一目标。

### 轻量透明 Runtime / 独立 Data

完整验证 Runtime：

```text
Mediova/
├── Mediova.exe
├── Components/FFmpeg/bin/
├── runtime-manifest.json
├── THIRD_PARTY_NOTICES.md
└── README.txt
```

默认用户轻量包：

```text
Mediova.exe
README.txt
runtime-manifest.json
THIRD_PARTY_NOTICES.md
```

- `%APPDATA%\Mediova` 保存配置、历史、会话和备份。
- `%LOCALAPPDATA%\Mediova` 保存缓存、临时文件、缩略图、本机状态、日志和崩溃信息。
- Runtime 可以公开、复制、覆盖、校验和删除后重建；Release 不包含私人 Data。
- 轻量更新包不包含 `Components/`，覆盖已有安装时必须保留原 `Components\FFmpeg\bin`。

### v4.2.x 任务状态模型

- 准备中任务接受当前媒体模式的全局默认和右侧个体编辑。
- 底部参数按字段立即作用于同模式准备中任务，并作为新任务模板。
- 右侧个体编辑使用草稿和显式应用；多选只提交实际修改字段。
- 任务进入队列时冻结转换参数、输出母目录、输出路径、冲突策略和必要运行快照。
- 活动队列运行期间可以继续导入同类型文件，并在独立预检后动态追加。
- 同一活动队列只运行一种媒体；另一模式仍可导入和编辑准备中任务。
- 队列中、转换中和暂停任务默认锁定，可通过独立搁置会话单独修改或安全移除。

### 输出目录与双模式参数

- 视频与图片分别保存输出母目录、最近目录和默认参数。
- 视频底部使用分辨率、格式、质量、体积模式和旋转。
- 图片底部使用尺寸、格式、质量、大小限制和旋转，并采用独立宽度配置。
- 切换模式时，输出母目录、参数、进度统计、按钮文案和命令作用域完整同步切换。
- 另一个媒体队列运行时，当前页不得显示或控制对方队列。
- 拖入顶层文件夹 `A` 时，输出按 `输出母目录/A/...` 复刻完整顶层和多级目录树。
- 输出文件完成后恢复文件时间，并恢复对应目录树的创建、访问和修改时间。

### 进度、压缩与状态显示

- “压缩后”和“进度”列保持轨道、填充、边框和文字可见。
- 条形采用 24 px 优选高度并在列表行内垂直居中。
- 压缩条原始体积侧使用可辨识浅灰底。
- 进度文字按每个字符中心所在背景配色：蓝色填充区白字，浅色轨道区深色字。
- 部分填充时同一标签可以同时出现白字和深色字，不依赖不稳定的裁剪重绘。
- 视频列表显示可排序时长列；图片显示 `—`；旧 10 列宽设置自动迁移。
- 状态灯使用 DPI 感知字体矢量圆点，不再拉伸低分辨率图标。

### 控件与交互边界

- 底部不得恢复旧“应用到选中”；右侧个体参数面板保留正常按钮。
- “全部恢复默认”使用紧凑自绘图标并保留边框间隙。
- 右键菜单只允许单一事件源，关闭后必须销毁菜单句柄。
- 搁置任务切换不得无条件重建全部下拉内容。
- 主窗口首次显示前必须完成布局，不得依赖用户缩放修复初始错位。

设计原因和历史取舍以 `软件开发总结.md` 为准；长期不可破坏规则以 `开发约束.md` 为准。

## UI 验证结论

长期 UI 准入采用五层证据：

1. 规则测试固定视觉语义；
2. 几何测试阻止越界、重叠和错误高度；
3. 源码契约固定媒体作用域、列结构和文字配色路径；
4. 真实 EXE 截图验证最终窗口；
5. 人工复核判断轨道、填充、字色、图标和整体布局是否符合产品目标。

CI 绿色不能单独替代视觉判断，但人工截图也不能替代属性和运行时门禁。v4.2.2 正是由人工截图发现并修复“自动测试全绿但蓝底仍为黑字”的问题，因此该原则必须长期保留。

## 已知限制与剩余风险

- 125%、150% 和 175% DPI、多显示器、不同 Windows 主题及动态悬停手感仍需真实桌面或用户持续确认。
- 拖放、托盘、显卡驱动、PotPlayer、HEIC、文件时间和特殊媒体继续标记为真实环境待观察。
- 用户默认使用不含 FFmpeg 的 `Mediova-v4.2.2-Light.zip`；已有安装保留 `Components/FFmpeg/bin/`。
- 正式资产未签名；不得在文档或界面中暗示已完成代码签名。
- 下一版本不得仅因版本号递增而启动，必须先登记可复现问题、目标和完成标准。

当前工作以 `工作记录.md` 为准；用户可见变化以 `Mediova_v4.2.2_版本说明.md` 为准。
