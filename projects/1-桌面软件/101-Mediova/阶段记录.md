## 当前架构结论

### 本地媒体结果闭环

- 软件不修改或删除源媒体。
- 每个输入必须形成明确结果。
- 只有真实存在并通过最低完整性检查的输出才能记为成功。
- 硬件编码失败时安全回退 CPU，不能让整个批次静默失效。
- 同名输出使用原子占用或等效机制，防止并发任务写入同一目标。

### 轻量透明 Runtime / 独立 Data

```text
Mediova/
├── Mediova.exe
├── Components/FFmpeg/bin/
├── runtime-manifest.json
├── THIRD_PARTY_NOTICES.md
└── README.txt
```

- `Mediova.exe` 是唯一直接主程序。
- FFmpeg/FFprobe 和相关 DLL 属于 Runtime，不作为 Data 存入 AppData。
- `%APPDATA%\Mediova` 保存配置、历史、会话和备份。
- `%LOCALAPPDATA%\Mediova` 保存缓存、临时文件、缩略图、本机状态、日志和崩溃信息。
- Runtime 可以公开、复制、覆盖、校验和删除后重建；Release 不包含私人 Data。
- 旧 AppData 组件只在 Runtime 缺失时保守复制，不覆盖新文件、不删除旧目录。

### v4.2.0 任务状态模型

- 准备中任务接受当前媒体模式的全局默认和右侧个体编辑。
- 底部参数按字段立即作用于同模式准备中任务，并作为新任务模板。
- 右侧个体编辑使用草稿和显式应用；多选只提交实际修改字段。
- 任务进入队列时冻结转换参数、输出母目录、输出路径、冲突策略和必要运行快照。
- 活动队列运行期间可以继续导入同类型文件，并在独立预检后动态追加。
- 同一活动队列只运行一种媒体；另一模式仍可导入和编辑准备中任务。
- 队列中、转换中和暂停任务默认锁定，可通过独立搁置会话单独修改或安全移除。
- 转换任务搁置时安全终止 FFmpeg、清理临时输出并保留并发名额；应用或取消后从 0% 重启。

### 输出目录与双模式参数

- 视频与图片分别保存输出母目录、最近目录和默认参数。
- 文件夹导入按导入根目录计算相对路径，并在输出母目录下复刻原目录树。
- 视频底部使用分辨率、格式、质量、体积模式和旋转。
- 图片底部使用尺寸、格式、质量、大小限制和旋转。
- 切换模式时，输出母目录、底部、右侧和默认值完整同步切换。

### 进度与状态显示

- “压缩后”和“进度”列轨道在所有任务状态和选中组合中保持常驻。
- 选中背景绘制在轨道下方，不遮挡条形或文字。
- 动态追加队列后，总百分比按真实分母重算，并显示“已完成 x/y”。
- 状态灯使用 14 px 基线、高对比实色和清晰边线。

设计原因和历史取舍以 `软件开发总结.md` 为准；长期不可破坏规则以 `开发约束.md` 为准。

## UI 验证结论

v4.2.0 在 v4.1.1 的真实窗口尺寸门禁基础上扩展为四种界面场景。CI 不只检查 PNG 是否存在，还固定启动模式、请求窗口尺寸、读取实际窗口边界，并在偏差过大时失败。视频宽屏、视频紧凑、图片模式和搁置模式均生成独立截图，避免只验证一个静态布局。

长期 UI 准入仍采用四层证据：规则测试固定视觉语义，几何测试阻止越界和重叠，真实 EXE 截图验证最终绘制，人工复核判断是否符合产品目标。CI 绿色不能单独替代视觉判断。

## 已知限制与剩余风险

- 125%、150% 和 175% DPI、多显示器、不同 Windows 主题及动态悬停手感仍需真实桌面或用户确认。
- 拖放、托盘、显卡驱动、PotPlayer、文件时间和特殊媒体继续标记为真实环境待观察。
- 首次部署必须使用完整 `Mediova-v4.2.0-Runtime.zip`，不能只复制 `Mediova.exe`。
- 正式资产未签名；不得在文档或界面中暗示已完成代码签名。
- 下一版本不得仅因版本号递增而启动，必须先登记可复现问题、目标和完成标准。

上述风险不得在后续记录中改写为“全部实机验证完成”。当前工作以 `工作记录.md` 为准；用户可见变化以 `Mediova_v4.2.0_版本说明.md` 为准。
