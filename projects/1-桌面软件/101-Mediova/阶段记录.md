## 当前架构结论

### 本地媒体结果闭环

- 软件不修改或删除源媒体。
- 每个输入必须形成明确结果。
- 只有真实存在并通过最低完整性检查的输出才能记为成功。
- 硬件编码失败时安全回退 CPU，不能让整个批次静默失效。

### 轻量透明 Runtime / 独立 Data

```text
Mediova/
├── Mediova.exe
├── Components/FFmpeg/bin/
├── runtime-manifest.json
├── THIRD_PARTY_NOTICES.md
└── README.txt
```

- `Mediova.exe` 是唯一直接主程序。
- FFmpeg/FFprobe 和相关 DLL 属于 Runtime，不作为 Data 存入 AppData。
- `%APPDATA%\Mediova` 保存配置、历史、会话和备份。
- `%LOCALAPPDATA%\Mediova` 保存缓存、临时文件、缩略图、本机状态、日志和崩溃信息。
- Runtime 可以公开、复制、覆盖、校验和删除后重建；Release 不包含私人 Data。
- 旧 AppData 组件只在 Runtime 缺失时保守复制，不覆盖新文件、不删除旧目录。

### v4.1.1 UI 基线

- 普通工具栏和次要按钮默认不填充卡片底色，仅保留极淡边线；悬停、按下、当前模式和禁用状态分层。
- 图标使用 18 px 基线；顶部按钮增加上下留白和横向间距。
- 状态灯为 11 px；右侧折叠按钮保持紧凑。
- 输出区域统一为“输出母目录”，支持编辑、最近目录、浏览和打开当前目录；相关下拉框采用扁平主题。
- 总进度条使用淡轨道且无明显外框；行内进度与体积条接近完整单元格宽度，文字在条形中央。
- 体积条按输入与输出体积总和绘制真实比例；±10% 和“变大但最终小于 15 MB”为黄色，明显压缩为分级绿色，明显增长为分级红色。
- 底部参数基线宽度为输出 84、格式 78、质量 72、体积 126、旋转 98 px，并随 DPI 缩放。

设计原因和历史取舍以 `软件开发总结.md` 为准；长期不可破坏规则以 `开发约束.md` 为准。

## UI 验证演进证据

首轮截图运行虽生成 1650×930 画布，但实际窗口宽度约 1034 px，右侧和下方出现黑色空区，宽布局与紧凑布局实质相同。人工复核阻止了误合并。随后 CI 加入 `GetWindowRect` 实际尺寸门禁，目标尺寸偏差超过 8 px 即失败；正式主线 CI 已生成无黑边、布局不同的两张真实尺寸截图。

这形成长期 UI 准入标准：规则测试固定视觉语义，几何测试阻止越界和重叠，真实 EXE 截图验证最终绘制，人工复核判断是否符合视觉目标。CI 绿色不得单独作为“视觉完成”证据。

## 已知限制与剩余风险

- 125%、150% 和 175% DPI、多显示器、不同 Windows 主题及动态悬停手感仍需真实桌面或用户确认。
- 拖放、托盘、显卡驱动、PotPlayer、文件时间和特殊媒体继续标记为真实环境待观察。
- 首次部署必须使用完整 `Mediova-v4.1.1-Runtime.zip`，不能只复制 `Mediova.exe`。
- 正式资产未签名；不得在文档或界面中暗示已完成代码签名。

上述风险不得在后续记录中改写为“全部实机验证完成”。当前工作以 `工作记录.md` 为准；用户可见变化以 `Mediova_v4.1.1_版本说明.md` 为准。
