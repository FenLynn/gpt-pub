## 正式能力结论

### 任务与结果闭环

- 软件不修改或删除源媒体。
- 每个输入必须形成明确结果，只有真实存在并通过最低完整性检查的输出才能记为成功。
- 硬件编码失败时安全回退 CPU；同名输出采用原子占用或等效机制。
- 视频和图片分别维护输出母目录、默认参数、进度统计和按钮作用域。
- 入队时冻结参数、输出母目录、输出路径、冲突策略和必要运行快照。
- 活动队列允许动态追加同类型任务；另一媒体模式可继续准备，但不能混入当前活动队列。
- 锁定任务只能通过独立搁置会话修改或安全移除。

### v4.2.3 底部按钮修复

- 底部进度、状态文字和开始/暂停/停止按钮由统一 footer 几何模型管理。
- 三个按钮在视频、图片、宽屏、紧凑、搁置和禁用状态下同高、同基线、固定间距并右对齐。
- 主按钮自绘前清除完整画布，消除禁用态外框残影。
- 正式截图人工复核确认该问题已经闭合。

### v4.3.0 预览与裁剪

- 支持自由、16:9、9:16、1:1、4:3 裁剪比例。
- 支持最大居中适配、拖框比例锁定、逐帧/逐秒键盘微调和应用到已选任务。
- 裁剪坐标通过纯函数约束为合法偶数边界，并继续在一次 FFmpeg 处理中完成转正、裁剪、缩放和编码。

### v4.4.0 图片扩展

- 图片复用同一裁剪对话框和比例规则。
- 高清预览按任务真实媒体类型生成。
- HEIC、HEIF、AVIF 转换前执行有界 FFmpeg 解码预检。
- 当前 FFmpeg 缺少解码能力时明确显示格式和处理建议，且不修改源文件。
- JPG/PNG、EXIF、拍摄时间、文件时间和目录时间保留链继续有效。

### v4.5.0 会话恢复

- 会话文件使用 schema 2 包络，记录版本、时间、保存原因和正常退出标记。
- 兼容旧任务数组格式。
- 保存采用同目录临时文件、同步落盘和主文件/`.bak` 轮换；主快照损坏时回退备份。
- 运行中、队列中、暂停、搁置和停止任务恢复为准备中，并从文件级 0% 重新处理。
- 冻结参数、输出母目录和冲突策略保留；临时输出路径、进度、引擎、错误和运行时间清除。
- 完成、跳过和失败结果保持；源文件缺失时明确失败。
- 不宣称帧级断点续转。

### Runtime 与 Data

完整验证 Runtime：

```text
Mediova/
├── Mediova.exe
├── Components/FFmpeg/bin/
├── runtime-manifest.json
├── THIRD_PARTY_NOTICES.md
└── README.txt
```

默认用户轻量包：

```text
Mediova.exe
README.txt
runtime-manifest.json
THIRD_PARTY_NOTICES.md
```

- `%APPDATA%\Mediova` 保存配置、历史、会话和备份。
- `%LOCALAPPDATA%\Mediova` 保存缓存、临时文件、缩略图、本机状态、日志和崩溃信息。
- Runtime、Artifact、Release 和更新包不得包含私人 Data。
- 轻量更新包不包含 `Components/`，覆盖已有安装时保留原 `Components\FFmpeg\bin`。

长期 UI 准入采用五层证据：视觉语义规则、几何属性、源码/绘制路径契约、最终 EXE 截图和人工复核。任何一层都不能替代其他层。

## 已知限制与剩余风险

- 125%、150% 和 175% DPI、多显示器、不同 Windows 主题及动态悬停手感仍需真实桌面持续确认。
- 拖放、托盘、显卡驱动、PotPlayer、文件时间和特殊媒体继续标记为真实环境观察项。
- HEIC、HEIF、AVIF 是否可读取取决于用户当前 FFmpeg 构建。
- 会话恢复是文件级重新排队，不是帧级或编码器内部断点续转。
- 正式资产未签名，不得暗示已经完成代码签名。
- 下一版本不得仅因版本号递增而启动，必须先登记可复现问题、目标和完成标准。

当前工作以 `工作记录.md` 为准；用户可见变化以 `Mediova_v4.5.0_版本说明.md` 为准。
