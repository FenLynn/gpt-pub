## 当前仍成立的架构结论

### 本地媒体结果闭环

- 软件不修改或删除源媒体。
- 每个输入必须形成明确结果。
- 只有真实存在并通过最低完整性检查的输出才能记为成功。
- 硬件编码失败时安全回退 CPU，不能让整个批次静默失效。

### 轻量透明 Runtime / 独立 Data

```text
Mediova/
├── Mediova.exe
├── Components/FFmpeg/bin/
├── runtime-manifest.json
├── THIRD_PARTY_NOTICES.md
└── README.txt
```

- `Mediova.exe` 仍是唯一直接主程序。
- FFmpeg/FFprobe 和相关 DLL 属于 Runtime，不再作为 Data 存入 AppData。
- `%APPDATA%\Mediova` 保存配置、历史、会话和备份。
- `%LOCALAPPDATA%\Mediova` 保存缓存、临时文件、缩略图、本机状态、日志和崩溃信息。
- Runtime 可以公开、复制、覆盖、校验和删除后重建；Release 不包含私人 Data。
- 旧 AppData 组件只在 Runtime 缺失时保守复制，不覆盖新文件、不删除旧目录。

### v4.1.0 界面规则

- 主界面统一底色、轻边线和控件五态，顶部工具栏保持单行。
- 输出区域统一为“输出母目录”，支持编辑、最近目录、浏览和打开当前目录。
- 进度条与体积条采用单层绘制，文字在完整条形区域内居中。
- 体积条按输入与输出体积总和绘制真实比例；±10% 和“变大但最终小于 15 MB”为黄色，明显压缩为分级绿色，明显增长为分级红色。

设计原因和历史取舍以 `软件开发总结.md` 为准；长期不可破坏规则以 `开发约束.md` 为准。

## 已知限制与剩余风险

- GitHub Windows Runner、自动几何测试和原生自检不能完全替代 Windows 10/11 真实桌面视觉体验。
- 拖放、托盘、多显示器、特殊 DPI、显卡驱动、PotPlayer、文件时间和特殊媒体继续标记为真实环境“待验证”。
- v4.1.0 首次部署必须使用完整 Runtime ZIP，不能只复制 `Mediova.exe`。
- 正式资产当前未签名；Release 必须明确记录签名状态。

上述风险已经明确登记，不得在后续文档中改写为“全部实机验证完成”。
