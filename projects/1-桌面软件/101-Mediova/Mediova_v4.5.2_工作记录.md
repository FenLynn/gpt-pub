## 第三轮：导入、输出结构与通知

范围：

- 直接拖入文件的最近公共父目录与相对路径保留；
- 不同磁盘和同名父目录冲突处理；
- 视频 / 图片统一算法；
- 文件夹导入视频、图片、重复、不支持和不可读统计；
- 右下角轻量渐显、上浮、约 5 秒消失通知。

### 已确认根因

- 文件夹导入已通过 `ImportTreeRoot` 保留所选顶层目录；
- 直接拖入文件此前集中进入 `Root == ""` 的分组；
- `ResolveOutputPath` 在 `Root == ""` 时将文件平铺到输出母目录。

### 已完成基础层

- 新增跨平台直接文件路径解析，不依赖测试主机操作系统识别 Windows 盘符和 UNC 共享；
- 直接文件按源卷分组；
- 同卷文件计算最近公共父目录，并把其共同顶层文件夹保留在输出相对树中；
- 多卷拖入生成稳定的 `C盘`、`D盘` 或 `server_share` 输出前缀元数据；
- `ScanDroppedPaths` 不再给直接文件生成空根分组；
- 覆盖同目录、嵌套目录、单文件、跨盘、UNC、空输入和混合文件 / 文件夹扫描测试；
- 新增源码已纳入 `SOURCE_FILES_SHA256.txt`。

### 自纠与验证

1. 首次验证发现 `path.Clean` 会把 UNC 开头双斜杠压成单斜杠，导致不同网络共享被误判为同一本地根；修复为在路径清理前先解析服务器与共享名。
2. 受控验证运行 `30833900951` 通过总清单、普通 Go 全测、全量竞态、`go vet`、Windows 测试程序和 GUI 双交叉构建。
3. 验证成功后一次性工作流已自删除；干净基础层提交为 `447ca7a8eb5f8b93ff8b328a94823f918fffa56a`。
4. 该提交由 GitHub Actions 推送，标准 CI `30833959913` 被平台标记为 `action_required` 且没有启动 job；当前正常文档提交将重新触发正式 P101 门禁。

### 下一步

1. 将 `OutputPrefix` 接入任务与最终输出路径，真正隔离跨盘和同名父目录；
2. 让添加文件、拖拽文件和文件夹导入使用统一导入结果对象；
3. 统一视频、图片、重复、不支持、不可读与扫描失败统计；
4. 重构右下角轻量通知的渐显、上浮、约 5 秒消失和手动关闭；
5. 建立第三轮固定清单并完成 Windows 原生验证。
