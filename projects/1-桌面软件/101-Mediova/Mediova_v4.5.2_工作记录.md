## 第一轮：基础 UI 与暂停语义

### 范围

- 顶部工具栏冷启动首次显示和统一背景；
- 输出母目录模式切换后的蓝色焦点残留；
- 右下角转换、暂停、停止按钮统一几何与实心图标；
- 总进度文字防闪；
- 暂停期间已用时和剩余时间冻结；
- 暂停态文字灰化；
- 总进度条淡轮廓；
- 右上角状态灯真圆化。

下拉框统一淡边线和列标题下框线保留在同一大阶段范围中，但因第一轮已经涉及主窗口启动、进度和按钮的多个受保护绘制路径，为控制审查规模，最终视觉接线顺延到第二轮的列表视觉收口，不与暂停时钟继续混改。

### 已完成实现

#### 有效运行时钟

新增 `activeRunClock`：

- 只累计实际转换运行区间；
- 暂停时冻结已用时；
- 多次暂停 / 恢复累计扣除全部暂停区间；
- 剩余时间和速度基于有效运行时长估算；
- 最终运行摘要同样排除暂停时间。

#### 总进度重绘

- 总进度仅在文字、暂停状态或可见百分比发生变化时重绘；
- 细小且不可见的进度变化不再持续擦除 footer；
- 暂停态使用灰色文字和低饱和填充；
- 增加完整淡轮廓，0% 时仍能看出进度范围。

#### 主按钮图形

- 转换 / 继续使用 GDI 填充实心三角形；
- 暂停使用实心双竖条；
- 停止使用实心方块；
- 图形填充色直接使用按钮当前前景色，随普通、悬停、按下和禁用状态变化；
- 不再依赖字体线框图标。

#### 工具栏和输出目录状态

- `WM_CREATE` 完成布局后，在 UI 主线程同步显示并重绘工具栏和标题分隔控件；
- 不使用后台 goroutine、ticker 或延迟轮询补显示；
- 视频 / 图片模式刷新输出母目录时，显式清除编辑框选区；
- 锁定状态下若焦点仍停留在地址框，转移到任务列表，避免蓝色整块选择残留。

#### 状态灯

- 改用方形边界内的 GDI 椭圆绘制真圆；
- 直径按文字高度与 DPI 边界计算；
- 旧字体字符 `●` 绘制被源码契约禁止。

### 自动测试

新增并通过：

- 暂停期间时钟冻结；
- 多段暂停累计；
- 重复暂停 / 恢复调用幂等；
- 进度重绘由内容变化驱动；

## 第二轮：列表、队列和缩略图

### 范围

- `#` 自动编号列；
- 缩略图内存与磁盘缓存生命周期；
- 原目录和输出目录无选择回退；
- 多选“退出队列”；
- 横向与纵向滚动条自动淡化；
- 列标题下框线；
- 下拉框统一淡边线。

### 已完成实现

#### 列模型与编号

- 最前方新增 `#` 列，显示当前可见顺序，从 1 开始连续编号；
- 文件、分辨率、时长、方向、输出分辨率、质量、旋转、体积、压缩后、进度和状态全部改用显式列常量；
- 排序、自定义绘制、局部行更新和状态文本不再依赖 `8 / 9 / 10` 等魔法数字；
- 对旧 10 列和 11 列列宽配置分别迁移，新增编号列不会导致用户原列宽整体错位；
- 编号列按当前筛选与排序后的可见顺序重算，不写入任务会话。

#### 缩略图所有权

- 每个任务拥有独立缩略图生成代次；删除任务后，迟到的异步生成结果不会重新写回列表；
- 磁盘缓存使用路径引用计数，多个任务共享同一缓存文件时，只有最后一个所有者释放后才删除；
- 删除、清空、清理已完成 / 问题任务和程序退出均进入同一释放路径；
- 从 ImageList 删除图像后同步修正后续任务索引，避免缩略图错位；
- 非缓存临时缩略图加载后立即删除，缓存缩略图按任务生命周期释放。

#### 目录回退

“原目录”和“输出目录”统一按以下顺序解析：

1. 单选或多选中的首个有效任务；
2. 当前工作区列表最后一个有效任务；
3. 当前媒体模式最近使用目录；
4. 当前媒体模式输出母目录。

输出任务尚未完成时，优先使用队列快照中的输出母目录，不再因为 `OutputPath` 为空而无响应。

#### 多选退出队列

- 右键“临时操作”新增“退出队列”；
- 只处理尚未开始运行的 `队列中` 任务；
- 可多选批量退出，统一转为搁置状态并保留冻结参数与队列快照；
- 转换中和暂停任务不会被该入口强行退出，仍使用原有安全搁置流程；
- 退出后可逐个激活搁置任务修改，应用后重新归队；
- 当前正在编辑另一个搁置任务时，不会静默切换交易对象。

#### 列表视觉

- 列标题下框线提高到明确但低对比的分隔色；
- 列表横向和纵向滚动条默认隐藏，鼠标进入、滚轮、滚动消息或列宽变化时显示，静止后自动隐藏；
- 搜索、筛选、输出目录和全局 / 个体参数下拉框统一使用 Explorer 原生淡边线主题；
- 不恢复网格线或重边框。

- 编号列模型与显式列索引；

### 门禁发现与自纠

1. 首次接线器按不存在的 `case 8 / 9 / 10` 匹配自绘分支；实际代码使用三个 `if cd.ISubItem == …`。脚本在唯一匹配失败时停止，没有推送半成品，随后改为真实分支签名。
2. 辅助函数 `v452ActivateHeldSelected` 已提前升级为双返回值，接线脚本仍重复执行旧签名迁移。重复步骤被删除，没有回退已完成代码。
3. 产品接线通过后，旧 v4.2.2 契约仍要求主文件内保留旧 11 列字面量与数字列索引；契约已更新为验证新的显式列模型。
4. 第一轮固定清单锁定了第二轮合法修改前的 `main_windows.go`、`v420_windows.go` 和 UI 状态文件；清单按现有文件集重新计算并更新固定摘要，没有绕过校验。
5. 首次正式 CI `30828474786` 的 Linux 任务在执行 Go 测试前被总源码清单拦截。原因是兼容契约与第一轮固定清单在第二轮接线末尾更新后，总清单仍保留三条旧摘要。现已按实际文件重新生成总清单。
6. 同一正式 CI 的 Windows 原生编译发现 `v452ListSubclassCB` 初始化表达式与子类消息处理函数互相引用，形成 Go 初始化环。现改为在 `init()` 中创建 Win32 回调地址，消息处理与卸载语义不变。
7. 收口任务 `30828737635` 已验证总源码清单、普通 Go 全测和 Windows 测试程序交叉编译均通过，并在推送前删除自身工作流。
8. 所有临时执行脚本和工作流均已删除。PR 当前差异只位于 `projects/1-桌面软件/101-Mediova/...`。
