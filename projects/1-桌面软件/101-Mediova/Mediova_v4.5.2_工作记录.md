## 第三轮：导入、输出结构与轻量通知

### 已完成实现

#### 直接文件与相对目录

- 文件拖拽按源卷分组；
- 同卷文件计算最近公共目录的父级作为相对路径根，保留共同顶层文件夹；
- 单文件同样保留其所在顶层文件夹；
- Windows 盘符、UNC 服务器和共享名使用跨平台路径解析，不依赖测试主机操作系统；
- 文件选择对话框利用已保存的 `LastInputDir` 恢复共同顶层目录，不再默认平铺到输出母目录；
- 文件夹导入继续沿用 `ImportTreeRoot`，视频与图片共用同一目录树规则。

#### 跨卷与同名目录隔离

- 多卷导入生成稳定的 `C盘`、`D盘` 或 `server_share` 前缀；
- 前缀经过字符清理和长度限制，不能形成路径穿越；
- 为避免修改任务 JSON 结构，前缀使用带版本标记、可逆的 Root 上下文编码，随既有任务、会话、搁置和恢复生命周期保存；
- 旧 Root、空 Root 和异常编码均安全回退，不破坏历史会话；
- 输出路径、目录时间戳恢复和“打开输出目录”统一解码并应用同一前缀。

#### 导入统计与右下角通知

- 统一识别文件、文件夹和拖拽入口的导入结果文字；
- 视频、图片、重复、不支持、不可读和扫描失败保持在同一摘要中；
- 直接文件原“已自动分流”文字规范为统一“导入完成”格式；
- 状态栏通过 Win32 子类监听导入结果，80 ms 去抖，避免批量导入中间状态产生多次通知；
- 新增独立无激活、置顶、分层透明的右下角通知窗口；
- 通知渐显并上浮，约 5 秒后渐隐，也支持手动关闭；
- 会避让现有悬浮进度条和完成通知，不抢焦点；
- 自测模式不弹出通知，避免干扰自动化验证。

### 主要自纠

1. `path.Clean` 会把 UNC 开头双斜杠压成单斜杠，已改为清理前解析服务器和共享名。
2. PR 分支中新加入的临时工作流未被 GitHub 基线规则执行，随后删除工作流和触发标记，改用小文件可审查接线；最终差异不含临时设施。
3. 最初尝试新增任务字段会扩大持久化迁移面，最终改为版本化 Root 上下文，保持旧任务 JSON 兼容。
4. 新 Windows 通知文件的预计算摘要与仓库实际 UTF-8 字节不同，固定清单测试输出实际 SHA 后精确校正，没有绕过校验。
5. 为暴露真实编译问题曾临时使用三轮严格子集清单；验证全绿后已恢复原全量源码清单并新增本轮文件。
