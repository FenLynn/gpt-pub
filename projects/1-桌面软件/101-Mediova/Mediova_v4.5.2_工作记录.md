# Mediova v4.5.2 工作记录

## 当前状态

- 正式版本仍为 Mediova v4.5.0，标签与 Release 为 `p101-v4.5.0`；
- v4.5.2 仍是用户验证候选，不是正式 Release；
- 当前活动分支：`p101-v452-round7-clean-redesign`；
- 当前 Draft PR：#354，基于 `p101-stable`；
- 第六轮已被实机否决；第七轮从稳定分支回退重做；第八轮继续处理用户实机发现的 UI 多层控制问题；
- 用户确认前不得合并到 `p101-stable` 或 `main`，不得建立标签或正式 Release。

## 历史阶段摘要

1. 第一轮：顶部工具栏、输出目录焦点、主按钮图形、有效运行时钟、进度防闪和状态灯基础修复。
2. 第二轮：12 列模型、编号列、旧列宽迁移、缩略图生命周期、多选退出队列与列表视觉收口。
3. 第三轮：直接文件共同顶层、跨卷与 UNC 分组、安全输出前缀、统一导入摘要和轻量通知。
4. 第四轮：双端时间轴、播放头、裁剪框创建/移动/缩放、旋转坐标映射及处理顺序。
5. 第五轮：Windows 原生鼠标交互、真实 FFmpeg 四方向输出矩阵及编辑框覆盖裁剪模型修复。
6. 第六轮：持续重绘与界面叠加方案被用户实机否决，未合并。
7. 第七轮：从 `p101-stable` 重新建立独立编辑窗口、五标记时间轴、状态灯与主界面基础视觉，并完成首批七项反馈修复。
8. 第八轮：不再叠加新补丁层，执行“UI 控制权收口”，解决多个实现同时控制同一控件造成的反复错乱。

## 第八轮根因

用户实机反馈中的列宽串扰、滚动条闪烁、底部按钮偶发错位、输出路径蓝色选区和剪裁窗口闪烁，并不是彼此孤立的小问题。根因是：

- 同一主窗口同时存在旧布局、第七轮布局和反馈层布局；
- 同一 ListView 同时存在列表绘制、滚动条开关和叠加绘制等多条子类链；
- 视频和图片虽建立独立文件，但仍回写旧全局列宽数组；
- 输出路径只清理外层 ComboBox，后续异步刷新又会恢复内部 Edit 选区；
- 剪裁窗口安装依赖控件创建事件的时序，不能保证最后一个控件创建后仍有事件触发；
- 预览画面和绿色框直接绘制到屏幕 DC，拖动时同时更新多个控件与摘要。

本轮约束为：

> 同一控件只有一个布局入口；同一状态只有一个权威数据源；同一画面只有一条绘制链。

## 用户 11 项反馈处理

### 1. 预览图不可见

- 左侧画布在无位图时显示“正在生成预览”或明确的 FFmpeg 状态，不再留下无法解释的黑框；
- 新预览成功前保留上一张成功帧；
- “高清预览”改为在左侧画布内显示处理后帧，不再调用外部图片查看器；
- 新请求通过序列号淘汰旧请求，旧请求不能覆盖更新结果。

### 2. 横纵滚动条不停闪烁

- 删除 `ShowScrollBar()` 显示/隐藏原生非客户区滚动条的循环；
- 改为在 ListView 正常绘制后叠加轻量悬浮滑块；
- 只有鼠标进入右侧或底部约 18 DPI 像素的边缘区，停留 500 ms 后才出现；
- 鼠标位于中央时没有计时器、轮询或持续刷新；
- 增加 `WM_STYLECHANGING` 样式守卫，阻止 ListView 在内容变化后重新加入原生横纵滚动条和立体边框。

### 3. 视频与图片列宽仍互相影响

- 视频和图片使用两套独立的 `Video` / `Image` 列宽数组；
- 旧 `TaskColumnWidths` 只作为第一次升级迁移输入，运行期间不再写回；
- 切换媒体、刷新列表、排序、导入和调整窗口尺寸均不得改变列宽；
- 只有列头鼠标按下前后宽度确实发生变化时，才认定用户完成了手动拖动并保存；
- `#` 编号列与其他列遵守同一规则。

### 4. 统一命名为“剪裁”

- 主页面入口改为“剪裁”；
- 右键菜单改为“剪裁…”；
- 独立窗口标题改为“剪裁 · 文件名”；
- 状态提示统一使用“剪裁设置”；
- 窗口内部保留“剪辑”和“画面”两个功能分区。

### 5. 时间轴重做

- 源起始时间固定显示在左侧，源结束时间固定显示在右侧；
- 不再在轨道下方写“源起点/源终点”；
- 剪辑起点使用向右蓝色旗标；
- 剪辑终点使用向左蓝色旗标；
- 当前时间使用独立红色下向游标和底部时间标签；
- 源时间、剪辑边界和当前时间分成三个垂直层；
- 起止标签接近时自动错层，不相互覆盖。

### 6. 剪裁页面整体美化

- 右侧标题简化为“剪辑”和“画面”；
- “设定起始时间/设定结束时间”简化为“起始时间/结束时间”；
- 按钮简化为“当前、源起点、源终点”；
- 源时间范围移到左侧；
- X、Y、宽、高四个输入框放在同一行；
- “高清预览、应用到已选、应用当前、取消”均按文字宽度紧凑排列；
- 右侧说明框改为浅灰只读检查卡，不再呈现为可编辑多行文本框；
- 检查卡固定显示转正尺寸、保留区域、保留面积、输出时长和处理顺序；
- 时间轴交互后强制恢复检查卡格式，旧摘要不能覆盖新布局。

### 7. 左侧绿色选区拖动防闪

- 视频帧、绿色选区和八个控制点先画入内存位图；
- 完整绘制后只执行一次 `BitBlt`；
- 拖动中裁剪数值最多约每 40 ms 同步一次；
- 鼠标释放后再完整更新输入框和检查卡；
- 只重绘画布，不触发整个剪裁窗口持续刷新。

### 8. 主任务区域现代化

- 移除 ListView 的强 `WS_EX_CLIENTEDGE` 立体边框；
- 阻止控件重新恢复 `WS_BORDER` 和原生滚动条样式；
- 表头使用加粗字体和清晰底部分隔线；
- 行之间使用极浅横向分隔线；
- 选中行使用浅蓝背景；
- 编号和缩略图仍在同一正常绘制链中叠加，不安装第二套绘制子类。

### 9. 右下角三个按钮偶发错乱

- 删除旧第七轮独立 footer 布局入口；
- 状态文字、开始、暂停和停止只由统一主窗口布局函数计算；
- 坐标直接依据主窗口客户区，不再把另一个正在移动的子控件作为锚点；
- 使用 `BeginDeferWindowPos / DeferWindowPos / EndDeferWindowPos` 一次性提交四个控件位置；
- 增加布局重入保护；
- 窗口缩放、右栏变化和刷新均经过同一个入口。

### 10. 悬浮提示重做

- 增加一个统一浅色悬浮提示管理器；
- 延迟 420 ms；
- 浅灰白背景、1 px 浅边框、约 6 px 圆角；
- 最大宽度约 280 px；
- 不激活窗口、鼠标可穿透；
- 点击、切换、缩放或失焦时立即关闭；
- 禁用按钮可附带当前不可用原因；
- 不使用重复计时器和黑色大框。

### 11. 输出路径蓝色选区与主进度条起点刻度

- 通过 `GetComboBoxInfo()` 获取输出路径内部真实 Edit 子窗口；
- 媒体切换和后续排队刷新完成后，多阶段执行 `EM_SETSEL`、`HideCaret` 并把焦点恢复到媒体按钮；
- 用户亲自点击路径框时取消自动清理，保留正常编辑能力；
- 主进度条只有进度大于 0 时才绘制填充；
- 删除 0% 时的假竖线刻度。

## 控制权收口

本轮移除了或降级为兼容函数的重复入口：

- 旧第七轮主窗口 WinEvent/layout hook；
- 旧独立剪裁布局事件 hook；
- 旧第二套 ListView 绘制子类；
- 原生滚动条显示/隐藏循环；
- 运行期间对旧全局列宽数组的写回。

剪裁窗口改为：首次检测到窗口后，仅投递一次 UI 线程安装消息；当 `WM_CREATE` 结束后，同步安装窗口、时间轴和画布的最终子类，然后删除临时安装器。该方案不再依赖“最后一个控件之后还会发生一次创建事件”的不可靠时序。
