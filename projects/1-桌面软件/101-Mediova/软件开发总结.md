# Mediova 软件开发总结

## 产品定位

Mediova 是面向 Windows 10/11 x64 的本地媒体批处理与创作工作站。产品从自动识别视频方向、一次完成转正与转码的单点工具，逐步扩展为同时处理视频和图片的可靠任务系统，覆盖递归导入、媒体探测、方向修正、分辨率与尺寸调整、编码压缩、裁剪、轨道兼容判断、输出校验、失败恢复和结果对比。

软件始终坚持本地处理，不上传用户媒体，不修改或删除源文件。Mediova 的核心价值不是简单包装 FFmpeg，而是把媒体处理、任务状态、参数冻结、输出占用、完整性验证和 Windows 桌面交互组成闭合且可追溯的工程流程。

## Runtime、Data 与交付边界

完整验证 Runtime 采用透明目录：

```text
Mediova/
├── Mediova.exe
├── Components/FFmpeg/bin/
├── runtime-manifest.json
├── THIRD_PARTY_NOTICES.md
└── README.txt
```

配置、历史、会话和备份位于 `%APPDATA%\Mediova`，缓存、临时文件、缩略图、本机状态和日志位于 `%LOCALAPPDATA%\Mediova`。公开 Runtime 与私人 Data 严格分离，组件可以复制、覆盖、校验和删除后重建。

完整 FFmpeg Runtime 只用于 CI 和内部验证。正式用户 Release 默认只提供四文件轻量覆盖包：

```text
Mediova.exe
README.txt
runtime-manifest.json
THIRD_PARTY_NOTICES.md
```

轻量包不包含 FFmpeg、FFprobe、`Components/` 或用户 Data。覆盖更新时保留原 `Components\FFmpeg\bin`。这一边界既减少重复下载，也避免把第三方运行组件和私人状态混入同一交付物。

## 任务状态与参数模型

v4.2.0 将软件从批次表单重构为可编辑队列，明确区分准备中、队列中、转换中、暂停、搁置待修改、完成和失败。

- 视频与图片分别保存输出母目录、最近目录和默认参数。
- 底部参数只作用于当前媒体模式的准备中任务，并作为新任务模板。
- 右侧个体编辑使用草稿和显式应用，多选时只提交实际修改字段。
- 任务入队时冻结转换参数、输出母目录、完整输出路径、冲突策略和运行快照。
- 活动队列允许继续导入同类媒体并动态追加；另一媒体模式仍可准备任务。
- 队列中、转换中和暂停任务默认锁定；单个任务可以进入独立搁置会话修改或安全移除。
- 转换任务搁置时安全终止 FFmpeg、清理临时输出并从 0% 重新开始，不伪装断点续转。
- 从列表移除任务不删除源文件，也不误删已完成的正式输出。

v4.2.2 进一步明确：视频与图片可以复用相似的底部控件结构，但进度统计、按钮文案、启用状态和命令作用域必须按当前工作区独立。另一个媒体队列运行时，当前页不得显示或控制对方队列。

## 输出目录、时间与结果闭环

拖入顶层文件夹 `A` 时，视频与图片均输出为 `输出母目录/A/...`，保留用户选择的顶层目录本身和以下完整多级结构。输出文件完成后恢复源文件时间，并沿对应输出路径恢复目录树的创建、访问和修改时间。

每个任务必须形成明确结果。只有输出真实存在并通过最低完整性检查后才能记为成功。启动失败、进程失败、输出缺失、输出异常过小、恢复失败和验证失败必须形成可见状态。硬件编码不可用或执行失败时安全回退 CPU；同名输出使用原子占用或等效机制，防止并发任务写入同一目标。

## 界面设计演进

顶部操作区被收拢为稳定单行结构，搜索、筛选和状态灯不能因窗口变化掉到下一行。底部区域统一组织输出母目录、当前媒体参数、总进度和队列操作，同时保持视频与图片状态独立。

v4.2.1 证明“几何正确”不等于“最终像素可见”。压缩和进度条已经通过高度、内缩和居中测试，但真实 `PrintWindow` 截图一度只剩文字。最终改为直接绘制轨道、渐变填充和边框，并增加自绘回调活动检查，才闭合真实绘制路径。

v4.2.2 再次证明 CI 全绿不能替代人工视觉判断。第一版进度文字虽然按填充区裁剪重绘白字，自动测试与原生自检均通过，但真实截图仍显示蓝底黑字。经过两轮截图复核，最终方案不再依赖 ListView/`PrintWindow` 中不稳定的裁剪区，而是：

1. 测量完整标签并保持整体居中；
2. 逐字符测量宽度；
3. 根据每个字符中心位于蓝色填充区还是浅色轨道区选择白色或深色；
4. 逐字符直接绘制。

这样 100% 蓝色进度条稳定显示白字，部分填充时同一标签可以按字符背景同时出现白色和深色。

v4.2.2 还形成以下长期设计结论：

- 状态灯使用 DPI 感知字体矢量圆点或等效高分辨率方案，禁止拉伸低分辨率位图。
- 图片参数宽度按真实文本长度单独配置，不能机械复用视频宽度。
- “全部恢复默认”图标必须紧凑，并在图标与边框间保留安全间隙。
- 压缩条原始体积侧必须有可辨识浅灰底。
- 视频列表提供可排序时长列，图片显示 `—`；新增列必须迁移旧列宽配置。

## 验证体系

长期 CI 固定源码逐文件 SHA-256，执行普通测试、全量竞态测试、`go vet`，并完成 Windows 测试二进制与 GUI EXE 双交叉构建。

稳定和正式主线准入还必须在隔离的 Data 根目录下完成：

- Windows 原生普通测试、竞态测试和 `go vet`；
- 固定公开通道真实 FFmpeg/FFprobe 下载与运行；
- 完整 Runtime 构建；
- EXE FileVersion、ProductVersion 和产品名校验；
- Runtime manifest 逐文件大小与 SHA-256；
- 私人 Data 泄漏扫描；
- 正式 EXE 原生 self-test；
- 视频宽屏、视频紧凑、图片模式和搁置模式四套真实窗口截图；
- 截图人工复核。

长期 UI 准入采用五层证据：视觉语义规则、几何属性、真实绘制路径、最终 EXE 截图和人工复核。任何一层都不能代替其他层。

## 后续原则

当前正式版本为 v4.2.2。下一版本不得仅因版本号递增而启动，必须先登记可复现问题、影响范围、目标和完成标准。自动验证和 CI 截图不能替代所有真实用户环境；125%～175% DPI、多显示器、主题、显卡驱动、拖放、托盘、PotPlayer、HEIC 和特殊媒体仍需持续真实桌面观察。
