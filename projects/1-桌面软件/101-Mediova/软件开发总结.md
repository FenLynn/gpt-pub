# Mediova 软件开发总结

## 产品定位

Mediova 是面向 Windows 10/11 x64 的本地媒体批处理与创作工作站。产品从自动识别视频方向、一次完成转正与转码的单点工具，逐步扩展为同时处理视频和图片的可靠任务系统，覆盖递归导入、媒体探测、方向修正、分辨率与尺寸调整、编码压缩、裁剪、轨道兼容判断、输出校验、失败恢复和结果对比。

软件始终坚持本地处理，不上传用户媒体，不修改或删除源文件。Mediova 的核心价值不是简单包装 FFmpeg，而是把媒体处理、任务状态、参数冻结、输出占用、完整性验证、异常恢复和 Windows 桌面交互组成闭合且可追溯的工程流程。

## Runtime、Data 与交付边界

完整验证 Runtime 采用透明目录：

```text
Mediova/
├── Mediova.exe
├── Components/FFmpeg/bin/
├── runtime-manifest.json
├── THIRD_PARTY_NOTICES.md
└── README.txt
```

配置、历史、会话和备份位于 `%APPDATA%\Mediova`，缓存、临时文件、缩略图、本机状态和日志位于 `%LOCALAPPDATA%\Mediova`。公开 Runtime 与私人 Data 严格分离，组件可以复制、覆盖、校验和删除后重建。

完整 FFmpeg Runtime 只用于 CI 和内部验证。正式用户 Release 默认只提供四文件轻量覆盖包：

```text
Mediova.exe
README.txt
runtime-manifest.json
THIRD_PARTY_NOTICES.md
```

轻量包不包含 FFmpeg、FFprobe、`Components/` 或用户 Data。覆盖更新时保留原 `Components\FFmpeg\bin`。这一边界减少重复下载，也避免第三方运行组件和私人状态混入同一交付物。

## 任务状态与参数模型

v4.2.0 将软件从批次表单重构为可编辑队列，明确区分准备中、队列中、转换中、暂停、搁置待修改、完成、跳过和失败。

- 视频与图片分别保存输出母目录、最近目录和默认参数。
- 底部参数只作用于当前媒体模式的准备中任务，并作为新任务模板。
- 右侧个体编辑使用草稿和显式应用，多选时只提交实际修改字段。
- 任务入队时冻结转换参数、输出母目录、完整输出路径、冲突策略和运行快照。
- 活动队列允许继续导入同类媒体并动态追加；另一媒体模式仍可准备任务。
- 队列中、转换中和暂停任务默认锁定；单个任务可以进入独立搁置会话修改或安全移除。
- 转换任务搁置时安全终止 FFmpeg、清理临时输出并从 0% 重新开始，不伪装断点续转。
- 从列表移除任务不删除源文件，也不误删已完成的正式输出。

v4.5.0 进一步把“运行中状态”和“可持久化事实”分开：冻结参数、输出母目录和冲突策略可以恢复；进度、引擎、临时输出路径和运行时间属于瞬时状态，异常恢复时必须清除。

## 输出目录、时间与结果闭环

拖入顶层文件夹 `A` 时，视频与图片均输出为 `输出母目录/A/...`，保留用户选择的顶层目录本身和以下完整多级结构。输出完成后恢复源文件时间，并沿对应输出路径恢复目录树的创建、访问和修改时间。

每个任务必须形成明确结果。只有输出真实存在并通过最低完整性检查后才能记为成功。启动失败、进程失败、输出缺失、输出异常过小、恢复失败和验证失败必须形成可见状态。硬件编码不可用或执行失败时安全回退 CPU；同名输出使用原子占用或等效机制，防止并发任务写入同一目标。

## 界面设计演进

顶部操作区被收拢为稳定单行结构，搜索、筛选和状态灯不能因窗口变化掉到下一行。底部区域统一组织输出母目录、当前媒体参数、总进度和队列操作，同时保持视频与图片状态独立。

### 真实像素优先于“看起来几何正确”

v4.2.1 证明“几何正确”不等于“最终像素可见”。压缩和进度条通过高度与居中测试后，真实 `PrintWindow` 截图仍一度只剩文字。最终改为直接绘制轨道、填充和边框，并增加真实绘制路径检查。

v4.2.2 进一步证明 CI 全绿不能替代人工视觉判断。最终进度文字方案不依赖不稳定的裁剪重绘，而是测量完整标签后，逐字符根据字符中心位于蓝色填充区还是浅色轨道区选择白色或深色，从而稳定实现跨边界双配色。

### v4.2.3：统一 footer 几何

用户实机发现视频与图片右下角按钮仍有错位。根因不是单一按钮坐标，而是进度、状态文字和按钮分别使用不同的底部偏移，同时禁用态自绘没有完整清除画布。

最终方案建立统一 footer 几何模型：先确定 footer 边界、内边距、进度区域和按钮组，再一次性布局三个主要按钮。按钮同高、同基线、固定间距并右对齐；自绘前清除完整画布。这个设计比继续修补局部偏移更稳定，也能被多尺寸和多 DPI 几何测试固定。

### v4.3.0：复用单一裁剪系统

预览与裁剪升级没有新建第二套窗口或渲染架构，而是在现有对话框上加入比例预设、最大居中适配、拖框比例锁定、键盘微调和应用到已选任务。

裁剪坐标和比例约束提取为纯函数，使偶数坐标、最小尺寸、边界限制和跨分辨率缩放可以独立测试。界面只负责表达意图，几何函数负责生成合法结果。

### v4.4.0：能力声明服从实际 FFmpeg

图片裁剪复用视频画面裁剪工作流，但关闭无意义的时间轴校验。HEIC、HEIF、AVIF 不通过文件扩展名直接宣称支持，而是在转换前调用实际 FFmpeg 做有界单帧解码预检。

这样软件可以明确区分“格式已识别”和“当前 FFmpeg 构建可解码”，失败时给出解决方式，同时保证源文件不被修改。现代图片能力因此是可验证能力，而不是静态宣传。

## v4.5.0 会话恢复架构

旧会话文件只是任务数组，保存和加载时会简单重置状态，无法区分正常退出、异常中断、格式版本和瞬时运行信息。v4.5.0 引入 schema 2 会话包络：

```text
schema
version
saved_at
clean_shutdown
reason
tasks
```

保存使用同目录临时文件、文件同步、主文件到 `.bak` 的轮换和原子替换。主快照损坏时可以回退备份；旧数组格式仍可读取。

恢复遵循文件级边界：

- 运行中、队列中、暂停、搁置和停止任务回到准备中；
- 冻结参数、输出母目录和冲突策略保留；
- 进度、引擎、临时输出路径、错误文本和运行时间清除；
- 完成、跳过和失败结果保持；
- 源文件缺失明确标记失败；
- 中断任务从 0% 重新处理，不复用可能不完整的编码输出。

这种方案没有伪装帧级断点续转，但提供了可解释、可测试、不会污染正式结果的恢复路径。2500 项混合状态压力测试固定了长队列恢复的时间和状态边界。

## 验证体系

长期 CI 固定源码逐文件 SHA-256，执行普通测试、全量竞态测试、`go vet`，并完成 Windows 测试二进制与 GUI EXE 双交叉构建。

稳定和正式主线准入还必须在隔离 Data 根目录下完成：

- Windows 原生普通测试、竞态测试和 `go vet`；
- 固定公开通道真实 FFmpeg/FFprobe 下载与运行；
- 完整 Runtime 构建；
- EXE FileVersion、ProductVersion 和产品名校验；
- Runtime manifest 逐文件大小与 SHA-256；
- 私人 Data 泄漏扫描；
- 正式 EXE 原生 self-test；
- 视频宽屏、视频紧凑、图片模式和搁置模式四套真实窗口截图；
- 截图人工复核。

长期 UI 准入采用五层证据：视觉语义规则、几何属性、真实绘制路径、最终 EXE 截图和人工复核。任何一层都不能代替其他层。

## 后续原则

当前正式版本为 v4.5.0。v4.5.1 仅用于可复现稳定性热修；下一主版本优先考虑队列可观测性、失败筛选、安全重试和精简处理报告，而不是继续堆叠格式或引入账户、云同步和复杂数据库。

新版本不得仅因版本号递增而启动，必须先登记可复现问题、实际价值、最小范围、兼容边界和完成标准。125%–175% DPI、多显示器、主题、显卡驱动、拖放、托盘、PotPlayer、现代图片和特殊媒体仍需持续真实桌面观察。
