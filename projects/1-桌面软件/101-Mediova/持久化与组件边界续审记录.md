# Mediova 持久化与组件边界续审记录

## 记录范围

本文承接《安装与配置继承审查》，记录 2026-08-03 继续完成的三轮边界处理：

1. Runtime 组件目录不可写时的明确降级；
2. 配置、任务会话和历史记录的独立恢复与故障隔离；
3. 在首次保存前预检应用数据目录的写入能力。

本轮成果仍只进入 `p101-exp`。不改变 v4.5.0 版本号、正式标签、Release 或正式 EXE。

## 第一轮｜Runtime 不可写时的组件降级与导入保护

### 复核发现

现有组件发现顺序已经可以回退到用户明确指定的外部 FFmpeg、透明 Runtime、旧 AppData 兼容目录、EXE 附近目录或系统 PATH，但 Runtime 目录不可写时的错误不够明确。FFmpeg ZIP 导入也会在真正写入前完成较多准备，用户难以区分“已有组件仍可使用”和“目录不可写且根本没有组件”。

### 已实施

- 新增不会创建 Runtime 目录的写入预检；
- 沿目标路径向上寻找最近存在目录，通过创建、同步和删除临时探针判断可写性；
- 区分“完整 FFmpeg 已存在但无法更新”和“不可写且缺少完整组件”；
- 已有完整组件时继续允许转换，只禁止导入或更新；
- 缺少组件时明确引导在 FFmpeg 菜单选择外部组件，或将软件放到可写目录；
- Runtime 路径被普通文件占用时不覆盖、不删除该文件；
- FFmpeg ZIP 导入在解压、备份旧组件和切换目录前先执行写入预检；
- 不把 AppData 作为新的隐式 Runtime，不清空用户外部组件路径；
- Windows 启动状态会显示 Runtime 降级结果；
- 新增 `RUNTIME_PREFLIGHT_FILES_SHA256.txt` 固定清单。

### 自动验证矩阵

- 尚未创建的 Runtime 组件树可写且预检无副作用；
- 已有完整 FFmpeg/FFprobe 对；
- Runtime 路径被普通文件阻断；
- 已有组件但目录不可更新的提示语义；
- ZIP 导入在受阻 Runtime 下无损失败；
- 原阻断文件保持字节不变。

## 第二轮｜任务会话与历史记录独立恢复

### 复核发现

`session.json` 原有恢复协议主要覆盖“主文件缺失但 `.tmp` 或 `.bak` 存在”的原子保存中断窗口；主文件存在但内容损坏时，恢复能力不足。

`history.json` 损坏时，历史读取会返回空集合。下一次写入可能把新记录写入主路径，从而覆盖损坏证据。配置、会话与历史虽然使用不同文件，但故障语义尚未完全隔离。

### 已实施

- 配置、会话、历史继续采用三套独立恢复策略；
- 会话主文件存在但损坏时，优先恢复有效 `.tmp`，其次恢复 `.bak`；
- 损坏会话主文件先隔离为 `.corrupt`，不静默覆盖；
- 没有有效会话快照时仅从空队列启动，不影响配置和历史；
- 有效历史主文件会维护独立 `.lastgood`；
- 历史主文件损坏时优先使用 `.bak`，其次使用 `.lastgood`；
- 无有效历史副本时隔离损坏主文件，从空历史继续；
- 会话或历史一方预检失败时，另一方仍独立处理；
- 两类文件同时损坏时保证 `config.json` 字节不变；
- Windows 启动状态说明恢复来源或隔离结果；
- 新增 `PERSISTENCE_ISOLATION_FILES_SHA256.txt` 固定清单。

### 自动验证矩阵

- 有效历史刷新最近有效副本；
- 损坏历史从 `.lastgood` 恢复并保留 `.corrupt`；
- 无历史副本时隔离后从空历史继续；
- 损坏会话从有效 `.tmp` 恢复并消费临时快照；
- 会话损坏证据保留；
- 会话与历史同时损坏时分别隔离；
- 配置文件保持字节级不变。

## 第三轮｜首次保存前的数据目录写入预检

### 复核发现

即使当前没有配置、会话或历史文件，应用数据目录也可能因为权限、路径冲突、磁盘或安全软件问题而不可写。如果只在真正保存时发现，用户可能已经修改大量参数或完成任务，但界面没有提前说明这些状态无法持久化。

### 已实施

- 应用数据目录解析完成后执行一次非破坏性写入预检；
- 预检只创建、写入、同步并删除一个临时探针；
- 不创建 `config.json`、`session.json` 或 `history.json`；
- 可写目录不留下任何临时文件；
- 缺失目录不由预检擅自创建；
- 数据路径被普通文件占用时保持原文件不变；
- 已有配置文件在预检前后保持字节级不变；
- 不可写时通过启动状态 UI 明确提醒配置、任务会话和历史更改可能无法保存；
- 提示用户检查目录权限、磁盘空间或安全软件占用；
- 路径解析失败继续由持久化文件预检报告，避免重复提示；
- 新增 `DATA_WRITE_PREFLIGHT_FILES_SHA256.txt` 固定清单。

### 自动验证矩阵

- 空白可写目录；
- 探针不留下文件；
- 缺失目录无副作用；
- 普通文件占用数据路径；
- 阻断文件保持字节不变；
- 已有配置文件保持字节不变；
- Windows 启动入口和 GUI 交叉构建。

## 当前结论

当前 `p101-exp` 已具备以下边界：

- Runtime 不可写时不会隐式改用新的 AppData 组件目录；
- 已有 Runtime FFmpeg 即使不可更新仍可继续使用；
- 无组件时给出明确外部组件选择路径；
- 配置、会话和历史互不替代、互不覆盖；
- 损坏会话和历史均会隔离原证据；
- 历史记录不会因下一次追加而静默覆盖损坏主文件；
- 首次保存前可以识别当前数据目录不可写；
- 启动状态 UI 可以说明 Runtime、恢复和写入能力异常；
- 正式 v4.5.0 基线保持不变。

## 后续重点

下一阶段只继续处理以下真实剩余边界：

- 启动后才发生的磁盘写满或安全软件临时独占，如何将配置或历史保存失败立即反馈到 UI；
- 便携模式首次启用、已有便携数据和普通 AppData 数据并存时的权威选择；
- 多条启动提醒同时出现时的摘要优先级和完整诊断入口；
- 状态栏、底部按钮和窄窗口之间的空间预算；
- 提升到稳定线前的 Windows 原生 Runtime 与桌面截图门禁。

当前不生成正式 EXE，不启动 v4.5.1，也不改变 v4.5.0 正式标签和 Release。
