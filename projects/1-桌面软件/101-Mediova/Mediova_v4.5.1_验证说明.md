# Mediova v4.5.1 验证说明

## 定位

Mediova v4.5.1 是在 v4.5.0 正式基线之后形成的实机验证候选，用于用户集中验证安装、原配置继承、运行期持久化、便携模式和状态反馈。

本候选不覆盖 `p101-v4.5.0` 标签，不创建正式 v4.5.1 Release。Windows 原生门禁已经证明其持久化与 Runtime 边界可靠，但用户真实桌面验证发现多项 UI、交互和生命周期问题，因此 v4.5.1 不转为正式版本，后续统一进入 v4.5.2 修复阶段。

## 主要变化

- 新安装不提前制造配置文件；
- 原 v2.8.4 及旧 Go 字段配置完整继承；
- 用户选择的 FFmpeg、PotPlayer 和输出目录保持权威；
- 配置、会话、历史文件相互隔离恢复；
- 运行中保存失败即时提示、去重并自动重试；
- 实时进度不触发高频会话重写；
- Windows 保存采用原生原子替换，ACL、磁盘或安全软件拒绝替换时，原主文件保持原位；
- 便携模式切换以前台当前数据为权威；
- 目标旧数据先备份，瞬态 `.bak`、`.tmp` 恢复副本不会重新夺权；
- 状态栏仅压缩诊断提醒，活动任务状态保持优先；
- 窄状态区仍保留明确“详情”入口；
- 完整运行状态进入诊断报告。

## Windows 原生验证

候选已经通过：

1. Windows Go 全测、全量竞态和 `go vet`；
2. 配置文件被无共享方式独占时，保存失败且原文件不变；
3. NTFS ACL 明确拒写时，保存失败且原文件不变；
4. ACL 或文件锁解除后，保存能够恢复；
5. 数据根目录被普通文件阻断时明确失败；
6. 普通 AppData 与便携目录并存时，当前数据覆盖目标旧数据，目标旧数据先备份；
7. 非托管文件保持不变；
8. 使用独立 64 MB NTFS VHD 制造真实磁盘满，保存失败且主配置不损坏；
9. 下载并验证真实 FFmpeg/FFprobe；
10. 生成完整 Windows x64 Runtime；
11. 校验 EXE 文件版本、产品版本、Runtime Manifest 和来源证明；
12. 检查 Runtime 不含配置、历史、会话或其他私有数据；
13. 原生自测不少于 62 项且全部通过；
14. 捕获视频宽窗口、视频紧凑窗口、图片页面和搁置编辑页面截图；
15. 输出独立 EXE、完整 Runtime ZIP、SHA-256、原生自测报告、故障注入报告和截图。

## 门禁发现与修复

首次 Windows 原生检出暴露了固定清单在 Windows 自动转为 CRLF 的问题。代码目录现已通过 `.gitattributes` 固定 Go 源码与 SHA-256 清单为 LF，使 Linux 和 Windows 对同一提交校验完全一致。

旧保存流程会先把主配置改名为 `.bak`，再把临时文件移入主路径；若第二步失败，回滚也可能受同一锁定、ACL 或磁盘状态影响。为消除这一结构性风险，现已改为：

- Windows 使用 `ReplaceFileW` 原子替换已有主文件；
- 首次写入使用带写穿语义的 `MoveFileExW`；
- 不再在替换前移动主文件；
- 替换失败时主文件保持原位；
- 成功后才清理陈旧恢复副本；
- 源码契约禁止重新出现 `os.Rename(path, bak)` 和反向回滚路径。

ACL 探针最终固定为严格顺序：先读取主配置基线，再施加拒绝 ACE，随后确认保存返回拒绝错误；递归移除目录和子文件的拒绝 ACE 后，再读取主文件并逐字节比较。报告同时记录 ACL 恢复输出、保存错误、恢复后读取错误和前后字节长度；该顺序避免把 ACL 本身造成的不可读误判为文件损坏，也不放宽保存失败和原文件不变的要求。

## 版本盖章方式

仓库主线中的 `appVersion` 仍保持 v4.5.0，以确保正式标签不被验证候选污染。

v4.5.1 构建脚本会：

1. 将候选源码复制到隔离临时目录；
2. 校验源码中仅存在一个精确的 v4.5.0 版本标记；
3. 仅在临时副本中改为 v4.5.1；
4. 从临时副本编译；
5. 写入 Windows 版本资源、Runtime Manifest 与 `build-provenance.json`；
6. 构建结束后删除临时副本。

因此正式源码和 v4.5.0 标签不变，验证 EXE 内部及 Windows 文件属性则明确显示 4.5.1。

## 用户真实桌面验证结论

Windows 自动门禁通过后，用户在真实媒体、真实窗口和连续操作中发现以下未闭合问题：

### 主界面与状态

- 顶部文件工具栏首次进入时可能不显示，随后显示时存在独立白色底板；
- 图片模式切回视频模式后，输出母目录地址框可能残留整块蓝色选择背景；
- 右下角转换、暂停和停止按钮仍有视觉错位，图标未按要求使用随前景色变化的实心形状；
- 总进度文字存在闪烁，暂停期间已用时仍增长，暂停状态也缺少灰色冻结表达；
- 总进度条缺少淡轮廓；
- 右上角状态灯可能被拉伸为椭圆，直径未严格按文字高度计算；
- 列标题下框线不清楚，横向与纵向滚动条过于显眼；
- 下拉框边线风格不统一；
- 当前悬浮通知视觉粗糙，不符合轻量、渐显、上浮和自动消失的目标。

### 任务、目录和资源

- 缩略图生成后缺少随任务移除、清空和退出而同步释放的完整生命周期；
- 原目录和输出目录在无选择时没有稳定回退到列表最后任务；
- 直接拖入文件时输出被平铺到母目录根部，缺少最近公共父目录和相对路径保留；
- 文件夹导入后没有给出实际加入的视频、图片与跳过数量；
- 队列中任务缺少支持多选的“退出队列”入口；
- 列表缺少从 1 开始的自动编号列。

### 裁剪

- “时长 / 画面”命名需要统一为“裁剪”；
- “当前位置”等普通标签存在不必要的灰色底纹；
- 时间轴没有起点和终点标记，也没有起止区间高透明度高亮；
- 时间轴高度不足，层次不清；
- 画面裁剪不能通过鼠标创建、移动和缩放选框；
- 裁剪与旋转缺少明确的源坐标语义，必须保证选择的源内容在旋转后随画面移动，而不是按旋转后象限重新裁剪。

这些问题证明：自动坐标测试、原生截图存在和构建成功不能替代用户人工视觉与交互验收。v4.5.1 的持久化成果保留在稳定线，但产品版本不正式发布。

## 后续处理

所有用户实机问题已经统一写入：

- `Mediova_v4.5.2_实机反馈修复规格.md`

v4.5.2 将按基础 UI、列表与生命周期、导入目录与通知、裁剪编辑器、真实 Windows 收口五轮推进。完成自动化后仍必须重新提供验证 EXE，由用户真实桌面确认后才能决定是否正式发布。
