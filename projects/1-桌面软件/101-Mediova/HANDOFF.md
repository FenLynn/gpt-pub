# Mediova 对话接续入口

本文件用于在更换 ChatGPT 对话后恢复 Mediova 项目上下文。

- 仓库：`FenLynn/gpt-pub`
- 项目路径：`projects/1-桌面软件/101-Mediova/`

## 接续方式

用户可能会同时提供上一轮对话的交接记录，也可能只提供本文件链接。

### 用户提供了上一轮记录

先阅读用户提供的记录，用于快速了解最近完成的工作、当前断点和待处理事项。

随后仍须读取项目文档并检查 GitHub 状态，确认记录中的分支、提交、PR、CI 和 Release 信息是否仍然准确。不要要求用户重复已经在交接记录中说明的内容。

### 用户没有提供上一轮记录

直接按照下面的读取顺序，从仓库恢复上下文，不要求用户重新回忆或转述之前的工作。

## 固定读取顺序

依次读取：

1. 仓库根目录 `GPT_RULES.md`
2. `projects/1-桌面软件/开发约束.md`
3. 本项目 `开发约束.md`
4. 本项目 `README.md`
5. `阶段记录.md`
6. `工作记录.md`
7. README 中列出的当前版本规格、验证说明和版本工作记录

随后检查与 Mediova 有关的当前分支、最近提交、开放或最近合并的 PR、相关 CI、正式标签与 Release。

## 信息使用原则

用户提供的上一轮记录和旧聊天内容用于快速定位上下文，但不作为最终事实依据。

项目文档用于恢复背景，Git、PR、CI 和 Release 用于确认真实状态。若交接记录、项目文档和实际仓库状态不一致，应以实际仓库状态为准，指出已经滞后的记录，并避免重复已经完成的工作。

## 接续后的首次回复

完成读取和核对后，先向用户说明：

- 当前正式版本和开发阶段；
- 最近已经完成的工作；
- 尚未完成或尚未实机验证的内容；
- 准确的继续工作断点；
- 本次是否进行了任何写入。

用户只要求接续或确认状态时，不得修改代码、文档、分支、PR、标签或 Release。

当前工作内容、提交、CI 和后续计划继续记录在原有 README、阶段记录、工作记录及对应版本文档中，不在本文件重复维护。
