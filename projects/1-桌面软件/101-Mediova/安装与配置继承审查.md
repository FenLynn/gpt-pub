# Mediova 安装与配置继承审查

## 范围边界

本审查只覆盖两类场景：

1. 全新安装后的默认行为、首次保存与再次启动；
2. 用户已有原软件配置时，对配置内容、组件路径和使用偏好的继承。

产品旧名称、目录改名和品牌迁移不再作为后续开发问题，也不再为此增加新的兼容分支。已有兼容代码保持不动，除非它实际阻断新装或原配置继承。

当前所有成果仅进入 `p101-exp`。正式 v4.5.0 标签、Release、版本号和正式 EXE 均不改变。

## 第一阶段｜原配置内容继承

### 已发现问题

早期软件构建曾以 Go 导出字段名保存配置，例如 `Resolution`、`Codec`、`Concurrency`、`UseGPU` 和 `RestoreSession`。

原加载器先创建一份新版本默认配置，再仅在当前值为空或为零时复制旧字段。由于大量默认字段本来就非空，用户原有的分辨率、编码器、质量、并发数、界面模式、文件命名、冲突策略、图片参数和多个布尔选项可能被默认值静默覆盖。输出路径等空字符串字段通常仍能继承，因此问题不容易被发现。

### 修复原则

- 仅当配置中实际存在旧版 Go 字段名时执行一次性升级；
- 现代 snake_case 配置保持字节级不变，不因启动而重写；
- 全新安装不主动制造 `config.json` 或迁移标记；
- 旧字段中的 `false`、`0`、空列表和非默认值均按“明确用户选择”处理；
- 混合配置中先读取现代字段，再以明确存在的旧字段为准；
- 升级前永久保留一份原始 `config.json.legacy`；
- 主配置损坏但 `.bak` 有效时，可从旧格式备份继承；
- 原版 v2.8.4 配置位于当前数据目录时直接继承，不依赖产品名称或目录改名路径；
- 不改变正式版本号、会话 schema、媒体处理逻辑、正式标签或 Release。

### 自动验证矩阵

- 全新安装无配置时返回正式默认值，不创建伪配置或 `.legacy`；
- 首次保存后重新加载，输出目录、图片目录、分辨率、编码器、质量、并发数、会话恢复开关和播放器路径完整回读；
- 旧 Go 字段配置完整继承视频/图片路径、最近目录、媒体参数、队列参数、界面状态、列宽、FFmpeg、播放器、GPU、历史、通知和图片参数；
- 旧配置中的 `false` 值不会被新默认值重新开启；
- 损坏主配置可从旧格式 `.bak` 继承，并保留实际用于迁移的原始内容；
- 现代配置启动前后保持字节级一致；
- 原版 v2.8.4 配置在当前数据目录中直接映射为当前设置；
- 独立固定清单 `INSTALL_CONFIG_FILES_SHA256.txt` 校验迁移源码、Windows 启动入口和测试文件。

## 第二阶段第一轮｜主配置最近有效副本与恢复状态 UI

### 已发现边界

原子保存过程中的 `.bak` 主要保护当前一次写入，但成功保存后短期备份会被删除。若主配置随后因磁盘、杀毒软件、异常写入或人工破坏而失效，启动时可能没有长期有效副本可用。此外，配置恢复和继承曾主要在后台发生，用户无法从界面确认本次启动是否使用了恢复路径。

### 已实施

- 启动正式加载前验证 `config.json`；
- 有效主配置刷新独立的 `config.json.lastgood`；
- 主配置缺失或损坏时优先使用 `.bak`，其次使用 `.lastgood`；
- 损坏主文件隔离为 `.corrupt`、`.corrupt.1` 等，不静默覆盖原证据；
- 主配置、`.bak` 和 `.lastgood` 均无效时明确报告，不把损坏文件伪装成默认配置；
- 全新安装无配置时不创建主配置、备份或迁移标记；
- 配置恢复、配置继承或目录不可用的信息写入统一启动状态；
- 主窗口就绪后可在状态栏一次性展示，正常新装和普通启动不显示额外提示；
- 状态文字合并多余空白并限制为 220 个字符，避免窄窗口底部失控；
- 新增 `CONFIG_RESILIENCE_FILES_SHA256.txt` 固定源码清单。

### 自动验证矩阵

- 全新安装不制造任何配置文件；
- 有效主配置生成并刷新最近有效副本；
- 损坏主配置从 `.bak` 恢复并保留 `.corrupt`；
- `.bak` 无效时从 `.lastgood` 恢复；
- 有效主配置永远优先，不被旧备份覆盖；
- 三份均无效时报告不可恢复错误并保留原文件；
- 启动状态文本的空值、换行、长度边界和中文截断；
- 旧安装配置固定清单与本轮配置韧性固定清单同时生效。

## 第二阶段第二轮｜FFmpeg 与播放器路径继承

### 设计原则

用户明确保存的外部组件路径属于用户配置，不应因为 Runtime 或自动检测存在而被静默覆盖。路径继承需要区分“明确有效”“可以无歧义规范化”和“当前不可用”三类状态。

### 已实施

- 有效 FFmpeg 或播放器文件路径原样保持权威；
- 旧配置若保存 FFmpeg 目录，仅在目录本身或其 `bin` 子目录存在完整 FFmpeg/FFprobe 对时规范为 `ffmpeg` 可执行文件；
- 配置误指向同目录 `ffprobe` 时，仅在完整组件对存在时规范为同目录 `ffmpeg`；
- PotPlayer 目录仅在其中实际存在播放器可执行文件时规范化；
- 无效外部路径不清空、不替换，继续保留供用户修复原位置；
- 外部路径当前不可用时，状态信息说明软件将尝试 Runtime、自动查找或系统默认播放器；
- 只有路径发生无歧义规范化时才保存配置，并刷新最近有效副本；
- 新增 `COMPONENT_INHERITANCE_FILES_SHA256.txt` 固定源码清单。

### 自动验证矩阵

- FFmpeg 直接目录；
- FFmpeg `bin` 子目录；
- 误存为 `ffprobe` 文件；
- 无效 FFmpeg 路径保持原值；
- PotPlayer 目录规范化；
- FFmpeg 与播放器混合继承；
- 两类路径均为空时不产生变化或提示。

## 第二阶段第三轮｜启动状态 UI 优先级

### 已发现边界

启动配置提示具有诊断价值，但不能覆盖转换进度、队列变化、任务失败、搁置编辑或参数应用等更高优先级的实时状态。单纯延时显示仍可能在用户快速操作时抢占状态栏。

### 已实施

- 根据内容将提示区分为 `配置状态` 和 `配置提醒`；
- 含“未完成、不可用、异常、损坏、失败、错误、只读”等内容时作为提醒；
- 提示始终保存在运行时诊断字段中，即使未显示也不丢失；
- 仅当状态栏为空、就绪、准备就绪或等待添加任务时展示；
- 正在转换、队列加入、任务失败、搁置、参数更新等实时消息绝不被覆盖；
- 启动时已有活动状态则短期等待，始终不满足时主动放弃显示；
- 保持 220 字符边界，避免长诊断挤压窄窗口。

### 自动验证矩阵

- 信息与警告前缀分类；
- 空值、长文本和中文截断；
- 空闲、就绪、等待任务等被动状态允许展示；
- 转换、队列、失败、搁置和参数应用等主动状态禁止抢占；
- Windows 状态栏延后展示逻辑可完成 GUI 交叉构建。

## 当前结论

三轮工作均已进入 `p101-exp`：

- 原配置内容中的非默认值、`false` 和 `0` 能够继承；
- 主配置具备独立最近有效副本和损坏隔离；
- 用户选择的 FFmpeg 与播放器路径保持权威；
- 可无歧义的目录型路径会规范化；
- 当前不可用的外部路径不会被擅自清空；
- 配置恢复与继承结果具备 UI 可见性；
- 启动提示不会覆盖实时任务状态。

这些结论基于自动测试、全量竞态、静态检查和 Windows 双交叉构建。真实 Windows 原生 Runtime、真实只读目录、杀毒软件占用和用户桌面视觉结果，仍需在提升到 `p101-stable` 前通过原生门禁或实机验证。

## 后续重点

后续安装和 UI 边界只继续检查：

- 新装机器上 FFmpeg/FFprobe 缺失、不可执行或 Runtime 无写入权限时的明确降级；
- 配置目录只读、磁盘满、文件被安全软件占用或首次保存失败时，是否保护原文件并给出稳定诊断；
- 配置、会话和历史文件同时存在时的读取顺序、故障隔离和互不覆盖；
- 便携模式与普通模式切换时，用户数据位置和组件路径是否保持可解释；
- 状态栏提示、底部按钮和窄窗口之间的空间预算与视觉层级；
- 不再扩展产品改名或目录改名兼容。

Windows 原生完整 Runtime 门禁仍只在候选提升到 `p101-stable` 或 `main` 时运行。当前不生成正式 EXE，不启动 v4.5.1，也不改变 v4.5.0 正式基线。
