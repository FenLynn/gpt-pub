# P109 · R71 数据管理与全员/分组右栏结构整改

> 分支：p109-exp。范围：仅 P109 的呈现层、Chromium 回归和项目说明。未修改业务算法、文件结构、raw、人工修订与冻结语义。

## 一、根因

R68 采用“一个数字一个框”，R69 把项目总览合入数据管理但保留了重复右栏，R70 仅靠附加组件和末层 CSS 弱化了卡片。全员/分组区域仍设置 overflow-y:auto，屏幕高度不足时必然出现内部滚动。人数同时在上方工作区工具栏和右栏标题出现。这些是信息架构问题，不是圆角和颜色问题。

## 二、唯一布局

* 顶部系统级：保留五工作区、月份和全局操作，数据页头只显示“数据管理”。
* 左侧：保留“项目状态 / 数据维护”两组分类及原有月历。
* 数据管理右侧：**一个完整主工作区**。不再在各子页并列显示项目状态/文件树副栏，不占用无价值的 240–300px。
* 存储与文件：只有此分类展开真实文件树。目录树来自已连接磁盘，不创建浏览器虚构文件。
* 未连接项目：所有项目类页面统一给出连接/初始化和 ZIP 恢复入口，不呈现虚假持久化数据、空月份表和空右栏。
* 已连接项目：项目概况使用一行无框事实摘要；月份用表格、健康用问题行、存储用构成及实际文件树。名册、规则、模板、历史、冻结均为无框表/列表，原始 Tabulator 正常复用。

## 三、解释性文字

标题、实际数据、状态、告警、错误、操作按钮必须直接可见。冗余说明、来源/统计口径、操作帮助不再常驻：使用带原生 title 和 aria-label 的可聚焦 ⓘ，鼠标悬浮或键盘聚焦可获取。对用户有安全影响的弹窗确认和异常提示不得删除或仅藏于 tooltip。

## 四、全员/分组右栏

右栏仅四个信息层级：考勤概况标题与唯一人数；2×2 无框指标（单位明确为人日/比率）及一条极简状态比例条；每日异常趋势；可切换指标的前五风险排行。删除整块冗余洞察和永久解释小字；细节藏于 ⓘ，完整排行榜保留在统计分析工作区。

右栏严格设置 overflow-y:hidden；但“隐藏滚动条”不是验收完成，**内部 scrollHeight 及排行最后一行、趋势图都要实际落在右栏可视边界内**。按屏幕高度调整图表和排行的尺寸，不牺牲关键字号。标题中的人数只显示一次，顶部工具栏不再重复。

## 五、保护与测试

* 测试 1366×768、1600×900、1920×1080，全员/分组共六种布局，检测右侧 overflow、scrollHeight、末排行及图表位置、唯一人数和字体可读性。
* 遍历数据管理全部十分类，检测左侧菜单、全宽内容区、文字帮助转悬浮、没有重复文件树以及无横向溢出。
* 继续原有 Chromium 业务/统计/导入/时间轴/保存/冻结/独立分支/ZIP 生命周期回归。测试失败不发布成功结论。
* 精确核对最新 exp SHA → P109 CI → Unified Pages 的 P109_SHA → P108 保留 → 部署结论。
* Windows Chrome/Edge 原生系统选目录、真实权限和不同 schema 迁移仍需独立实机验收。

## 六、维护规则

以后不要重新引入“一个数字一个框”、同一事实多处重复、默认解释段落、大块空状态、无意义右栏和全员/分组右栏内部滚动。优先改当前唯一渲染入口和对应测试，避免继续在 CSS 末尾叠加多个相互覆盖的兼容层。
