# AttendScope 数据架构

目标结构：

```text
project.json
config/
data/YYYY/MM/
  raw/
    attendance/<importId>/原文件.xlsx
    leave/<importId>/原文件.xlsx
    trip/<importId>/原文件.xlsx
  imports.json
  working/
    state.json
    revisions.json
    derived/
  snapshots/Fxxxx/
    snapshot.json
  branches/Bxxxx/
  output/
```

`raw` 永不原位修改；`working` 可持续保存；`snapshots` 不可变；历史冻结版本修订时进入 `branches` 子空间。

从 R33 开始，importId 为导入事务的独立键；规范化数据包含 `importId`、`source`、`sheet`、真实 `row`。导入清单尽可能保存 SHA-256。working state 保存该月员工名册、组别、系统/人工判断所需规则及来源记录，snapshot 同时保留冻结的配置与 working 状态。不要向公开仓库提交真实个人数据。

历史说明（R62 以前）：冻结只能创建。**自 R66 起已补上从冻结派生独立 branch 并按分支保存的工作流**；旧版不能据此视为完成迁移。

## R62 · 姓名统一、导入预览、存储恢复、截图与横向 PDF（2026-10-21）

**架构原则：** 现有五个工作区不增加主页；离线、文件优先；持久化原始事实、规范化记录、人工决定、导入配置和规则，不保存可重新计算的整套分析结果。修改仅限 P109 开发分支，不动 P108、main、stable 或共享部署器。

**身份规则：** 姓名是唯一身份，以 Unicode NFKC 规范化并收敛空白；不试图通过工号或闸机编号区分同名员工。同名始终归一为同一人，跨月不再使用排序生成的 E001/E002 作为永久身份。已有月度工作状态载入时迁移员工引用、组别、人工判定及自动加班排除 ID。界面名册仅展示姓名及组别。

**导入方案：** 五类文件均统一从可视化导入向导进入；Excel XLSX、CSV（UTF-8、GB18030/GBK，逗号、分号和 Tab）显示实际源行、列及行号。首行默认作为表头但依然显示在预览里，不计入导入；也可切换表头使用方式、额外跳过开头行。姓名、日期、时间、日期时间、进出、类型、地点、备注等列先自动推断，用户可人工覆盖任意列映射。校验给出有效／跳过行数和失败行号，正式提交前确认。

**进出规则：** 每条规则包括关键字、进或出、完全匹配或部分匹配。默认支持进、出、进1、进2、出1、出2、入口、出口等。完全匹配和最长关键字优先，同优先级冲突则标为无法识别；允许增删规则，并保存在月度 working/snapshot 中。不同闸机只增加关键词，不新增闸机设置或设备主键。

**工作状态：** 月度 working/state.json 是权威主状态；保存前复制上一有效文件到 working/state.previous.json，写回后再次读取核验，重连时如当前 JSON 损坏可尝试恢复上一个版本。顶部“恢复”能加载下载的 working JSON 或冻结 snapshot JSON；派生 analysis 不重复入库。新项目不再主动创建未实现的 branches 目录；原有目录不删除。

**统计口径：** 总加班时长仍按实际时间区间并集，登记加班与已确认自动加班分别显示。增加登记记录数、自动连续会话数、独立加班次数：来源条目数可以大于物理连续加班次数，避免把一段加班误解释为两次。人工 ×／✓ 决定优先，原始打卡始终不修改。

**导出／截图：** 保留 Excel 明细导出，新增带 BOM 的 UTF-8 CSV。支持矩阵、统计图、个人时间轴 PNG 截图；当前可见的 ECharts 图使用原图高分辨率导出，批量无可见图时使用相同数据绘制的归档图，避免网络依赖。有本地项目目录时保存在 data/YYYY/MM/output/captures；否则浏览器下载。截图以月份和毫秒时间戳命名，横向 A4 PDF 一页一图、等比例居中，可一键合成已有截图或新生成三类报告图片。

**风险边界：** 名字完全相同的不同现实员工将按照用户的明确规则合并；这是可接受的简化，不宣称具备同名异人识别。已保存的规则不会被升级静默覆盖。截图批处理生成图属于归档重绘，与浏览器窗口逐像素截图可能存在细微样式差异。未连接目录时工作状态／截图备份依赖用户保存本地下载文件。

**验收：** CI 必须运行原有全员、组别、个人、统计、规则和时间轴完整 Chromium 回归，并额外覆盖 CSV/XLSX 日期、首行预览、姓名稳定键、完整匹配与部分匹配、人工设置、PNG 和 A4 横向多页 PDF。成功的 GitHub Pages 部署需核对准确源码 SHA。

## R67 补充：已验收的目录与数据边界

现行持久化继续使用 data/YYYY/MM/，不在缺少逐版本迁移的情况下直接重命名真实项目目录。

data/YYYY/MM/ 下面 raw/type/importId/原文件不可变、working/state.json 和 state.previous.json 可更新；snapshots/F.../snapshot.json 不覆盖；branches/B.../branch.json 和 branches/B.../working/state.json 为独立派生修订工作区。parentSnapshotId 记录来源冻结。project.json 记录 current、activeBranch、months，健康扫描从磁盘枚举目录来交叉核对，索引补缺必须人工批准并先备份。

config/project-profile.json 是用户显式固定的名册、组别、列映射/关键词模板和考勤时段默认；historical working 的个人和计算规则优先于项目默认，新建月份时才选用显式固定的模板。

项目健康扫描可查 working、previous、快照、分支、索引、raw 存在性与部分 SHA-256 值。它不自动修改事实、不会悄悄把重名人合并成同一班次、也不会自动将孤立原始目录写进导入清单。

完整 ZIP 使用 manifest + SHA-256；原始文件、工作及冻结/分支随整个项目目录备份。为了防止 ZIP 无限套娃，备份不重复包含旧 backups/。仅使用可信来源的代码更新包，升级器拒绝对 data、config、project.json 动手。
