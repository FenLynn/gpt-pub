# R85 · 环境兼容与便携项目

版本：0.2.11-preview，数据 schema 2。只维护 p109-exp 的 P109，不提升 stable/main，不创建正式 Release。

## 设计目的

纯 HTML 需要浏览器授权才能直接读写目录。目录 API 缺失、权限撤销、只读磁盘、浏览器历史存储禁用是不同问题；不能仅在启动时检查 API 存在便宣称环境可用。

R85 统一提供三层工作方式：

| 方式 | 使用条件 | 保存与继续 |
|---|---|---|
| 目录项目 | 可选择并授权读写目录 | 保存当前月 working；下次恢复已授权目录 |
| 便携项目 | 可读取本地文件并下载，支持安全哈希 | 下载完整项目 ZIP；下次手动打开最新 ZIP |
| 工作状态救援 | 完整文件不可读或哈希不可用，但可下载 JSON | 保留所有已加载月份的状态；不含原件和未加载冻结/修订 |

便携模式通过内存目录适配器复用现有的文件路径和业务读写逻辑。导入、原件追溯、月份、冻结、修订都沿用同一结构，不另外维护一套精简计算引擎。内存适配器不被当作浏览器可持久保存的真实目录句柄。

## 第一次使用便携项目

1. 完整解压程序，打开 index.html，选择 Work。
2. 选择“新建便携项目”，确认建立空项目。名册和业务数据应为空。
3. 选择月份并导入源表，检查原件、合并记录、统计与人工处理。
4. 点击顶部“保存”。程序生成完整项目 ZIP，并打开下载确认窗口。
5. 检查浏览器下载目录，确认 ZIP 实际存在。点击“我已确认文件下载完成”。取消下载、下载被阻止或找不到文件时不要确认。
6. 下次打开程序，从 Work 的“打开项目 ZIP / 救援 JSON”选择最新包，核对月份、原件和人工处理后继续。

便携项目不会自动从下载目录重新读取，也不以浏览器缓存代存业务。转便携时保留最近目录，但清除原目录的默认打开状态；下次没有默认 Work 项目时显示 Demo / Work，不擅自重开以前的其他目录。下载确认只是用户对文件落盘的确认；浏览器没有可靠 API 让网页验证任意下载文件的真实落盘结果。打包后又有业务变化时，旧确认不能清除新修改，必须重新打包。

## 目录写入中途失败

保存、连接、初始化、冻结和目录备份失败时统一提供重新授权、转便携并下载、打开已有项目包、新建便携和救援 JSON。取消或失败保留当前会话。

导入验证只检查文件内容。确认导入需要另外保存原件，因此可能验证通过却遇到目录写入失败。预览会保留原文件、字段和目标月份；选择“目录不可写？转为便携模式后重试”，转换成功后再次确认同一文件，无需重选源表。失败前已有导入和工作内容保留，新导入的原件只在成功后纳入工作。

转换时先读取可用原项目，再叠加全部已加载月份的最新内存状态和本次导入原字节。不会回写原目录。任何文件不可读、已登记原件缺失或与登记哈希不一致时，拒绝标为完整，并提供救援 JSON。

冻结在便携项目内生成新的不可变快照后，项目标记为待下载；必须再次下载完整包才带走新快照。快照只创建不覆盖，普通 working 编辑也不追改已有快照。

截图/PDF 共用输出持久化入口：目录写入失败时自动下载已生成文件，提示实际检查下载，不假称目录写入成功；目录中的旧截图读取失败时，PDF 仍列出本次页面截图。便携模式将输出加入内存项目并标为待下载，不影响考勤事实的保存口径。

## 备份边界

| 文件 | 包含 | 不包含 / 限制 |
|---|---|---|
| 目录完整项目备份 ZIP | 磁盘中已保存的项目文件 | 尚未保存的内存修改；有未保存月份时会提示 |
| 完整便携项目 ZIP | 可读的项目文件、全部已加载月份最新工作、原件、可读冻结与修订 | 不递归嵌套 backups；原件缺失时拒绝生成 |
| 工作状态救援 JSON | 所有已加载月份的人员、业务记录、规则、人工处理与项目默认配置 | 不含原始文件字节、未加载冻结/修订，不解除未保存提醒 |
| 月度 working / snapshot JSON | 单个月份的工作或冻结状态 | 不含全项目原件，不是完整备份 |
| 程序升级 ZIP | index.html、src、说明和发布清单 | 不含用户项目数据 |

便携 ZIP 仍使用现有 p109-backup-manifest.json：逐文件字节数和 SHA-256 校验，兼容“恢复整个项目 ZIP 到空目录”。打开坏包、普通 ZIP、程序升级 ZIP、重复路径或未来数据 schema 时，不替换当前项目。

完整项目上限为 5000 文件、160 MB 内容；读入项目包上限 180 MB。大项目需通过系统文件管理器整体备份。SHA-256 证明完整性，不是发布者身份签名。

救援 JSON 可从“打开项目 ZIP / 救援 JSON”恢复，并显示“救援工作区”。请继续保留原目录和源表。若原件丢失，救援记录无法凭空还原源文件；缺失原件应按其登记路径恢复准确原字节，不能用改过的文件冒充旧证据。

## 其他环境能力统一处理

环境卡片仅出现在“数据管理 → 存储与文件”，不增加常驻路径或警告栏。

| 能力受限 | 处理 |
|---|---|
| 没有目录 API | Work 提供便携新建与打开；保存完整 ZIP |
| 有 API 但权限/写入失败 | 保留未保存状态，提供重新授权或便携/救援 |
| IndexedDB / localStorage 禁用或写入失败 | 手动打开项目；不阻止业务，不用错误的旧目录替代便携项目 |
| 压缩 XLSX 解压不可用 | 另存 CSV 后导入；CSV 不需要该 API |
| 剪贴板失败 | 显示选中文本，用 Ctrl+C 复制目录路径 |
| SHA-256 不可用 | 拒绝无法校验的项目/升级 ZIP；提供救援 JSON |
| 下载 API 不可用 | 明确报告不能落盘，保留未保存提醒和当前页面 |
| API 存在但实际下载被浏览器拦截 | 用户检查文件后才确认；不能仅因触发下载就标记已保存 |

浏览器完全禁止写入和下载，或系统断电、强退时，网页不能保证保存。应恢复下载/授权能力并保持页面，不宣称存在能绕过权限的后台方案。核心 JavaScript、本地文件读取和现代浏览器仍是运行前提，不承诺旧版 IE 等环境。

## 升级与迁移

入口保持右上角“导入 → 程序升级 ZIP”。可写环境继续自动校验、备份、更新、逐项核验和重载；R84 的版本比较、恢复日志和失败回滚保留。

使用便携项目也能授权真实程序目录进行升级。备份落到程序目录的 backups，不能只写进页面内存后就重载。所有未下载确认的便携变化仍阻止升级。

没有程序目录写入能力时：先下载确认完整项目包，保留旧程序，把新版离线程序完整解压到新的可写文件夹，打开新版，手动载入该项目 ZIP。目录项目也可在新版连接原数据目录。纯 HTML 无法自动替换一个没有写权限的旧程序目录，这个分支必须保留人工解压步骤。

## 验证与边界

`tests/r85-audit.cjs` 使用真实浏览器下载、ZIP 字节往返和原生 OPFS 文件流，覆盖：

- 同时禁用目录 API、IndexedDB、localStorage 的空项目 → 导入 → 冻结 → 两月份保存 → 关闭页面 → 重开。
- 原件字节、人工判断、冻结字节不变；原件可浏览。
- 下载开始不清除未保存；打包后再修改不能用旧确认清除。
- 坏包保留当前项目；缺原件拒绝完整包，救援包含所有已加载月份并可重开。
- 无哈希、无下载、无 XLSX 解压；CSV 可继续导入。
- 目录保存失败后转便携，保留内存修改且原目录字节不变。
- 目录写入失败时截图和 PDF 自动下载，核对真实 PNG/PDF 字节。
- 同一失败导入预览转便携后重试，旧数据与新原件都保留。
- 便携项目更新真实浏览器程序目录，备份落盘且不误调用原生句柄比较。

完整 smoke 继续覆盖 R78–R84、准确旧 R77/R83 升级、业务/隔夜加班、教程、布局和生命周期。自动化使用 OPFS、临时目录及能力/故障注入；不能代替 Windows 外部系统目录授权、系统下载策略和真实磁盘故障的实机验收。最终结论以准确提交对应的 CI 为准。
