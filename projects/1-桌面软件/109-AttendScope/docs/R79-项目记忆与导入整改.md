# R79 · 项目记忆与导入整改

版本为 `0.2.5-preview`，数据 schema 仍为 2，引擎标记提升为 R79。修改限于 P109。

## 项目与代码

推荐目录关系如下，项目不必位于程序旁边：

```text
考勤程序/
  index.html
  src/
考勤项目甲/
  project.json
  config/
  data/
考勤项目乙/
  project.json
  config/
  data/
```

新建项目只接受独立空目录。已有的同目录安装不迁移、不删除，继续允许连接。代码更新在分离模式下明确选择程序目录，先将当前项目和旧程序备份到项目的 backups，再只更新程序文件。普通完整项目备份只打包该项目；它不是浏览器最近项目列表的备份。

## 最近项目与启动恢复

IndexedDB 的独立数据库保存已授权目录句柄、显示名称、最近打开时间和上次项目标识，不把考勤业务数据搬入浏览器历史。首次使用新版需要连接一次已有目录。

启动先检查已存句柄的读写权限。权限有效时走正常项目校验、整体载入路径；权限需要确认时显示“继续打开”，由明确点击调用 requestPermission，不在启动时自动弹授权。失败、取消、目录搬动或损坏不替换当前工作状态。用户已开始操作时不再让延迟的启动恢复抢占工作区。

项目菜单展示最近五项，管理页展示全部。按目录的 isSameEntry 去重，目录同名仍独立。显示名称可改，移除仅删除浏览器历史记录。浏览器配置隔离、站点数据清理和权限撤销可能使自动恢复需要重新授权或重新选目录；磁盘项目不因此删除。

对应 API 依据：[Chrome File System Access](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)、[持久权限说明](https://developer.chrome.com/blog/persistent-permissions-for-the-file-system-access-api)。

## 导入的月份和业务校验

原问题已由实际反馈确认：选择9月，导入10月文件，旧预览仅检查格式，所以显示可导入；提交再筛月份，才抛出“未识别到本月有效考勤记录”。

R79 预览和提交共用 `p109ParseBusinessRow`。预览明确显示目标月份、文件日期范围，自动校验月份和有效时间区间。文件的主要月份不同则提供显式切换入口。选择目标月份只改变导入草稿，确认后才打开或新建该月；取消和权限失败保留原月份、名册和业务记录。

考勤允许前后各一天用于跨月配对。出差/外出要求日期区间与目标月相交；请假要求同日有效起止，加班允许明确的跨午夜结束时刻。部分行失败时必须确认跳过；没有有效行时禁用导入。

原始文件成功保存后才提交名册和工作数据。新导入的原件写入失败时，尝试清理本次新建的 importId 目录；历史原件不覆盖。错误显示在弹窗中并提供重试。

界面默认只展示必要字段、日期范围、预览和导入操作。表头、跳过行、编码、映射复用及自定义进出规则放入“更多选项”。恢复已有复杂规则仍受支持。

## 其他发现与修复

- XLSX 使用 XML 的 local name 读取，接受标准命名空间前缀，不再将带前缀的合法表误当空表。
- Excel 序列日期先按秒舍入，避免浮点误差使19:00变成18:59:59。日期和时间有明确分列表头时优先采用分列映射。
- 外出地点保留映射；时间保留输入中的有效秒。
- 漏刷末次出卡后，次日再次进入且超过既定重复刷卡窗口，不再把前一进入延续到次日出卡。旧会话按不完整证据待核，不推算整晚加班。正常完整跨日/跨月进出会话和20分钟阈值继续回归。

## 验证范围

`r79-audit.cjs` 用独立浏览器上下文和本地 HTTP 测试服务调用浏览器原生 OPFS 句柄、文件流和 IndexedDB：覆盖空项目、9月/10月错配、取消、实际写入、页面重载自动恢复、同名目录区分、切换、改显示名、仅移除历史、授权提示分支、写入权限失败和重试、秒级日期与分列识别、漏刷加班修复、窄屏主操作、独立程序目录更新及双目录备份。

该 HTTP 服务仅用于自动化验证 OPFS，不是离线软件的运行依赖。OPFS 在 file origin 下受限，因此该测试不能替代外部磁盘目录的操作系统选择器、实际权限撤销和浏览器原生授权弹窗验收。file:// 的程序启动、业务、保存冻结、还原、跨版本升级和 UI 由完整 smoke 与真实临时磁盘接口桥接另行覆盖。不得把模拟授权分支写成原生外部权限已通过。

历史升级继续使用真实 R77 提交 `71caeaa99b7eb41b71ee457d1334a8bcff2de561`，核对原件、working 和冻结文件的保留。旧同目录项目与新建独立数据目录分别验收。

本地 Edge 155 完整 smoke、R78 专项、R79 专项、生命周期与界面审计通过，离线页面零远程请求、零运行时错误。另逐个导入五份 XLSX 和五份 CSV：均为20人、1430条打卡及相同业务分析，漏刷用例改为待核、自动加班0分钟。独立临时浏览器配置还验证了关闭整个浏览器后重启、从 IndexedDB 恢复 OPFS 项目的路径；该项仍不等同于外部目录的系统授权验收。

本轮只提供 `p109-exp` 候选及本地离线包，不提升 stable/main，不建立正式标签或 Release。最终测试和 CI 状态以对应源提交为准。
