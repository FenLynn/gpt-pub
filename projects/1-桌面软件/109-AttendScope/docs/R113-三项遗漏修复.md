# R113 · 三项遗漏修复

版本：0.2.39-preview；普通工作数据schema 15。仅修改P109，不新增管理模块。

## 1. 上午到岗证据

旧问题：同一天先有00:10进、00:30出，再有08:50进，全天最早的00:10可能使上午迟到漏标。只有夜间与下午记录时，也可能漏掉“上午缺少完整出勤证据”。

本版仅在上午到岗判断中，排除已经在上午上班点之前结束的完整访问；采用后续有效进卡判断。真实连续在岗跨越上班点仍算有效，包括前一晚进入、当天上午离开的完整访问。未闭合早进记录不被武断删除；原始卡、全天首进、在岗时长和临时外出另按原口径保留。报备覆盖、请假晚返只计临时外出和人工确认为正常的统计约定不变。

旧冻结缺少新规则版本时按历史口径，普通工作补入新规则并提示核对保存。新配置声明最低版本0.2.39-preview，防止旧程序误读。

## 2. 无法直接写程序目录时升级

程序包仍须先通过项目标识、版本、结构、文件哈希与数据格式兼容校验。不支持目录选择时不再显示无效操作按钮；支持选择但授权失败时也显示备用步骤。重新授权成功会恢复正常安装流程。

备用操作：

1. 保存当前工作。保存到浏览器缓存后，仍需下载完整项目ZIP，确认文件实际落盘。
2. 将校验通过的**程序升级ZIP**完整解压到一个新目录，保留旧程序与项目备份。
3. 打开新目录的index.html，选择Work，打开刚才确认下载的**项目数据ZIP**，核对月份、名册、原件和人工处理结果。

向导提供“下载完整项目备份”。程序包和数据包用途不同，不能相互代替。不支持写入的浏览器不会被描述为已经自动更新。

## 3. 缓存内容损坏后的恢复

缓存校验不仅包括外层SHA-256，还包括ZIP内容、项目配置、月份与工作状态结构。最新缓存哈希正确但内部配置损坏时，也尝试同项目上一份有效缓存。

- 恢复上一份时显示其保存时间，并保持未保存提醒；用户须核对、保存并下载独立备份。
- 保存恢复结果时，不将已识别为坏的当前缓存覆盖到上一份好缓存上。
- 多页面保存冲突检查继续有效，不能用旧页面覆盖新保存。
- 新程序版本或新缓存格式不会静默回退；不同项目的上一份不会被当作本项目恢复。
- 两份均无效时保留缓存记录，不自动清空；恢复过程中被取消则不接管当前页面。

缓存仍只是当前浏览器中的便捷工作副本，不能代替磁盘备份。清理站点数据后必须靠独立项目ZIP恢复。

## 验证范围

新增r113-audit.cjs覆盖上午独立夜间、真实跨夜、班前短访问、宽限秒边界、报备与人工处理、旧冻结和ZIP重开；缓存结构/哈希损坏、重保存保护、未来版本及取消；无目录API、授权失败、授权重试、损坏升级包拒绝与真实备份下载。历史兼容与生命周期回归继续运行。

现代浏览器移除部分API后的降级检查不能替代原生Win7系统验收。Win7/360的既有用户成功反馈不等同于本次已在该系统全面实测。
