# R109 · 早退与孤立卡隔离

版本0.2.35-preview，工作格式schema 11。

## 修复的问题

原先上午早退使用全日的配对不确定状态；下午早退则会被当天任意未闭合进入记录阻止。因此添加一张无关夜间卡，就可能把明确早退降为待核，漏掉早退次数。

| 原始证据 | 添加的无关记录 | R109 |
|---|---|---|
| 08:30进、11:20出；下午正常 | 23:00孤立出 | 上午早退保留 |
| 同上 | 22:00未闭合进 | 上午早退保留 |
| 上午正常；13:30进、16:50出 | 22:00未闭合进 | 下午早退保留 |

夜间记录和缺卡提示仍保留；不会删除卡、补造进出或虚构加班。此次只缩小早退判断受不相关异常影响的范围，完整配对与工时计算没有改写。

## 判断边界

上午的配对不确定仅在本班次及可调返岗窗口内影响明确早退；下午仅由本班次内未闭合进入保留原待核保护。班后返回是否足够短，仍由实际离岗至返回的间隔判断，不能仅因返回时间离班末近就豁免。例如16:50出、17:15进且未闭合，是25分钟离岗，不因其只比17:10晚5分钟而抹掉早退。

班内未知方向或缺卡仍可要求待核。没有完整下午出勤对时，不能把上午的最后出卡当成下午早退。默认10＋2分钟短窗口、秒级边界、连续重复卡不无限续窗、请假/出差/外出报备覆盖、人工正常与单项×/恢复保持有效。

## 数据兼容

新增`earlyDepartureRuleVersion`：2为新规则，1保留原全日关联规则。旧普通工作缺少此字段时迁移为2并标记未保存；旧冻结及修订保留1，在规则页明确应用后才启用2。原冻结文件不改写，新配置最低程序版本为0.2.35-preview。新程序包支持schema 2–11；旧程序拒绝回写新工作。

## 验证

- 原6000组随机、14408项逐秒扫描、36项定向用例全部作为必须通过的断言；先前4项独立诊断中的3处漏标已修复，没有再通过豁免失败来放行。
- 新增专项覆盖晨晚孤立进/出/未知、正常日不新增早退、短/长返岗、班内不确定、多个未闭合记录、可调早退宽限、三类报备优先、旧冻结、无效规则、人工处理、原始打卡与工时不变和真实项目ZIP重开。
- 所有压力样本单人每天最多50卡，上午下午对称。构造样本的通过情况不能当作真实业务零风险证明。

本轮解决的是已确认的早退漏标问题。此前的同秒冲突行序、下午超两小时迟到漏标、重复出卡缩短外出、陈旧午夜证据等其他问题仍需分别处理，不计入本轮修复结论。
