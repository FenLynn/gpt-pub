# P109 · R65–R67 全生命周期与项目健康总控

更新：2026-10-21。分支：p109-exp。内部 ID 仍为 \`P109-AttendScope\`，用户显示默认名称「考勤」，可在设置中修改。

## 操作入口

下载 CI 生成的「P109-考勤-R67-可更新离线版.zip」（注意，只有该 ZIP 是干净的首次安装包；git 仓库目录里另有演示数据配置）。解压后直接双击 \`index.html\`，无需安装 Python/Node、联网或 CDN。未连接工作目录时，应用顶部提示「演示 · 待初始化」；点击「初始化」或「目录」，选择用于长期保存项目的文件夹，再确认创建空白项目。初始化后立即创建空名册和本月工作状态，不将演示人员作为真实员工。

已有目录通过「目录」重新连接，软件读取项目 ID、月份索引、月度 working/previous、人员与考勤规则，并自动进行项目健康检查。若选择没有 \`project.json\` 的目录，会要求用户确认初始化，避免悄悄将任意文件夹设为项目。对更高数据 \`schemaVersion\` 的项目拒绝用旧代码写入。

## 「项目」总控面板

扫描**始终只读**，从磁盘实际 \`data/YYYY/MM\` 中重建索引，而非只相信 \`project.json.months\`。面板集中展示：当前工作月份与保存状态、已保存月份、人员数、导入次数、人工修订数、冻结数量和冻结 ID/时间、独立修订副本数量、原始文件数及健康问题。可手动重新扫描。

健康检查至少覆盖：
- 未初始化、选错项目、无法解析 project.json、版本不兼容
- 月份索引缺漏、索引指向不存在目录、当前月份目录缺失
- working/state.json 损坏、可用 previous 备用版本、内部年月与目录不符
- 导入清单对应的原始文件缺失、孤立未登记原始目录
- 有 SHA-256 的较小原文件重新计算哈希（每个不超过 16 MB、单轮至多 120 个）；其他文件标明未校验，不将「未验证」等同「健康」
- 冻结文件损坏、冻结 ID/年月元数据不一致、独立修订副本的工作状态损坏
- 员工空名、规范化重名或重复 ID、旧版配置格式警告

**安全整理边界**：只允许有用户确认时把磁盘上已经存在且 working 完整的月份补入项目索引。整理前备份 \`project.index.previous.json\`；有同名备份时拒绝覆盖。不做原件合并、不修改打卡时间、不删除孤立文件、不合并不一致的多个 working、不改写冻结。其他健康问题由用户基于备份人工解决。

## 项目级「可选固定」

点击项目面板中的三个独立选项：固定当前人员名册/分组、固定当前导入规则/映射模板、固定当前考勤时段/加班门槛。明确确认后保存在 \`config/project-profile.json\`。新建月份优先采用**显式固定**的配置；历史月份仍以各月 working 为准，既有配置不会被升级静默覆盖。

导入弹窗中的「此映射下月复用」会保存列映射、表头和识别模板；仅在下一文件表头与列名一致时自动复用，否则重新推断，不强行错位套用。进出规则继续支持完整和部分匹配。

## 保存、冻结、独立修订

- 保存：写入 \`data/YYYY/MM/working/state.json\`，原有效版优先备份为 \`state.previous.json\`，写入后读取核验；raw 源文件按 importId 独立保留。
- 冻结：新建 \`snapshots/F.../snapshot.json\`，唯一 ID 不可覆盖。
- 从冻结继续编辑：展开冻结版本，点击「派生修订」，建立 \`branches/B.../working/state.json\` 和 \`branch.json\`，保存时仅写分支工作状态，不改原月份 working 和冻结文件；项目标识记录 activeBranch，重连后重新进入该分支。可显式返回主工作状态；子快照保存 parentSnapshot 来源。
- 注意：项目目录直接手工被外部应用移动/删除时，浏览器需要重新选择目录；版本控制不替代整盘备份。

## 完整 ZIP 备份与恢复

在「项目」点击「备份整个项目 ZIP」，扫描文件总数/大小上限为 **5000 文件或 160 MB**。ZIP 附带独立 \`p109-backup-manifest.json\`，记录每个文件大小和 SHA-256。包括目录中实际存在的程序、config、project.json、data 原件、working、snapshot、branch 和 output；**不再重复打包旧 backups/ 子目录**，防止备份无限套娃。浏览器不能读取权限外的文件，需先连接正确项目目录。

恢复时先选空目标文件夹，再选择 ZIP；拒绝不含清单、身份错误、损坏或有路径穿越/重复路径的压缩包。全部哈希校验后用户确认才写入。恢复完成重新连接目录，不擅自替换当前工作空间。ZIP 使用浏览器可离线读取的无压缩存储模式（体积可能略大）。

## 离线程序安全更新

项目面板「安全更新程序」接收 \`tools/package-release.py\` 构建的含 \`p109-release-manifest.json\` 的程序 ZIP；仅接受 \`index.html\`、\`README.md\` 与 \`src/\` 的文件，**拒绝更新包修改任何 data/config/raw/working/snapshots/branches/project.json 路径**。校验项目 ID、版本非降级、数据 schema 兼容、每个文件长度与 SHA-256。安装前自动在本地 \`backups/pre-upgrade-*.zip\` 保存并验证完整工作目录；然后逐项覆写源代码、读回校验，错误时尽力回滚已经写过的程序文件。成功后重新打开 index.html 即可运行新代码，数据原目录保持不变。

完整性哈希不是开发者数字签名，因此用户只应从可信的 GitHub 仓库获取发行包。当前已经验证同数据 schema 的代码替换，**没有宣称任意未来数据格式都能无损自动升级**。
