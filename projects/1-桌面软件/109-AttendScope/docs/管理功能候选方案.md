# 管理功能候选方案

以下均为后续方案，R113只修遗漏，不实施新功能。目标是沿用现有“导入预览→字段对应→批量处理→筛选→导出→ZIP备份”，减少重复登记，不扩成复杂人事系统。

## 建议优先做的三项

| 功能 | 解决的问题 | 操作与结果 |
|---|---|---|
| 名单核对与差异清单 | 月月导入后找新人、漏人、同名与组别变化 | 选择基准名册和本月文件，列出新增、缺少、重复、组别不一致；逐项确认或批量加入/忽略，导出待核清单 |
| 人员变动台账 | 调组、入职、停用后，历史月份容易跟着变 | 为变动选生效日期，预览影响月份后确认；历史冻结不改，当前和未来月份按生效范围继承，保留变更原因和记录 |
| 待办与核查闭环 | 异常看过了但不知道谁处理、是否处理完 | 在现有异常上记录待核/已确认/不需处理、经办人和备注；可按组筛选、批量确认、导出未完成事项；原始证据和考勤改判仍独立保留 |

第一项最适合先做：可以直接复用现有名册、忽略名单和导入原件，不增加新的日常录入负担。人员变动涉及历史生效，应放在独立后续版本，避免匆忙改动当前月模型。

## 名单核对：具体如何用

1. 选“现有长期名单”作基准，拖入新的名单或业务表；记住各类型自己的列设置。
2. 对应姓名、可选工号、组别；先看差异，不直接改名单。
3. 分栏显示新增、基准有但文件没有、疑似同人、同名不同人、组别变化。
4. 选择处理：加入全员、加入忽略、关联已有人、保留原组、采用新组、暂不处理。
5. 确认后生成处理记录；导出未处理项，随项目ZIP保存。

文件没出现某个人不等于离职，不能自动删除。同名不得直接合并；若引入工号，应作为可选明确身份依据并安排旧身份迁移，不能只换显示名就声称解决同名问题。

## 不限于考勤的三类台账

| 台账 | 建议字段 | 有意义的管理结果 |
|---|---|---|
| 设备/钥匙/工装借还 | 物品编号、名称、领用人、领用日、预计归还日、实际归还日、状态、备注 | 在借、逾期未还、人员离开但物品未清；同一物品重复借出提示核对 |
| 培训与资格记录 | 人员、项目、完成日期、有效期、附件索引、备注 | 哪些人未完成、即将到期、组别完成率；按批次导入，不要求逐人录入 |
| 通用任务/事项清单 | 事项、负责人、组别、开始日、截止日、完成日、优先级、状态 | 本周到期、逾期、按组未完成数量，以及可导出的催办清单 |

三类台账应有独立模板和数据范围，复用导入、筛选、批量设置和导出能力。没有完成日期不自动认定完成；缺少截止日期不制造逾期。经办人只是本地记录字段，不代表登录身份或多人审批权限。

## 管理概览与月度交接

- **人员概览**：在册、纳入统计、忽略、当月有数据但未关联的人数，点击数字进入清单。分母与月份范围写清，不能把无打卡直接等同离职。
- **业务安排概览**：按日查看各组已报备出差、请假与预计在岗；明确“报备安排”与“实际打卡”两套来源，避免把计划当事实。
- **月结核对单**：提示未处理异常、缺少原件、未保存月份、尚未确认落盘的备份。允许继续操作，不以提醒阻止保存、导入或下载。
- **年度交接**：沿用现有配置导出创建新项目，继承名单、分组、忽略、别名、规则、工作日、导入与文字配置及界面偏好；历史项目保持独立冻结ZIP。新增台账届时明确“只继承模板/在办事项/全部记录”选项，避免把历年已完成事项无意带入。

## 后续实施边界

1. 先做名单差异与核查备注，再做人员生效历史，最后按真实需要选择一种通用台账，不一次加入全部入口。
2. 每次批量处理先显示影响条数；能撤销本次派生修改，原件与冻结不覆盖。
3. 配置、台账与人工处理都进入项目ZIP；支持旧版打开前的版本提示和升级后重开核对。
4. 继续以单人离线工作为基础。项目ZIP不具备多人实时协同和权限审计，不能把经办字段包装成多人系统。
