# R84 · 升级与发布前校核

版本 0.2.10-preview / R84，数据 schema 2。本轮仅修改 P109 与自有 CI，候选停留在 p109-exp。

## 操作路径

右上角导入 → 程序升级 ZIP → 选择升级包 → 首次授权程序文件夹 → 开始升级 → 完成并重新载入。包不需要解压；目录授权属于浏览器要求，不能由纯 HTML 自动跳过。已授权程序目录通过 IndexedDB 记住，权限有效且版本吻合时可复用。取消选择或拒绝授权不改变项目。

未连接项目也能更新程序；已连接项目时同时备份项目和程序。任何非 Demo 工作月份尚未保存都阻止安装，避免只备份磁盘却丢掉内存工作。

R83 用户第一次装入 R84，需要从旧版项目菜单的原有升级入口进入；旧页面不会在未更新前出现新按钮。R84 以后统一使用导入菜单。

## 事务与版本

- 程序包须具备 P109 标识、受支持的格式和数据 schema、语义版本、完整文件清单、字节数和 SHA-256。程序内部版本须与清单一致，入口引用的所有本地资源须包含在包中。
- 语义版本区分预览后缀与正式版本，数字预览序号正确排序，构建元数据不影响先后。拒绝旧版覆盖；相同版本允许修复。未来格式和最低升级器要求不满足时停止并提示过渡版本。
- 升级前读取旧程序与项目，创建备份并读回校验；程序侧一定保留备份，独立项目侧也保存副本。
- 覆盖前写入带 schema 的恢复日志，逐文件写入及核验。安装清单属于事务，index.html 最后更新。
- 包括“当前文件已部分写入但写操作抛错”的情况，均纳入回滚。恢复旧内容后逐项核验，新建文件移除。不会删除用户业务数据，也不以清理为由删除旧版不再引用的文件。
- 中断留下 writing 日志时，下次从升级入口选择原程序目录，使用原备份恢复；恢复失败时保留日志与备份，禁止继续覆盖。页面无法加载、磁盘损坏、持续失去写权限等仍需人工恢复或用独立新程序目录连接原项目。
- SHA-256 清单检查完整性，不能替代可信发布来源或数字签名。

## 界面和逻辑校核

保留五工作区、十个数据子页、七个设置页的全量界面回归，覆盖不同桌面宽度、弹窗键盘焦点、短列表无多余滚动、长列表末行可达。业务回归继续覆盖五类多文件合并、可选映射、月份错误、原件字节、项目隔离、人工判定、加班跨夜和跨月、导出、安全恢复与关闭保护。

本轮修复原始证据详情的姓名、时间、方向和行号直接拼 HTML 问题，统一转义，加入含 HTML 的数据验证。数据管理活动入口仍只有 45-console.js 中的一套 renderDataWorkspace，实现不存在旧版渲染覆盖叠加。

## 验证证据

`r84-audit.cjs` 使用真实浏览器 OPFS 文件流与 IndexedDB，验证损坏/缺失/错误产品/不兼容包、降级、后台未保存月份、部分写入失败、日志恢复、清单同步、入口最后更新、真实文件选择向导、目录记忆及完成后重载。覆盖 1280×720、1366×768、1920×1080 的宽度和焦点约束。

生命周期审计分别执行准确历史 R77 和 R83 程序代码中的升级流程，并在升级后重新打开新版、核对业务和原件字节。自动化未代替 Windows 外部目录弹窗的人工授权验收，不把 OPFS 称为系统文件夹权限实测。

CI 对准确提交执行范围、离线、语法、全量 Chromium 及候选打包，上传限期程序 ZIP、SHA256SUMS 和截图/JSON 证据。无正式 tag 或 Release。
