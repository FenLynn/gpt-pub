## 2. 当前最重要的开发原则

### 2.1 不要“大改时间轴”

用户已经多次明确要求：

- 时间轴整体结构如果已经对，只修用户指出的那一点。
- 不要因为修标签、缩略条、右侧按钮，就顺手改主时间轴的坐标、缩放逻辑、轨道结构或视觉层级。
- 上一轮最大的错误就是把“只修四个文字”扩大成“重做时间轴坐标体系”。

后续采用 **最小修改原则**：

> 一条反馈对应一处行为；除非它们有直接因果关系，不要联动重构。

### 2.2 用户会直接看截图，不接受“代码逻辑上正确”

每轮改动后必须：

1. 等 `P109 AttendScope CI` 成功。
2. 下载 `p109-offline-browser-screenshots` Artifact。
3. 实际查看相关 Chromium 截图。
4. 确认视觉问题真的消失，再汇报。
5. 共享 Pages 成功后才说“线上已更新”。

不要把“commit 已写入”说成“页面已经好了”。

## 3. 当前时间轴设计的确定约束

### 3.1 主时间轴固定 6 个逻辑轨

用户已经定死：

1. 进：箭头
2. 出：箭头
3. 出差
4. 请假
5. 外出
6. 加班

进 / 出之间是主时间基线。

### 3.2 四个行为轨

- 出差、请假、外出、加班四条轨道始终存在。
- 没有数据时也显示，但背景非常淡。
- 有数据时才显示对应行为颜色。
- 四条轨道彼此紧挨，不能留大空隙。
- 轨道间分界线比轨道底色略深一点。
- 四个行为名称必须始终固定在主图最右端，不能随着缩放范围移动或消失。
- 名称颜色跟各自行为色一致。
- 标签不要放在行为区间内部。
- 不要再添加右侧圆点 / 小图标。
- 用户上一轮要求标签字号不要过大。当前意图是比曾经 17 px 的版本缩小约 20%。

### 3.3 法定工作时间

- 可以作为很淡的辅助视觉。
- 不应覆盖四个行为轨形成大片阴影。
- 行为轨区域更适合保留工作时间端点的淡虚线。
- 虚线保留。
- 法定工作时间属于辅助层，不能抢行为条或打卡箭头。

### 3.4 进 / 出颜色

- 必须与“正常 / 异常 / 缺勤”和四类行为颜色全部区分。
- 当前颜色定义在 `src/app/10-analysis.js`。
- 不要重新使用正常绿、异常黄、缺勤红或任一行为主色。

## 4. 下方缩略图 / navigator 的硬要求

这是用户最反复指出的区域，修改时必须逐像素核对。

- 缩略图是全天 0:00–24:00 导航，不要为了对齐主图而改变主时间轴本身的缩放逻辑。
- 进 / 出竖条必须完全包含在 navigator bar 内：
  - 顶部刚好贴 bar 上边缘
  - 底部刚好贴 bar 下边缘
  - 不能向上或向下冒出 1 px
- 内部横线不要显示。
- 下方颜色要比主图箭头更淡。
- 非选中区域中的竖条要进一步淡化。
- handle / 选中区域 / 非选中区域要能明确区分，但仍保持浅灰 + 白色体系。
- 修改后必须用真实 Chromium 截图确认，不能只看 CSS 数值。

## 5. 矩阵与人工判定

### 5.1 矩阵聚焦

用户认可方向：

- 选中横线、竖线或格子时，无关区域淡化。
- 当前格最突出。
- 同行 / 同列根据选择类型保留较高可见度。

### 5.2 人工标记勾勾

- 勾勾必须完全位于单元格右上角内部。
- 不得越出方块。
- 边缘尽量光滑。

### 5.3 “初始 / 人工”

右侧时间轴信息区目前采用：

- 初始：点击可恢复系统初始判断。
- 人工：正常 / 异常 / 缺勤三块。

关键规则：

- 如果某天初始状态就是“正常”，人工的“正常”块必须变淡并禁用，不能把人工改成与初始完全相同的状态。
- 初始是异常 / 缺勤时同理。
- 切换到左侧全局“初始”视图时，矩阵上的人工勾勾不显示。
- 人工色块未选中时可只显示颜色；选中时显示白色文字。

## 6. 右侧信息区

用户不喜欢“小空间塞很多卡片”的方式。

当前方向：

- 尽量扁平化。
- 可以用 `概况 / 行为` tab。
- 少边框，少重复标题。
- “概况”应显示个人当天完整时间轴信息，不因为左侧筛选“请假 / 外出”等就只显示该筛选类型。
- 行为 tab 可列出出差 / 请假 / 外出 / 加班。
- 不要用筛选条件替代个人完整当天概况。

## 7. 总览 / 统计

**尚未定稿。不要在没有新用户意见时自行大改。**

用户已经明确说过当前“总览”和“统计”不满意，但还没有给最终结构。

接手后如果继续做这两页：

- 先单独分析现有 `overview` / `stats` 的信息目标。
- 不要边修时间轴边顺手改总览 / 统计。
- 推荐把两者职责分开：
  - 总览：快速判断整体情况与异常分布。
  - 统计：用于比较、分组、趋势和钻取。
- 在用户确认方向前，不做大范围 UI 重构。

## R49 · 午休容错与自动加班候选（2026-10-20）

- **原则**：原始打卡、真实登记加班及派生候选严格分开。自动候选不等于员工实际加班已获批准，不得自动写入原始加班记录或薪酬结果。
- 班内工时仅统计完整 `进→出` 区间与上午/下午班次的交集，午休时段不被算入；未分段的午休显示“工时按班次扣午休”，但不假定员工实际有无工作。原“在岗”字段仍保留完整进出间隔含义，避免静默改变历史统计口径。
- 午间 `出` 后缺少下午配套 `进/出`，优先作为**疑似/待核**，不直接根据午间的最后一次 `出`判定为确定早退；午休早离或返岗过晚也只做待核标记。有请假/外出记录覆盖返岗差异时不报午休返岗疑点。
- **自动加班**：工作日仅统计正常下班后实际完整配对的出勤段；非工作日完整配对区间扣除设置的午休时段。默认最短候选时长 30 分钟，可在“设置 → 考勤规则”调整 0–240 分钟。配对不完整或当天已有登记加班时不额外计入候选，避免双重计时。
- 新增统计指标“自动推算候选工时、加班候选人日、加班候选人数”，全员、跨组、组内、个人统一从 `state.analysis` 的同一事实层派生；个人时间轴的概况与行为栏分别明确标“加班候选／推算待核”，原加班轨道仍只画已有来源区间。
- 自动算法基于打卡证据，**不能确认劳动事实、审批、工时支付或跨午夜加班**；只有出入记录完整，才能出具估算。当前仅支持单日班次，复杂轮班／跨日加班要等班制明确再扩展。
- Synthetic Chromium 案例覆盖：标准四次打卡、仅两次打卡跨午休、午休提前出/晚返、下午漏打卡、已登记加班、临界阈值、周末完整或不完整进出、请假覆盖午间晚返、三层候选统计、规则持久化。旧六轨时间轴和原始数据验证继续执行。
