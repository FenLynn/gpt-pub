# R39 · 桌面工作台布局改造方案（2026-10-19）

## 用户确认的原则

1. 顶部仅保留 AttendScope 品牌、全局四工作区导航、月份选择及导入/目录/保存/冻结/导出/设置。取消额外的第二层横向导航。
2. 左上角始终属于当前工作区的二级导航和筛选：全员/分组使用组别、状态、判定与待核查；个人使用员工、内容子页、状态与判定；数据管理使用记录/名册/规则/导入子页。
3. 月历始终放在左侧**底部**，无论哪个工作区都可见并可按日期下钻。顶部年月负责切换月份，左下月历负责选择日期，职责不重复。
4. 右侧主内容尽量占满剩余水平空间，矩阵自动扩张日列、姓名正常连写；撤销占高的四张 KPI 大卡、五张组别小卡以及横排异常姓名标签。
5. 摘要改成一条轻量水平文字指标；矩阵工具栏统一为标题和简明说明；页面整体扁平化、避免多余边框、阴影与小字号。
6. 继承活动六轨时间轴 `36-tracks.js` 和 Tabulator 原始证据；不修改考勤算法、数据格式或 Shared Pages 工作流。

## 设计实现

- 复用 `20-shell.js` 的 DOM 外壳、`39-workspaces.js` 的数据分流、`r37.css` 当前分页结构，不引入第二套应用状态或新 UI 框架。
- 现代四工作区采用共享侧栏生成器；旧 CI 专用 classic 模式保留相同矩阵/时间轴渲染和传统布局。
- 尺寸以 1920×1080、1600×900、1366×768 为验收基线，重点监测水平页面溢出、首屏矩阵起点、左下月历可见性、姓名列、导航不重复。
- 保证侧栏人员/组别/状态操作有效；个人侧栏子页与原图表同步；数据管理的二级页移到左边，不重复右侧标签。
- 所有动态文本转义。真实员工资料不进入公共 Git，截图仅使用公开模拟数据。

## 验收条件

1. 现代模式的导航仅在系统栏出现一次；副导航及状态筛选出现在左侧；右侧无大 KPI 卡、组别卡及横排异常标签。
2. 四个工作区可切换；左侧月历在 1366×768 仍在视口内，且日期点击有对应行为。
3. 1366 宽及以上现代全员页面不会出现浏览器整体横向滚动，矩阵宽度随视口充分展开，姓名不被拆字。
4. 最小化跨页重绘生命周期风险；Chromium CI 中原有时间轴滑块几何、箭头、聚合和人工判定回归全部不退化。
5. P109 CI 成功后检查 Shared Unified Pages 完整打包 P108+P109，对照准确 P109 head SHA，不触碰 main/stable/正式 Release。

## 不属于本次 UI 改造的遗留事项

Windows File System Access 真机验收、同名员工身份映射、夜班和复杂考勤判据、长期 CSS 历史层叠彻底清除。
