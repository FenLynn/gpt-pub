# P109｜AttendScope 开发约束

> 约束层级：C｜项目级  
> 上位约束：`/GPT_RULES.md`、`projects/1-桌面软件/开发约束.md`  
> 适用范围：`projects/1-桌面软件/109-AttendScope/` 与 P109 自有 Pages/CI。

## C-01｜离线是产品硬约束

- `index.html` 必须可作为本地文件直接打开；不得依赖 CDN、远程字体、在线 API、在线图表或运行时包管理器。
- GitHub Pages 只是静态预览入口，不能成为正常运行依赖。
- 程序代码使用相对路径，不依赖 `index.html` 文件名。

## C-02｜原始数据不可变

- 用户导入的原始考勤、请假、出差文件只能复制保存，不得原位改写。
- 人工处理只进入 revisions/working/snapshot 等派生层；清除人工痕迹不得删除或改写 raw。
- 公开仓库禁止提交真实用户考勤、真实人员名册、真实请假出差和任何可识别个人信息。

## C-03｜保存与冻结分离

- 保存更新可变 working 状态，适合间断工作。
- 冻结创建不可变 snapshot；冻结后全局配置变化不得影响该镜像。
- 历史 snapshot 如需修改，应从 snapshot 创建隔离 branch 工作区，修改后重新冻结，不得“解冻后原位修改”。

## C-04｜分析可追溯

- 每条规范化打卡必须可回溯到来源文件、工作表和原始行/记录标识。
- 图表、矩阵、传统表格和 PDF 报告必须共享同一事实层，禁止各自重复计算形成不一致结果。
- 明确问题与疑似问题必须分级：红色只用于明确迟到、早退、缺勤等；黄色用于配对不完整、连续同向等待核实情况。

## C-05｜兼容与可恢复

- 中文文件名、空格、括号等操作系统允许的文件名不得影响导入逻辑；内部逻辑使用 importId/recordId，不用文件名作为身份。
- 关键 JSON 必须带 `schemaVersion`。
- derived/output 允许删除后重建；raw、配置、人工修正和冻结快照不得依赖 derived/output 才能恢复。

## C-06｜共享 GitHub Pages 发布不可互相覆盖

- `gpt-pub` 的唯一 Pages 发布者为 `main` 上的 `.github/workflows/repository-pages.yml`。一次部署必须同时保留 `/p108/` 与 `/p109/`。
- P109 自有 `.github/workflows/p109-attendscope-pages.yml` **仅运行范围、离线、源码和 Chromium 浏览器 QA**，不再含 `actions/deploy-pages`、`pages: write` 或只包含 P109 文件的 Pages Artifact。
- P109 通过项目 CI 后由共享发布器完整组装静态站点；P109 独立迭代不得重建单项目 Pages 部署，以免 FigureStudio 出现 404。
- P109 纯离线包与本地浏览器 QA 不受影响。需要验证线上 URL 时在共享发布器成功以后进行，不能再通过恢复 P109 的独立发布 job 达成。
